# WDER 使用文档

> [Wiki 首页](README.md) · [玩家玩法](玩法说明.md) · [权限与管理员指令](权限组与管理员指令.md) · [插件机制说明](插件机制说明.md) · [国家史书机制](国家史书机制.md) · [城镇史书机制](城镇史书机制.md) · [文化史书机制](文化史书机制.md)

本文面向服主和管理员，说明安装、配置、命令入口与运行边界。实际生效值以服务端 `plugins/WorldDynamicsEngine-Reborn/` 下的配置为准。

## 1. 插件与依赖

WorldDynamicsEngine:Reborn（WDER）在 Towny 的城镇、国家和居民数据之上，提供国家治理、国家集团、战争与和约、文化及背景机制。它不取代 Towny 的创建、圈地、领土权限或原生金库。

运行要求：

- Java 21
- Paper 1.21.x
- Towny
- Vault API 兼容的经济提供者

AuraSkills、CraftEngine、RealisticSeasons 是可选依赖。缺少可选插件时，对应的技能奖励、自定义物品或日历时间联动不可用；依赖缺失不应阻止基础模块运行。多币种操作需要经济提供者真实支持配置的货币，不能仅凭汇率配置推断经济服务支持该币种。

## 2. 安装与启动

1. 将 WDER JAR 放入服务端 `plugins` 目录。
2. 安装 Towny 与 Vault 兼容的经济插件。
3. 使用 Java 21 启动 Paper。
4. 检查启动日志中的依赖和数据库初始化信息。

SQLite 数据表会自动创建。MySQL 数据库需预先创建，连接账号需要表的读写和建表权限。缺少 Towny 或 Vault 经济服务时，WDER 会停用。

## 3. 配置文件

配置位于 WDER 插件数据目录：

| 文件 | 主要用途 |
| --- | --- |
| `config.yml` | 全局模块开关、货币、经济、存储与居民税接管 |
| `nation.yml` | 国家政体、选举、集结及国家史书开关 |
| `town.yml` | 城镇政体、选举、征召兵、常规城镇战争、集结与城镇史书开关 |
| `organization.yml` | 集团类型、维护费、主权帝国自治、贡税与军事义务 |
| `war.yml` | 战争理由条件、战争分数、和平条款和停战期 |
| `ideology.yml` | 文化、模因、戒律、费用、金库税制及文化/教会史书开关 |
| `relics.yml` | 两件宗教圣物与速度效果 |
| `backgrounds.yml` | 儿童期、成年期背景及 AuraSkills 增量 |
| `foods.yml` | 食物分类和饮食戒律心情判定 |
| `drops.yml` | 玩家死亡额外掉落池 |
| `inn.yml` | Towny INN 床位费 |
| `event.yml` | 国家、城镇、文化和教会史书事件句子模板、日期格式、书名和命令提示 |
| `message.yml` | GUI 标题、说明与菜单文案 |
| `lang/` | 命令和系统消息多语言文本 |
| `data/worlddynamics-engine.db` | 默认 SQLite 数据库 |
| `history/<史书UUID>/` | 国家史书 JSON 事件文件及 TXT 导出 |
| `history/towns/<史书UUID>/` | 城镇史书 JSON 事件文件及 TXT 导出 |
| `history/ideologies/<史书UUID>/` | 文化史书 JSON 事件文件及 TXT 导出 |
| `history/churches/<史书UUID>/` | 教会史书 JSON 事件文件及 TXT 导出 |

全局模块开关位于 `config.yml`。文化和背景另有各自配置开关；国家、城镇及文化/教会史书分别使用 `nation.yml -> history.enabled`、`town.yml -> history.enabled` 和 `ideology.yml -> history.enabled`。

### 存储和货币

`config.yml -> storage.type` 支持 `sqlite` 和 `mysql`，默认 SQLite。数据库后端或连接参数变更需要完整重启；WDER 不提供 SQLite 与 MySQL 的自动迁移。

`economy.exchangeRates` 第一项必须与 `economy.defaultCurrency` 完全一致，该项是运行时默认货币。货币 ID 区分大小写，例如 `USD` 与 `usd` 不同。Towny 国家、城镇金库和国家集团余额以默认货币结算；集团账户不支持按币种分账。

## 4. Towny 同步、保存与重载

- 启动时读取现有 Towny 城镇与国家，并为缺少 WDER 治理档案的对象建档，不重置已有治理数据。
- 运行期间的创建、删除、改名、入国、退国等生命周期由 Towny 事件维护，不靠周期性扫描补齐。
- `/wde reload` 重载配置、语言、菜单与相关任务，但不重新扫描 Towny 数据。
- 修改 `storage.*` 后必须重启。插件会自动补齐部分旧配置缺失字段，不覆盖已存在值，也不替服主重新平衡已有参数。

```text
/wde reload
/wde debug balance <玩家> [货币]
/wde debug craftengine
/wde debug realisticseasons
```

`/wde debug` 子命令需要 `wde.debug`，重载需要 `wde.reload`。完整权限节点和管理员命令见[权限与管理员指令](权限组与管理员指令.md)。

## 5. 常用入口

```text
/wde
/wde help [页码]
/wde nation [国家名] [menu]
/wde town [城镇名] [menu]
/wde org [menu]
/wde war [menu]
/wde ideology [menu]
/wde background
/wde rally <nation|town>
/wde history <list|read|txt|book>
```

GUI 用于浏览和发起操作；最终命令仍会重新检查玩家身份、权限、费用、战争状态和目标归属。普通玩家权限为 `wde.player`，实际操作仍受 Towny 职位和业务规则限制。

### 菜单页面直达

`/wde menu` 打开首页。用 `/wde menu [玩家] <页面> [参数]` 可直达指定页面：

```text
/wde menu war
/wde menu war 北境
/wde menu war-detail <焦点键>
/wde menu @Alice war 北境
/wde menu background-stage childhood
```

`war <对手>` 只查接收者正在参与、且对手在敌方的战争。同一对手出现在多场战争时打开第一场，可用 `war-detail <焦点键>` 精确指定。打开页面本身不会宣战或切换计分板专注。

不填玩家时为自己打开。代开要求 `wde.menu.others`（默认 OP），接收者必须在线并拥有 `wde.player`；控制台必须指定接收者。页面及按钮按接收者自己的权限运行。玩家名与页面 ID 相同时用 `@玩家` 消歧。Tab 可补全页面 ID 和可选接收者；战争目标及焦点键只补全发送者本人的战事。

| 页面 ID | 参数（`[]` 可省略，`<>` 必填） |
| --- | --- |
| `home` | 无 |
| `war` / `war-detail` / `war-declare` | `[对手]` / `<焦点键>` / `[nation\|town] <目标>`（默认 `nation`） |
| `town` / `nation` | `[城镇]` / `[国家]` |
| `conscript` | `<城镇> <居民>` |
| `organizations` | 无 |
| `organization` / `org-members` / `org-applications` / `org-war-votes` / `org-wars` | `<集团>` |
| `subject` | `<集团> <附属国>` |
| `peace` / `peace-inbox` | `[集团]` |
| `peace-received` | `<提案方> [集团]` |
| `background` / `background-stage` / `background-detail` | 无 / `<阶段>` / `<阶段> <背景ID>`，阶段为 `childhood` 或 `adulthood` |
| `culture` / `culture-list` / `culture-manage` | 无 |
| `culture-detail` / `treasury` / `doctrines` / `memes` | `<文化>` |
| `attitudes` | `<文化> <戒律ID>` |

确认框、聊天输入和依赖当前草稿的编辑步骤不能单独打开，请从对应页面进入。

## 6. 治理与国家集团

国家政体为 `DICTATORSHIP`、`DEMOCRACY`、`NOBLE_COUNCIL`；城镇政体为 `DICTATORSHIP`、`REPUBLIC`。独裁制界面不会展示选举操作。选举周期、候选人和投票资格分别由 `nation.yml`、`town.yml` 和玩家在 Towny 中的身份决定。

国家集团只以国家作为成员单位，类型为：

- `TRADE_ALLIANCE`：贸易联盟及联盟制裁
- `MILITARY_ALLIANCE`：成员国入盟投票和集团宣战投票
- `SOVEREIGN_EMPIRE`：主席国管理从仆国的国家层级事务
- `IDEOLOGICAL_ALLIANCE`：绑定文化并提供相应联盟规则

主权帝国从仆等级为傀儡国、保护国、自治领，并可标记为卫戍国。自治、镇压、固定税额上限、贡税、强制参战及卫戍巡检参数位于 `organization.yml`。主席国不直接管理从仆国下属城镇。

城镇与国家使用 Towny 的实时归属。民主国家领袖变更会尝试同步 Towny 国王；首都转让时，按剩余城镇人口优先、名称排序选择继任首都。

### 外交致函

国王、政府领袖或军队统帅可代表本国向其他国家发送侮辱、通知或请求信：

```text
/wde diplomacy letter <目标国家> <insult|notice|request> <正文>
/wde diplomacy letters <页码>
/wde diplomacy readletter <信件UUID> [页码]
```

正文最多4000字符，发送后不支持修改；命令中的空格会保留。费用由发信人的个人钱包支付，配置位于 `config.yml -> diplomacy.letters.cost.amount/currency`，默认100默认货币，0免费，修改后 `/wde reload`。

信件按收发国家UUID保存，目标国家成员在线时收到通知；目标领导者离线也可稍后查收。读取与列表需要上述外交身份，仅收发两国可读取原始信件。侮辱信不会自动设为敌对或宣战。

史书采集开启时双方各记一条事件，正文亦保存在事件参数中，默认史书句子只展示类型，例如“于2026年10月19日，甲国向乙国发表了一封言辞激烈的信”。通知信为“正式的信”，请求信为“充满恳切的信”。措辞由 `event.yml` 调整，使用史书所选现实或季节日期。史书是公开历史，不应在信中填写隐私或秘密。

### 书面契约

契约用于保存任意正文及双方的签署/决定记录，不会执行正文中的约定，也不会改变城镇、国家、战争、经济或外交状态。创建者在主手持书与笔时输入命令，随后在原版书本编辑界面撰写正文并签署；系统自动写入签署日期和签约方，签约方名称过长时会以 `...` 截短。接收方从待办列表打开成书查看后，可点击承认或拒绝；处理结果和经办人会被保存并追加在书末。

可用组合为玩家-玩家、玩家-城镇、玩家-国家、城镇-城镇、城镇-国家、国家-国家。发起城镇一方须为该城镇镇长或本插件记录的城镇领袖；国家对国家契约中，共和/民主政体仅允许外交官发起，其他政体允许最高领袖或外交官发起。城镇/国家接收方由相应授权代表处理。契约正文与待处理状态独立保存在插件数据库中。

```text
/wde contract create <发起方类型> <接收方类型> <接收方名称>
/wde contract inbox
/wde contract list
/wde contract view <编号>
/wde contract accept <编号>
/wde contract reject <编号>
```

发起方类型可选 `player`、`town`、`nation`；接收方类型按允许组合选择。发起方名称自动取当前玩家、其所属城镇或国家。国家对国家需以 `nation nation` 发起。待办和列表中的条目可点击打开；只有已打开过对应契约的接收方授权代表才能承认或拒绝。

状态流转、权限校验和存储字段详见[《契约系统机制说明》](契约系统机制说明.md)。

## 7. 战争、和约与停战

玩家手动选择战争理由，系统在菜单、命令和投票结算时校验资格。理由包括征服、收复失地、独立、圣战、贸易冲突、羞辱宿敌、输出革命和取缔非法组织。主要资格为：

- 输出革命：发起国是民主制。
- 收复失地：目标国拥有符合配置连续持有时长的本国旧城镇。
- 贸易冲突：目标贸易联盟正在制裁发起国。
- 羞辱宿敌：双方互相敌对。
- 圣战：交战双方均已设置彼此不同的文化。
- 取缔非法组织：目标为军事同盟或主权帝国主席国。
- 独立：城镇向所属国家，或仆从国向帝国主席国。

常用命令：

```text
/wde war
/wde war declare nation <目标国家|组织> <理由> [目标城镇|组织]
/wde war declare town <目标城镇或所属国家> <理由>
/wde war focus
/wde org declarewar <军事同盟> <目标国家> <理由> [目标城镇|组织]
/wde org votewar <军事同盟> <目标国家> <yes|no>
/wde org peacetreaty [集团名]
/wde org reviewtreaty [集团名]
```

国家战争直接开战；军事同盟成员须提交宣战提案并按权重投票。占领分每 `war.yml -> scoring.cycleSeconds` 累计，击杀分即时计算。分数用于战争详情和和约预算，不会单独触发自动胜负。中立保护、停战期、Towny spawn 限制、防守方复活冻结及城镇战争开关共同约束战争行为。

战争目标按理由自动对应：征服、收复失地需要选择一个目标城镇；独立以独立发起方（防守方）的首都/城镇为目标，圣战、输出革命以目标国首都为目标；羞辱宿敌、取缔非法组织以展现霸权为目标。占领类目标要求进攻方在目标城镇的在线占领人口比例严格超过 75%；展现霸权要求击败的不同敌方玩家数量达到开战时防守阵营人口。目标在服务器运行期间连续达标超过 `war.yml -> warGoals.holdSeconds` 后，进攻方可提交唯一对应的单条和约并强制兑现。独立战争中，若进攻方当前未达到首都占领比例，且独立方分数减去进攻方分数达到 `war.yml -> warGoals.defenderIndependenceScoreDifference`（默认 40），独立方也可主动提交 `DEMAND` 方向的单条“允许独立”条款并强制兑现。进攻方目标达标后的独立条约仍为 `SURRENDER` 方向；其他目标为 `DEMAND` 方向。控制目标失控会重新计时；联盟战争没有强制兑现。

和约条款由后端校验可用性，包括赔款、强制改信、转城、解散或退出军事联盟、解放从属国、通行、羞辱、掠夺首都、每日固定贡金、强制附庸、允许独立、强制民主化与取缔非法组织。固定贡金以默认货币计价，每个 Towny 新日结算一次；旧比例贡金协议迁移为 0 并停征。目标兑现对应的条款分别是转移目标城镇、允许独立、强制改信、强制民主化、羞辱或解散目标组织。输出革命和约由进攻方指定目标国一名非开战时国王的现任镇长为民主制总统；改为民主制后，政体按配置锁定默认 100 天，可使用现实天或 RealisticSeasons 日历天。总分和条款分值由 `war.yml` 控制。未满足目标兑现条件时，普通条约仍须由接收方接受。

战争分差不会自动决定胜负或接受普通条约；独立战争防守方仅在进攻方当前未达到占领比例、且分差达到配置门槛时，可用单条允许独立要求强制兑现。主权帝国自治领可依规则支付费用和平独立；从仆国执行 `leave` 会进入战争菜单，不会自动宣战。

完整限制、计分、和约状态及 Towny 联动见[插件机制说明](插件机制说明.md)。

## 8. 文化与背景

玩家可使用 `/wde mood` 快捷查看当前心情值、动态期望修正，以及每条未到期心情加减的来源、数值和剩余时间；正向条目显示为绿色，负向条目显示为红色。每项态度可在 `doctrines.registry.<戒律>.attitudes.<态度>.moodChange` 中单独设置遵守增益与违背扣减值；未设置时沿用全局或瞬时行为默认值。

OP 与创造模式玩家的实际心情固定按 50 处理，不累计真实心情，也不参与自动崩溃或灵感判定；戒律触发的变化会以仅存于内存的测试预览显示在 `/wde mood`，退出 OP/创造模式后预览清除。非人化标记者仍完全豁免且不显示预览。

在 `ideology.yml -> doctrines.registry.<戒律>.attitudes.<态度>.moodChange` 中，可分别设置 `compliant` 遵守增益和 `violation` 违背扣减；缺省时沿用全局变化值，动物击杀与食物行为仍可使用独立配置。

崩溃首次触发时会显示 Title 警告和效果名称。处于“疯言疯语”期间，玩家自行发送的聊天会被拦截，系统生成的疯言疯语仍会以玩家身份发送。

文化数据配置在 `ideology.yml`。玩家个人、城镇和国家各有归属；创建者自动成为新文化的追随者和领袖。玩家可用 `setplayer none` 取消个人信仰；若离开时是领袖且仍有其他合格继任者，系统会随机移交领袖职位。仍有信徒但没有合格继任者时，领袖暂时不能离开；最后一名合格信徒离开后，宗教会自动解散并清理相关信仰归属。玩家当前心情会显示在“信仰与文化”菜单。戒律态度的 `moodWeight` 越高，遵守/违反该戒律时心情增减越大；动物击杀和食用人肉另有独立的 `mood.instantActions` 配置，行为型变化默认 30 分钟后消散。护甲戒律按当前装备维护长期心情加/减值，装备、信仰或态度变化时重算；态度选择界面会展示符合加成和违反扣减的预计值。心情范围为 0～100。心情每分钟进行一次判定；低于 50 时按差值概率崩溃，高于 50 时每隔默认 2 分钟从当前可用池随机获得一种灵感；基础池包含射击和近战，自然至上、黑暗亲和、传教热忱、裸体主义和地底之心模因分别加入驯服、夜莺、劝慰、行动激励和挖掘激励灵感，间隔和效果开关可在 `ideology.yml -> mood.inspiration` 配置。待用灵感会保存，在 `/wde mood` 显示；对应攻击命中时消耗一次；驯服灵感可保证一次有效驯服，或喂养一只成年可繁殖动物使其生成幼崽并消耗对应物品；夜莺、行动激励和挖掘激励抽中后立即分别获得夜视、速度 III 和急迫 III，默认持续 15 分钟。崩溃程度取决于剩余心情，并可能触发五种不同崩溃。Bukkit OP 豁免自动心情变化和判定，心情按 50 处理；管理员可用 `/wde admin ideology collapse <在线玩家> <崩溃效果ID>` 手动触发已启用的崩溃内容。悲伤徘徊时玩家无法手动移动，角色会平滑地朝随机安全方向行走；信仰危机只改信一次。普通崩溃结束后默认获得 +40 心情、持续 30 分钟的“得到宣泄”。崩溃时长、悲伤徘徊速度与范围、宣泄值可在 `ideology.yml -> mood.collapse` 调整。图标可使用原版材质名或完整 CraftEngine 物品 ID。

“苦痛美德”模因可解锁两种效果：它把第六种崩溃效果 `self_harm` 加入重度候选，触发时玩家获得 5 秒凋零；高心情灵感池中还会加入“拉伸灵感”，抽中后 15 分钟内方块和实体交互距离各增加 1 格。交互距离效果会保存到期时间，重连或插件重载后恢复，不会叠加；管理员的 `moodclear ... inspiration` 会立即清除。

“动物平权”模因可加入崩溃效果 `wild_outburst`。触发后，玩家会持续丢弃主背包、快捷栏、盔甲、副手及光标物品，清空后崩溃结束；默认每 10 tick 丢一组。效果期间不能整理或拾取物品，保护插件取消掉落时原物品会保留并重试。设置位于 `ideology.yml -> mood.collapse.effects.wildOutburst`。

新玩家期望按累计在线时长逐档变化：默认 0～2 小时为“极低期望” `+30`，之后每 2 小时依次为“很低期望” `+24`、“低期望” `+18`、“合理期望” `+12`、“高期望” `+6`，满 10 小时为“很高期望” `0`。`/wde mood` 会分别显示当前新玩家期望档位、镇长配置修正（默认 `-8`）、国王配置修正（默认 `-12`）、当前实际生效值和合计。两种身份修正不叠加；同时担任镇长和国王时只应用国王修正。保存 `ideology.yml` 后，期望配置会自动检测并立即重评在线玩家的心情；其他配置项仍需执行 `/wde reload`。阶梯和身份修正位于 `ideology.yml -> mood.expectations`。

若个人信仰的“非人化”戒律态度为“必需”，自动崩溃固定触发“人性崩溃”，在失明期间按配置播放多步标题和聊天提示。流程结束后永久获得“非人化”标记，心情锁定为 50，所有心情加减和自动崩溃/灵感判定均停用；流程可在 `ideology.yml -> mood.collapse.effects.humanityCollapse` 自定义。

只有选择“非人异化”模因的文化才能启用“非人化”戒律。启用后，尚未获得非人化标记的个人信徒会持续承受 `-15` 心情的“耻于为人”；进入非人化状态后，该条目自动清除，心情固定为 50。

管理员可使用 `/wde admin ideology moodclear <在线玩家> <all|mood|collapse|dehumanized|inspiration>` 清理对应心情状态，执行结果会写入审计记录。

### PlaceholderAPI 占位符

检测到 PlaceholderAPI 时会自动注册 `wder` 扩展；未安装时插件照常运行。文本型归属变量在没有对应资料时返回空字符串，数值变量使用表中说明的默认值：

| 占位符 | 返回内容 |
| --- | --- |
| `%wder_mood%` | 当前有效心情（0～100，在线时包含动态期望修正；OP、创造模式和非人化状态固定为 50）。 |
| `%wder_mood_expectation%` | 在线玩家的动态期望修正；离线时为 `0`。 |
| `%wder_culture%` | 当前文化名称。 |
| `%wder_culture_leader%` | 当前文化领袖名称。 |
| `%wder_culture_governance%` | 当前治理模式，按插件语言显示。 |
| `%wder_culture_memes%` | 已选模因名称，按选择顺序以逗号分隔。 |
| `%wder_culture_meme_1%` 至 `%wder_culture_meme_4%` | 对应顺序的单个模因名称。 |
| `%wder_background_childhood%`、`%wder_background_adulthood%` | 儿童时期或成年时期背景名称。 |
| `%wder_town%`、`%wder_nation%` | 在线玩家当前的 Towny 城镇和国家；未加入或离线时为空。 |

其中 `%wder_mood%` 为原有变量，其余为新增变量。

```text
/wde ideology list
/wde ideology info <文化>
/wde ideology create <名称>
/wde ideology setplayer <文化|none>
/wde ideology setnation <国家> <文化|none>
/wde ideology settown <城镇> <文化|none>
/wde ideology setmemes <文化> <模因1> [模因2] [模因3] [模因4]
/wde ideology ritual list <文化>
/wde ideology ritual register <文化> <speech|duel> <仪式名>
/wde ideology ritual start <文化> <仪式名> [决斗者1] [决斗者2]
```

国家治理变更进入国家史书；城镇治理变更进入该城镇自己的史书。两种采集分别由国家、城镇配置控制。

仪式配置位于 `ideology.yml -> rituals`。终身制/枢机制由文化领袖注册仪式并消耗教廷金库；共议制由活跃教会首脑注册，费用按各活跃教会金库占比分摊。当前模板包括激励演讲（主持人和观众）与荣耀对决（主持人、两名决斗者和观众）。仪式默认持续 15 分钟，结束时按范围内同文化参与者身份权重随机得到糟糕、平庸、成功或完美评级；奖励逻辑当前预留为空。

宗教圣物配置在 `relics.yml`。服主可设置两件原版物品或 CraftEngine 物品；有个人信仰的玩家在物品栏或副手携带任意一件时获得速度效果。`effects.speedLevel` 设置效果等级，范围为 0～10，0 表示关闭；修改后执行 `/wde reload`。

背景分儿童期和成年期，必须依次选择；配置位于 `backgrounds.yml`。强制选择开关可让未完成选择的玩家暂时无法移动。AuraSkills 奖励需要相应插件可用。

## 9. 国家史书

`nation.yml` 中的 `history.enabled` 控制是否采集。当前资源配置已启用；若需停用可设为 `false` 后 `/wde reload`。时钟支持：

```yaml
history:
  enabled: true
  clock: REAL_TIME
  world: world
```

`REAL_TIME` 按服务器现实日期分组；`REALISTIC_SEASONS` 使用指定世界日历，无法读取时该事件回退现实日期。`event.yml` 定义事件句子和占位符。

国家史书使用永久 UUID 索引保存在 SQLite/MySQL；每个事件另生成一个 JSON 文件，存于 `history/<史书UUID>/`。国家解散后只归档，不删除索引与历史；显示名附现实存续日期。历史停用期间不会补造普通事件；重新启用时重新采集当前快照。

```text
/wde history list [页码]
/wde history read <国家名或史书UUID> [页码]
/wde history txt <国家名或史书UUID>
/wde history book <国家名或史书UUID> [卷号]
```

TXT 写入史书目录，成书为“XXXX的史书”，长内容可分卷领取。史书机制、事件字段和归档边界见[国家史书机制](国家史书机制.md)。

### 城镇史书

`town.yml -> history.enabled` 控制城镇史书采集。新安装默认开启；升级时若旧配置缺少该字段，补全值为 `false`。关闭期间不记录普通变化；重新开启时从当前状态重新建立快照，不补造停用期间历史。时钟配置与国家史书相同，并可单独设置：

```yaml
history:
  enabled: true
  clock: REAL_TIME
  world: world
```

城镇史书记录建立/接管、解散、改名、政体、城镇领袖、Towny 镇长、文化、所属国家和人口数量变化；不记录居民姓名。城镇与国家分别使用 Towny UUID 和独立索引，改名续写，解散后保留归档。事件句子使用 `event.yml -> townEvents`、`townBook` 和 `townMessages` 模板。

```text
/wde history town list [页码]
/wde history town read <城镇名或史书UUID> [页码]
/wde history town txt <城镇名或史书UUID>
/wde history town book <城镇名或史书UUID> [卷号]
```

JSON 与 TXT 位于 `history/towns/<史书UUID>/`。详细的身份、快照、模板和归档规则见[城镇史书机制](城镇史书机制.md)。

### 文化与教会史书

`ideology.yml -> history.enabled` 独立控制文化和教会史书，新安装默认开启；旧配置缺少该字段时升级补全为关闭。停用期间不采集普通事件，重新启用时以当前治理、归属和金库状态作为基线。现实/季节日历设置也在该配置块中。

文化史书记录创建/解散、治理模式、领袖、枢机、模因/戒律、什一税、金库及个人/城镇/国家归属数量变化。教会史书记录首脑、成员数量、金库、制裁、议案状态以及合并/分裂/解散。公开时间线不包含个人投票、投票人 UUID、成员名单或议案理由。

```text
/wde history ideology list [页码]
/wde history ideology read <文化名或史书UUID> [页码]
/wde history ideology txt <文化名或史书UUID>
/wde history ideology book <文化名或史书UUID> [卷号]
/wde history church list [页码]
/wde history church read <教会名或史书UUID> [页码]
/wde history church txt <教会名或史书UUID>
/wde history church book <教会名或史书UUID> [卷号]
```

对应 JSON/TXT 分别位于 `history/ideologies/<史书UUID>/` 和 `history/churches/<史书UUID>/`。叙述模板位于 `event.yml -> ideologyEvents/churchEvents`。事件字段、隐私范围和归档规则见[文化史书机制](文化史书机制.md)。

## 10. 其他模块与上线检查

- `inn.yml`：Towny INN 床位费。成功入睡后收费，本镇居民免费；床位定价单独保存。
- `drops.yml`：玩家死亡时额外抽取物品，不替换原版掉落；支持原版与 CraftEngine 物品。
- `foods.yml`：原版与 CE 物品分类以及饮食戒律心情判定。
- `relics.yml`：原版与 CE 圣物 ID 以及持有时的速度效果。
- `message.yml` 与 `lang/`：GUI、命令提示及多语言文本。
- `rally`：成员主动传送至军队统帅或镇长位置，费用由国家或城镇金库承担。

首次上线前确认 Java 21、Paper、Towny 和经济服务正常；备份 SQLite/MySQL；核对默认货币；测试国家与城镇同步、权限、和约执行和可选插件联动。启用史书后，另测试初始化接管、新国家成立、城镇归属变更、战争和约、解散归档、TXT 与分卷成书。

WDER 不承诺未实测的插件组合、经济原子性、TPS 或第三方直接绕过标准事件的行为。存储备份应覆盖数据库和 `history/` 目录。
