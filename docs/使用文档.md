# WorldDynamicsEngine:Reborn 使用文档

> [Wiki 首页](README.md) · [玩家玩法](玩法说明.md) · [权限与管理员指令](权限组与管理员指令.md) · [机制说明](插件机制说明.md)

> 面向服主、管理员与配置人员。  
> 本文按当前源码与资源配置编写；功能开关和数值以服务器实际配置为准。
> 玩家玩法请参阅[玩法说明](玩法说明.md)。

## 1. 插件简介

`WorldDynamicsEngine:Reborn`（WDER，万邦演变引擎：重生）是在 Towny 之上扩展国家治理、国家集团、战争、和约、意识形态和角色背景的插件。

Towny 继续负责居民、城镇、国家、领土、地块权限和原生金库；WDER 为这些对象增加政体、职位、征召兵、集团关系、战争状态和战后效果。WDER 不取代 Towny 的圈地、城镇创建或国家创建。

### 运行要求

- Java 21
- Paper 1.21.x；项目当前构建目标为 Paper 1.21.11
- Towny
- 可通过 Vault API 注册的经济提供者
- VaultUnlocked 建议安装；多货币功能需要经济提供者确实支持相应币种

`AuraSkills`、`CraftEngine`、`RealisticSeasons` 为可选集成。缺少可选插件时，对应加成功能、物品识别或季节日历功能不工作，不应影响 WDER 的基础 Towny 治理系统。

## 2. 安装与启动

1. 将 WDER 插件 JAR 放入服务端 `plugins` 目录。
2. 安装并启动 Towny，以及实现 Vault 经济服务的经济插件。
3. 使用 Java 21 启动 Paper。
4. 首次启动会生成配置、语言和数据库文件。
5. 若旧目录 `plugins/WorldDynamicsEngine` 存在且新目录不存在，插件会尝试迁移旧数据目录。

若 Towny 或 Vault 经济服务不可用，WDER 会在启动时停用。检查启动日志中的依赖初始化信息。

## 3. 文件与数据

默认数据目录为 `plugins/WorldDynamicsEngine-Reborn/`。

| 文件 | 用途 |
| --- | --- |
| `config.yml` | 模块开关、默认货币、汇率、存储后端、外交访问与居民税接管 |
| `nation.yml` | 国家政体、自动民主换届周期与投票期限 |
| `town.yml` | 城镇政体、共和换届、征召兵上限、常规战争参与开关 |
| `organization.yml` | 国家集团类型、维护费、自治等级、贡税、镇压、卫戍和联盟附加规则 |
| `war.yml` | 和约条款分数、战争计分、停战期、独立战争参数 |
| `ideology.yml` | 意识形态开关、创建/改信费用、模因与戒律定义 |
| `backgrounds.yml` | 两阶段背景故事及技能等级奖励 |
| `inn.yml` | 旅馆床位默认收费 |
| `drops.yml` | 玩家死亡额外掉落池 |
| `foods.yml` | 原版/CE 食物分类与饮食戒律力量、虚弱效果 |
| `message.yml` | 游戏内 GUI 标题、说明、提示及主权帝国管理菜单文本 |
| `lang/` | 命令和系统提示的语言文件 |
| `data/worlddynamics-engine.db` | SQLite 默认数据库文件 |

业务数据以实体分类保存，包括城镇、国家、居民、集团、意识形态和旅馆床位定价。SQLite 数据表由插件自动创建；MySQL 的数据库实例需由管理员预先创建，账号需有建表和读写权限。

### Towny 数据同步

- 每次插件启动时读取当前 Towny 城镇和国家，为缺失的 WDER 治理记录建档；新建记录默认独裁、无意识形态。
- 启动同步不会重置已有 WDER 政体、选举、意识形态和集团状态。
- 启动时更新城镇归属与国家下属城镇关系。
- 运行期间通过 Towny 创建、删除、改名、城镇归属和居民变动事件维护数据，不使用周期任务扫描 Towny 是否缺少记录。
- `/wde reload` 不会重新扫描 Towny；要重新执行启动导入流程需重启服务端。

### 保存与周期任务

- Towny 城镇生命周期事件和常规城镇数据修改会保存 WDER 城镇状态；城镇定时任务用于共和选举处理，不是定时扫描 Towny。
- 国家数据定期保存，民主选举处理周期约为 5 分钟。
- 居民、国家集团和意识形态数据每 5 分钟自动保存；多数业务修改也会主动保存。
- 停服时保存主要业务分类。
- 国家集团维护费、主权帝国贡税、镇压度结算、军事义务巡检和独立战争周期按集团配置运行。

## 4. 配置与热重载

### 4.1 全局开关

`config.yml`：

| 配置 | 作用 |
| --- | --- |
| `framework` | 当前使用 `towny` |
| `govEnabled` | 国家、城镇治理及外交功能 |
| `orgEnabled` | 国家集团功能 |
| `armyEnabled` | 军队与征召兵功能 |
| `locale` | 命令语言：`zh_cn`、`en`、`es` |

意识形态开关位于 `ideology.yml -> religionEnabled`；背景开关位于 `backgrounds.yml -> enabled`；旅馆开关位于 `inn.yml -> enabled`；死亡掉落开关位于 `drops.yml -> playerDrops.enabled`。

### 4.2 存储

`config.yml -> storage.type` 支持 `sqlite` 和 `mysql`，默认 SQLite。

- SQLite 文件路径：`storage.sqlite.file`，相对 WDER 数据目录。
- MySQL 参数：`storage.mysql.host/port/database/username/password/parameters`。
- 切换存储后端或修改连接参数需重启，不能依靠热重载切换运行中的数据库连接。
- 请在升级、修改存储或迁移数据前备份数据库文件或表。
- 插件不会自动把既有 SQLite 数据跨库迁移到 MySQL，MySQL 数据库需预先创建。

### 4.3 默认货币与多货币

`economy.exchangeRates` 第一项是运行时默认货币，必须与 `economy.defaultCurrency` 一致。汇率以默认货币为基准。不要随意重排首项或仅修改其中一个字段。

所有货币标识严格区分大小写，配置和命令参数必须与经济提供者返回的标识完全一致，例如 `USD` 与 `usd` 是不同币种。仅小写 `default` 是默认货币别名。错误大小写或不可用币种不会回退读取、扣除默认货币；居民财富与税收计算会跳过这些无效项，避免重复计算同一余额。普通 Vault 模式仅支持配置的默认币种。

WDER 使用 Vault 经济服务；通过 VaultUnlocked 的现代多货币能力收费时，经济提供者必须实际声明并支持对应币种。Towny 国库本身以默认货币结算，指定其他币种的国家/城镇金库费用会先按汇率换算。国家集团余额、存款和取款是单默认货币余额，不支持按币种分账。

### 4.4 主要配置文件

- `nation.yml`：`validGovernmentTypes`、`nationElectionIntervalDays`、`nationElectionDurationDays`。
- `town.yml`：`validTownGovernmentTypes`、共和选举周期/时长、`townConscriptLimitRatio`、`allowRegularWarParticipation`。
- `organization.yml`：有效集团类型、成立费、维护费、`nationOrgLimit`、意识形态联盟倍率、主权帝国自治、税收上限、贡税、强制贡金、镇压与军事巡检。
- `war.yml`：和约分数上限与条款成本、击杀/占领计分、停战期与 RealisticSeasons 日历设置、独立战争分数池和周期。
- `ideology.yml`：创建/改信费用；每条模因和戒律定义可配置 `icon`，直接放在对应定义项内。
- `backgrounds.yml`：儿童和成年两个阶段的背景、故事文本及 `skillLevelBonuses`。
- `drops.yml`：抽取次数和原版/CraftEngine 掉落池。
- `inn.yml`：默认床位费金额与币种。

调整政治、经济和战争参数前，建议在测试服验证边界情况。WDER 在多个配置中会为旧文件补齐缺少字段，但不会自动替管理员重新平衡已有数值。

### 4.5 热重载

```text
/wde reload
```

需要 `wde.reload` 权限，默认授予 OP；完整管理员权限 `wde.admin` 包含该节点。重载前保存运行时数据，重新读取全局与模块配置、语言文件，重建命令和监听器，并重启相关任务。它会检查遗留 Towny 中立集团状态，但不会重新导入 Towny 城镇/国家。

修改 `storage.*` 后，重载只会提示需要重启，不代表运行中数据库连接已经切换。需要完整重启服务端。

### 4.6 调试命令

以下命令需要 `wde.debug` 权限，默认授予 OP，完整管理员权限也包含该节点：

```text
/wde debug balance <玩家> [币种]
/wde debug craftengine
/wde debug realisticseasons
```

分别用于核对经济提供者实际余额、CraftEngine 连接/物品/方块识别，以及 RealisticSeasons 指定世界日期。

## 5. 命令入口与图形界面

所有命令均使用 `/wde` 根命令。输入 `/wde` 打开主菜单；`/wde help [页码]` 可查看带点击翻页的帮助，控制台可用页码参数翻页。

普通玩家默认获得 `wde.player`，能访问所有正常玩法命令；国王、镇长、教主、投票资格、费用和战争状态等业务校验仍保留。管理员使用独立的 `/wde admin` 入口，完整权限为 `wde.admin`，也可按模块授予管理权限。完整指令表、LuckPerms 分组示例和日志说明见[权限组与管理员指令](权限组与管理员指令.md)。新版权限节点需在升级 JAR 后重启注册。

### 5.1 国家与城镇管理菜单

```text
/wde nation
/wde nation menu
/wde nation <国家名> menu
/wde town
```

管理菜单按玩家所属国家、城镇和职位显示操作；独裁制不展示选举操作。数值从聊天栏输入，输入 `cancel` 取消。选项只提供操作入口，最终权限和规则由原有命令逻辑再次检查。详见[国家与城镇管理菜单](国家与城镇管理菜单.md)。

### 5.2 国家集团菜单

可浏览、筛选、创建和管理四类国家集团；主权帝国有主席国与从仆国档案、贡税、自治、镇压和独立战争专用界面。详见[国家集团管理菜单](国家集团管理菜单.md)。

### 5.3 和平条款菜单

```text

```

当前国家国王可在 GUI 中选择战争对象、方向和条款；接收方可查看并接受或拒绝。菜单不是绕过命令权限的入口。下述完整命令仍可用于管理与自动化。

## 6. 国家与城镇治理

### 6.1 国家政体

默认有效类型为：

- `DICTATORSHIP`：国王可任命治理领袖和军队统帅。
- `DEMOCRACY`：国家选举由下属城镇镇长构成候选人；国家居民参与政府领袖投票。民主军队统帅使用候选人投票。到期处理按配置周期进行。
- `NOBLE_COUNCIL`：国王发起领袖或军队统帅提名，由下属城镇镇长按是/否投票。

常用命令：

```text
/wde nation <国家> setgovtype <DICTATORSHIP|DEMOCRACY|NOBLE_COUNCIL>
/wde nation <国家> setgovleader <玩家>
/wde nation <国家> startelection
/wde nation <国家> voteleader <候选人|yes|no>
/wde nation <国家> appointarmycommander <玩家>
/wde nation <国家> votearmycommander <候选人|yes|no>
/wde nation <国家> addgovmember <玩家>
/wde nation <国家> kickgovmember <玩家>
```

政体、任命和投票命令会分别检查国王、政府领袖、镇长或国家居民身份。民主制胜选后会尝试同步 Towny 国王身份，并迁移首都至候选人所属城镇。

### 6.2 城镇政体与征召兵

默认城镇政体为独裁和共和。共和制有现实时间选举周期；独裁制不展示选举信息。

```text
/wde town <城镇> setgovtype <DICTATORSHIP|REPUBLIC>
/wde town <城镇> setleader <玩家>
/wde town <城镇> nominateleader <玩家>
/wde town <城镇> voteleader <候选人|yes|no>
/wde town <城镇> setelectiondays <天数>
/wde town <城镇> setconscript <玩家> <enabled|disabled>
/wde town <城镇> setconscriptprivilege <玩家> taxfree <enabled|disabled>
```

征召兵必须是本镇居民。人数上限默认按城镇人口的 `50%` 计算，实际比例由 `town.yml` 控制；主权帝国卫戍国城镇使用人口 `100%` 的容量。`allowRegularWarParticipation` 默认关闭，控制城镇是否参与 Towny 常规战争。

### 6.3 国家税制与军队

```text
/wde nation <国家> settowntax <城镇> <fixed|wealth_percentage> <数值>
/wde nation <国家> enlistarmymember <玩家>
/wde nation <国家> dischargearmymember <玩家>
/wde nation <国家> tpconscript <玩家>
/wde nation <从仆国> tpchaircommander
/wde nation <国家> adddiplomat <玩家>
/wde nation <国家> removediplomat <玩家>
```

军队成员由当前军队统帅管理。`tpconscript` 需要授权军队统帅，目标须为在线征召兵；主权帝国主席国的统帅另有从仆国调度规则。Diplomat 标记用于外交身份功能，不代替国家职位。

### 6.4 Towny 居民税接管

`config.yml -> economy.townyResidentTaxOverride.enabled` 默认开启。启用后，WDER 接管 Towny 的城镇居民税结算：

- 定额税先扣默认货币，再尝试从其他已配置货币按汇率补足。
- 财产比例税按居民多币种财富折算总额计算应缴税款。
- 余额不足时可部分收取，最终将折算后的金额存入城镇金库。
- `logPartialCollection` 控制是否记录部分收税日志。

修改居民税之前请确认经济提供者币种列表、默认汇率和 Towny 税制一致。

## 7. 国家集团

成员单位是国家，不是个人玩家。集团类型：

- `TRADE_ALLIANCE`：贸易联盟，可对国家设置制裁。
- `MILITARY_ALLIANCE`：军事同盟，宣战需集团投票。
- `SOVEREIGN_EMPIRE`：主权帝国，主席国管理从仆国。
- `IDEOLOGICAL_ALLIANCE`：创建时绑定联盟意识形态，只接收同意识形态国家。

主要命令：

```text
/wde org info <集团>
/wde org create <集团名> <类型>
/wde org applynation <集团>
/wde org votejoin <集团> <申请国> <yes|no>
/wde org reviewjoin <集团> <申请国> <accept|reject>
/wde org leave <集团>
/wde org deposit <集团> <金额>
/wde org withdraw <集团> <金额>
/wde org dissolve <集团>
```

除主权帝国直接由主席国审理外，集团入盟使用国家权重表决。权重因集团类型和国家资金/人口而异。军事同盟禁止中立国家加入；意识形态联盟拒绝无意识形态或信仰不匹配的国家。申请、投票和最终准入会重新检查相应条件。

### 7.1 贸易制裁

```text
/wde org sanction <贸易联盟> <国家> <enabled|disabled>
```

对制裁国：

- 禁止使用该联盟成员国家的外交访问传送。
- 若制裁国与目标领土所属成员国之间没有活跃战争，则禁止进入该成员国领土。
- 这项豁免按被制裁国与目标领土所属成员国的双边战争状态判断，不要求服务器全局和平。

### 7.2 主权帝国

从仆自治等级从高到低为 `DOMINION`（自治领）、`PROTECTORATE`（保护国）、`PUPPET`（傀儡国）；帝国还可指定卫戍国。

```text
/wde org promoteautonomy <帝国>
/wde org demoteautonomy <帝国> <从仆国>
/wde org setgarrison <帝国> <从仆国> <enabled|disabled>
/wde org mobilizewar <帝国> <从仆国> <enabled|disabled>
/wde org replaceleader <帝国> <从仆国> <玩家>
/wde org demandtribute <帝国> <从仆国>
/wde org grantindependence <帝国> <从仆国>
```

- 从仆国申请提升自治需镇压度为 0 且无独立战争，费用从本国国库扣除。完整路径为“傀儡国 → 保护国 → 自治领 → 和平独立”；自治领继续执行 `promoteautonomy` 时需本国未参加任何活跃战争，支付相同升级费用后退出帝国，不需主席国批准、不触发战争，也不自动改变外交关系。国家与城镇保留，从属、贡税、卫戍和强制参战义务解除。
- 主席国降低从仆国自治等级需镇压度达到 100；成功后重新执行该自治等级的下属城镇税率上限。
- 更换从仆国领袖和强制贡金可降低镇压度；金额与降低值由 `organization.yml` 配置。
- 卫戍国免除常规从仆贡税，征召容量为人口 100%，强制承担帝国常规战争义务。
- 主席国可要求普通从仆国参与战争；中立和独立战争限制仍有效。普通从仆国不受统帅附近巡检 Debuff。
- `organization.yml -> sovereignEmpire.warParticipation` 的统帅附近巡检 Debuff 仅适用于卫戍国；巡检半径与周期分别由 `commanderRadius` 和 `checkIntervalSeconds` 控制。
- `/wde org leave <帝国>` 对从仆国会开启独立战争，不是和平退出；主席国不能退出帝国。
- `grantindependence` 仅对正在进行的独立战争生效，表示主席国放弃压制。

详细图形界面见[国家集团管理菜单](国家集团管理菜单.md)。

## 8. 战争、和约与停战

### 8.1 中立保护

WDER 以 Towny 的国家/城镇中立状态作为和平维护费保护依据。

- 中立国家不能发起、作为目标或跟随成员参加常规军事同盟战争，也不能加入军事同盟。
- 和平时期开启国家中立后会退出军事同盟，并清理关联申请、投票和常规宣战提案。
- 已参战国家或城镇不能在战争期间临时开启中立；须先结束战争或通过和约退出。
- 中立城镇居民不参与常规击杀计分，并在相关常规交战中受到保护。
- 国家中立不阻止城镇作为主权帝国从仆国参与独立战争；独立战争开始后也不能临时开中立逃战。

这套规则作用于 WDER 管理和可拦截的 Towny 事件。若其他插件直接改写 Towny 状态且绕过事件，需单独测试兼容性。

### 8.2 常规战争

```text
/wde org declarewar <军事同盟> <目标国家> <理由>
/wde org votewar <军事同盟> <目标国家> <yes|no>
```

军事同盟战争通过内部权重投票发起。无军事同盟的国家也可直接宣战并持有独立战争记录，双方所有相关成员同步敌对关系。常规战争与独立战争统一采用击杀和周期占领计分；从仆国参战义务巡检仍是独立的惩罚机制。

```text
/wde war
/wde war focus
/wde war focus <序号>
/wde war focus clear
/wde war declare nation <国家或目标集团> <理由>
/wde war declare town <城镇> <理由>
/wde war surrender town <敌镇>
```

国家宣战由国王、国家治理领袖或军队统帅发起；军事联盟成员仍必须投票。城镇宣战由 Towny 镇长发起，默认受 `town.yml -> allowRegularWarParticipation: false` 禁止；中立保护仍生效。集团作为目标仅用于 `destroy_threat`，解析为其主席国并联动实际参战成员。

理由标识：`conquest`（征服）、`reconquest`（收复失地）、`independence`（独立战争）、`holy_war`（圣战）、`trade_conflict`（贸易冲突）、`humiliate_rival`（羞辱宿敌）、`export_revolution`（输出革命）、`destroy_threat`（摧毁威胁）。
`independence` 与其他借口一样由玩家手动选择，仅允许城镇向所属国家、仆从国向帝国主席国使用。城镇命令为 `/wde war declare town <所属国家> independence`，仆从国命令为 `/wde war declare nation <主席国> independence`。`holy_war` 要求两国均拥有意识形态且彼此不同，无意识形态国家不能发起或成为圣战目标。`export_revolution` 仅限民主制国家；`reconquest` 要求敌国持有本国曾连续拥有超过阈值天数的城镇；`trade_conflict` 仅对正在封锁本国的贸易联盟成员有效；`humiliate_rival` 要求两国相互敌对；`destroy_threat` 只允许军事同盟或主权帝国主席国为目标。菜单、补全、宣战及投票结算统一检查这些资格。
收复失地配置位于 `war.yml -> reasons.reconquest`：`minimumDays` 默认 7，持有时长必须严格超过该值；`clock` 为 `REAL_TIME`（现实天）或 `REALISTIC_SEASONS`（季节日历天），`world` 指定日历世界。旧配置自动补全，调整后可 `/wde reload`。城镇历史保存在城镇数据中，从升级后开始记录，同一次连续持有才有效，不累计短期反复持有；无兼容季节记录时回退现实天。

参战玩家会自动看到当前专注战争的侧边计分板，显示我方/敌方总分、占领分、击杀分及当前主要分账。若同时参加多场战争，可在 `/wde war` 菜单中点进具体战争并设为专注，或先执行 `/wde war focus` 查看编号，再用 `/wde war focus <序号>` 切换；`clear` 会清除当前手动专注并允许系统重新选择一场活跃战争展示。

`war.yml -> scoring` 统一配置：`cycleSeconds` 默认 300，`killPoints` 默认 1，`defenderRespawnLockSeconds` 默认 30。仅防守方复活后冻结；独立借口的发起方为进攻方。死亡、旁观玩家不计数，防守方复活冻结期间不计数。

每个国家的原始城镇权重总计 50，多城国家首都 25，其余 25 按非首都城镇居民数分配；零人口城镇按 1 处理，单城国家或独立城镇为 50。每周期按实时城镇人口、首都和参战玩家所在地计算。
防守方城镇的原始权重按 `进攻人数/(进攻人数+防守人数)` 分给进攻方，剩余给防守方，无人时全归防守方。全面和约将每国贡献除以防守阵营国家数，使阵营基础池总计 50；针对各国的未归一化原始贡献另行累计，用于单独谋和。
进攻方领土不给进攻方本土守军占领分；防守方实际反攻时按该镇权重乘以防守人数比例获得额外分，全面和约按进攻阵营国家数归一化，额外池最高每周期 50。单独谋和只计算相关两国领土贡献及针对相关国家的击杀分，不借用其他国家的占领优势。各周期均累加。

战争开始与结束会通过全服聊天栏播报。常规战争及通用和约存于 SQLite/MySQL `wars` 分类，不再重复存于各军事联盟。旧联盟记录自动合并迁移，已有累计总分保留；历史单国占领分无法反推，单国分账从升级后的新周期开始。独立战争仍与所属帝国关联存储。

### 8.3 和平条款 GUI

交战方国家国王可从 `/wde` 主菜单打开和平条款，或运行 `/wde org peacetreaty [集团名]`。接收方使用 `/wde org reviewtreaty [集团名]` 打开收到的条约。

GUI 包含双方国家头像、战争分数差、要求/给予方向、可编辑条款、独立分页、预览与二次确认。点击“同意”是提交提案，不代表对方已接受。受理方可以查看、接受或拒绝；接受前重新校验当前身份、战争状态和条款合法性。原有带参数命令依旧可用。

支持条款：

- 赔款 `reparations:<百分比>`
- 强制改信 `forceConversion`
- 转移城镇 `transferTown:<城镇>:<接收国>`
- 解散同盟 `dissolveAlliance`
- 强制踢出联盟 `expelFromAlliance`
- 解放从仆国 `liberateSubject:<国家>`
- 无条件通行权 `unconditionalPassage`
- 羞辱 `humiliate`
- 劫掠首都 `lootCapital`
- 长期贡金 `tribute`
- 允许独立 `allowIndependence`

多条命令行条款用分号分隔。每条点数和总上限由 `war.yml` 控制；默认上限为 100。全面和约适用于双方战争盟主；符合规则的成员国家可单独谋和，单独谋和的条款总分按双倍计算。意识形态联盟的同教/异教倍率也会影响条款点数。

独立借口中，`allowIndependence` 是可选的政治结果条款，不是其他条款的前置要求。对方接受后仆从国退出帝国、城镇退出所属国家；分差不会使条约自动接受。城镇镇长可打开 `/wde org peacetreaty` 及 `/wde org reviewtreaty`，命令上下文中城镇身份使用 `town:<城镇名>`。

### 8.4 独立战争与停战期

从仆国执行 `leave` 后打开战争菜单，手动选择独立借口并宣战，不立即退盟或自动开战。所有战争使用统一账本、计分、复活冻结、中立、停战与条约规则；城镇独立也受 `town.yml -> allowRegularWarParticipation` 限制。独立专属周期上限、胜负判断和强制接受机制已移除，旧 `sovereignEmpire.independenceWar` 配置自动删除；旧独立战争分数及条约迁入统一战争账本。

无集团战争的国家仍可从和平条款 GUI 谋和；完整命令的集团参数使用 `war`，例如 `/wde org peacetreaty war <敌国> demand humiliate`。城镇战争提供上述镇长结束战争入口与停战期，不套用国家国库和国家条约条款。

和约或单独谋和后，相关国家进入停战期。默认按 `war.yml -> truce.baseHours` 与条约分数比例计算。可选 RealisticSeasons 模式用指定世界的日历推进新停战期：

```text
/wde debug realisticseasons
```

依赖、世界或日历不可用时使用现实时间备用截止点；旧停战记录维持创建时的计时类型。

## 9. 意识形态与角色背景

### 9.1 意识形态

命令及 GUI：

```text
/wde ideology
/wde ideology list
/wde ideology info <名称>
/wde ideology create <名称>
/wde ideology treasury <名称>
/wde ideology donate <名称> <默认货币金额>
/wde ideology settithe <名称> <fixed|wealth_percentage> <额度>
/wde ideology setplayer <名称>
/wde ideology setplayer <玩家> <名称|none>
/wde ideology setnation <国家> <名称|none>
/wde ideology settown <城镇> <名称|none>
/wde ideology setmemes <名称> <模因1> [模因2] [模因3] [模因4]
/wde ideology abdicate <名称> <玩家>
/wde ideology excommunicate <名称> <player|town|nation> <目标>
```

创建者在创建成功后自动成为新意识形态追随者与领袖，只支付创建费用。自主首次选择免费，之后改信按配置收费；强迫改信不享受首次免费。玩家、国家、城镇费用来源及联盟折扣按对应模块规则。玩家侧不再支持把个人意识形态主动清空为 `none`；GUI 中始终只保留一个当前个人意识形态。

已经担任任意宗教领袖的玩家不能再次创建意识形态。按 UUID 检查全部宗教的当前领袖，命令在扣费前拒绝，菜单禁用创建按钮，管理员代建也受此限制。交出所有领袖职位后可以再次创建；仅改信或放弃信仰不能绕过限制。现有数据不会自动删除或重分配职位。

模因与戒律修改冷却：

- `ideology.yml -> cooldowns.mode` 支持 `REAL_TIME` 和 `REALISTIC_SEASONS`。前者按现实天计算，后者按 RealisticSeasons 日历天计算。
- `cooldowns.world` 指定 RealisticSeasons 取日历的世界。若模式为 `REALISTIC_SEASONS` 但插件、日历或世界不可用，会自动回退到现实天，不会让修改永久锁死。
- `cooldowns.memes.days` 控制整组模因修改后的冷却天数；`cooldowns.doctrines.days` 控制单条戒律态度修改后的冷却天数。设为 `0` 表示关闭该类冷却。
- 模因冷却按整个意识形态记录；一旦保存新的模因组合，在冷却结束前不能再次修改该意识形态的模因。戒律冷却按每条 doctrine 单独记录，A 戒律冷却中不影响 B 戒律。
- 玩家 GUI、`/wde ideology setmemes` 以及管理员 `ideology memes/doctrine` 入口都会遵守冷却；管理员修改同样会刷新冷却计时。

教廷献金与什一税：

- 每个意识形态独立持有一个默认货币金库，余额与税额保存在原有 SQLite/MySQL 宗教记录中。没有取款、退款献金或管理员提现入口，领袖也不例外。
- 任意玩家都可向任意意识形态献金，`donate` 从玩家当前世界的默认货币余额扣款；菜单需要二次确认，成功后播放音效。
- 仅当前领袖可设置什一税。`fixed 100` 表示每人每日 100 默认货币；`wealth_percentage 10` 表示每日当前财富的 10%。比例上限 100%，定额上限 1000000000000，最多 8 位小数，0 为停征。
- 征税由 Towny `NewDayEvent` 触发，在主线程执行，面向 WDER 居民记录中当前个人信仰所属宗教的全部玩家，包括离线信徒和领袖。不依据城镇/国家信仰额外征税，不受城镇征召兵免税特权影响。
- 比例税基为 `config.yml` 已配置且实际可用币种的折算财富，严格区分币种大小写。固定税与比例税均优先扣默认货币，不足时按汇率补收其他币种；不足只收已有资金，不累积欠税。
- `ideology.yml -> economy.treasury.taxWorld` 指定每日征税查询和扣款的世界，默认 `world`，包括在线与离线玩家均使用它。经济插件按世界分账时，只统计这个世界，避免重复计入；世界未加载时跳过当日征税并警告。
- `enabled` 控制献金和征税；`titheEnabled` 单独控制自动征税。新宗教默认比例 10%，由 `defaultTitheType`、`defaultTitheAmount` 控制，领袖可调整。旧宗教缺失字段时金库与税额均为 0，须由领袖设税后才收费。
- 入账先提交单条数据库记录，成功后再发布内存余额。存储失败时不入账，并尝试把刚扣的各币种原额退回；这不是从金库取款。跨经济插件与数据库不能保证断电级原子性，退款失败会记录严重日志，管理员应核对。
- 配置和菜单文案支持 `/wde reload`。不要重排默认货币或改变现有金库的记账单位；金库余额不会在更换默认货币后自动换算。

模因用于信息展示和戒律态度筛选，本身不直接产生数值效果。模因和戒律图标写在 `ideology.yml` 对应定义的 `icon` 字段中，使用原版物品材质名。定义是可选的：删除定义后该选项不再显示，也不参与约束或效果；重载不会自动补回，已保存的玩家选择会保留但暂不生效。内置效果已接入穿着护甲、饮食戒律及宰杀动物相关戒律。

玩家击杀动物后，如果相关戒律均未被违反，会获得短暂抗性提升；违反任一适用戒律则获得虚弱。`slaughter_animals` 适用于动物击杀，`killing_innocent_animals` 只适用于不会攻击或反击玩家的动物。持续时间及效果等级由 `ideology.yml -> doctrineEffects.animalKilling` 配置；未配置适用戒律时不会触发效果。

饮食映射配置：

- `foods.yml -> mapping.vanilla` 使用原版材质名；`mapping.craftengine` 使用完整 CE 物品 ID。分类值为 `VEGETARIAN`（素食）、`MEAT`（肉食）、`HUMAN_MEAT`（人肉）、`BLOOD`（血食）。
- 已识别的 CE 物品优先使用 CE 映射，未配置时不按其原版底材判定。未映射食物、普通药水不奖惩；没有个人意识形态或没有适用饮食规则的玩家也不奖惩。
- 默认将 `world_dynamics_engine:blood` 分类为血食，`world_dynamics_engine:blood_meat` 分类为人肉，可自行调整。映射只用于分类，不能把普通物品变成食物，CE 仍需配置可食用行为并触发服务器进食事件。
- `namespace:wder/meat_eating` 的 `abhor_meat/fear_meat/disgust_meat` 允许素食，肉食和人肉违背；`anti_vegetarian_disgust/hate/abhor` 允许肉食和人肉，素食违背。
- 人肉同时检查肉食和 `namespace:wder/cannibalism`。食人戒律 `abhor/fear/disgust` 违背，`accept/enjoy/crave/greedy` 不违背。允许食人不代表强制所有食物都必须为人肉。
- 血食只检查已配置的 `namespace:wder/blood_feeding`，负面态度 `abhor/fear/disgust` 违背，`accept/enjoy/crave/greedy` 不违背。旧版 `wde` ID 也可识别；若定义不存在，该戒律不显示也不参与判定，重载不会自动补回。
- 任意适用规则违背即获得虚弱，否则获得力量；未知态度跳过，不按未知规则奖励。违背时沿用 `message.yml` 戒律提示及其冷却。
- `effects.durationSeconds` 默认 30，`strengthLevel/weaknessLevel` 默认 1，可配置 0～10 级，0 不提供该效果，时长限制 1～3600 秒；`enabled: false` 关闭饮食奖惩。原版进食、食物中毒、容器回收等行为不改变。
- 护甲与饮食原版效果统一按来源求和。同来源重复刷新不自我叠加，不同来源同类型等级相加；饮食切换力量/虚弱时替换本来源旧贡献。活跃戒律会覆盖同类型药水或其他插件效果，贡献清空不恢复旧效果；其他类型不受处理器影响。牛奶清除后，有效戒律贡献可能在下一次核对时重新施加。
- 死亡、离线、改信、戒律态度变更、关闭意识形态及 `/wde reload` 清除旧贡献；重载后持续护甲效果重新判定，饮食效果需再次进食。计时使用服务器 tick，每个限时来源独立到期。
- 只在成功进食后判定，取消进食不奖惩。效果延迟到进食完成后的下一主线程任务应用，避免被牛奶的原版清除效果覆盖；蛋糕仅在实际吃下一口后判定。
- `/wde reload` 重新读取整个映射和效果配置，缺失的开关/效果字段自动补全；不会自动补回你删除的映射条目。

违反已有戒律效果时的提示位于 `message.yml -> ui.doctrine_violation`；将文本设为空字符串可关闭提示，`ui.doctrine_violation_cooldown_seconds` 控制同一玩家、同一戒律的提示间隔。具体图标与提示配置见[意识形态提示与图标配置](意识形态提示与图标配置.md)。

意识形态制裁记录与贸易联盟制裁不同：前者当前主要是领袖/玩家身份数据，不能当作已经实现经济或领土封锁。

### 9.2 角色背景

`backgrounds.yml -> enabled` 开启后，背景分儿童期与成年期两阶段。各阶段只能选择一次，成年期必须在儿童期之后。`forceSelectionOnFirstJoin` 可在新玩家完成两阶段选择前限制移动。

背景标题、故事、技能增量和玩家名占位符均从配置读取。AuraSkills 为可选集成；若未安装或用户数据尚未就绪，奖励会按实现延迟补发或保持待处理。

```text
/wde background
/wde background status
/wde background list <childhood|adulthood>
/wde background info <childhood|adulthood> <id>
/wde background choose <childhood|adulthood> <id>
```

## 10. 旅馆与死亡掉落

### 10.1 Towny 旅馆床位费

`inn.yml` 开启后，可对准 Towny `INN` 地块内完整的床执行：

```text
/wde inn set <金额> [币种]
```

仅床位收款人（地块拥有者；无拥有者时为镇长）或该镇镇长可定价。命令在床脚附近生成/更新告示牌。非本镇居民成功入睡后收费，本镇居民免费；失败入睡不结算，成功入睡后才将费用转给收款人。

旅馆币种必须由经济提供者精确支持，不按汇率换算。若退款失败，服务端会记录 `INN REFUND FAILED`，管理员需核查并处理。Bed 价格数据单独保存在存储分类 `inn_beds`。

### 10.2 玩家死亡掉落池

`drops.yml -> playerDrops.enabled` 默认关闭。开启后每次死亡按 `rolls` 次抽取候选池，每次等概率选一项，再独立判断其 `dropChance`。失败不补抽；原版死亡掉落保留并额外添加 WDER 掉落。

条目类型为原版 `vanilla` 或可选 `craftengine`。CraftEngine 未安装、物品 ID 未加载或配置无效时，该条目不会正常生成。

## 11. 兼容与已知边界

- `plugin.yml` 将 AuraSkills、CraftEngine 和 RealisticSeasons 声明为软依赖；相关功能只有在对应插件和 API 可用时生效。
- CraftEngine 调试命令为 `/wde debug craftengine`；RealisticSeasons 调试命令为 `/wde debug realisticseasons`。
- SQLite 与 MySQL 之间没有自动数据迁移工具。切库前自行导出/导入并备份。
- 国家集团账户为默认货币余额，不支持多币种分账。
- 意识形态大部分模因和戒律没有实际游戏效果；不得把“配置里有定义”当作“玩法已经接入”。
- 目前没有覆盖所有命令的图形化管理界面；GUI 是管理入口，不替代所有命令，也不覆盖 Towny 原生土地和经济管理。
- 正常命令默认由 `wde.player` 开放，继续依据 Towny 身份与 WDER 职位判断操作资格。管理入口使用 `wde.admin` 及模块子权限；原有 `wde.debug`、`wde.reload` 仍可单独授权。
- 同时使用 Towny SiegeWar 等战争扩展前，应单独验证敌对状态、地块保护、中立和击杀计分是否冲突。
- 使用文档不承诺未经测试的插件组合、TPS 或并发安全表现。

## 集结传送配置

- `/wde rally nation`：本国各镇征召兵及当前 Towny 镇长主动传送到 WDER 军队统帅，费用从国家国库扣除。
- `/wde rally town`：本镇征召兵主动传送到当前 Towny 镇长，费用从城镇金库扣除。
- `nation.yml -> rally.enabled/cost` 控制国家集结，默认启用、每次 250 默认货币；`town.yml -> rally.enabled/cost` 控制城镇集结，默认启用、每次 100 默认货币。支持 `/wde reload`，旧配置缺失项自动补全。
- 费用由系统配置决定，无玩家改价入口。`cost` 不得为负，最多 8 位小数，上限 1000000000000；0 表示免费。国家集结还要求 `armyEnabled` 开启。
- 资格以实时 Towny 归属和 WDER 征召兵名单为准；管理员身份不绕过资格。军队统帅及镇长在线时即提供集结目标，不需要逐个批准成员请求。
- 主菜单只向符合身份的玩家显示按钮，并提供二次确认；最终命令再次校验资格、冻结状态、费用和目标。
- 扣费通过 Towny `BankAccount`，不扣成员个人余额。目标是命令执行时的实时坐标，不是城镇出生点。使用标准插件传送事件，保留贸易制裁和其他插件拦截。
- 取消或传送异常时尝试原额退回同一金库，退款失败记录严重日志。跨插件扣费与传送不能提供断电级原子性，应检查异常日志。
