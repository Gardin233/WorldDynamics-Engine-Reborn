# WDER 使用文档

> [Wiki 首页](README.md) · [玩家玩法](玩法说明.md) · [权限与管理员指令](权限组与管理员指令.md) · [插件机制说明](插件机制说明.md) · [国家史书机制](国家史书机制.md)

本文面向服主和管理员，说明安装、配置、命令入口与运行边界。实际生效值以服务端 `plugins/WorldDynamicsEngine-Reborn/` 下的配置为准。

## 1. 插件与依赖

WorldDynamicsEngine:Reborn（WDER）在 Towny 的城镇、国家和居民数据之上，提供国家治理、国家集团、战争与和约、意识形态及背景机制。它不取代 Towny 的创建、圈地、领土权限或原生金库。

运行要求：

- Java 21
- Paper 1.21.x
- Towny
- Vault API 兼容的经济提供者

AuraSkills、CraftEngine、RealisticSeasons 是可选依赖。缺少可选插件时，对应的技能奖励、自定义物品或日历时间联动不可用；依赖缺失不应阻止基础模块运行。多币种操作需要经济提供者真实支持配置的货币，不能仅凭汇率配置推断经济服务支持该币种。

## 2. 安装与启动

1. 将 WDER JAR 放入服务端 `plugins` 目录。
2. 安装 Towny 与 Vault 兼容的经济插件。
3. 使用 Java 21 启动 Paper。
4. 检查启动日志中的依赖和数据库初始化信息。

SQLite 数据表会自动创建。MySQL 数据库需预先创建，连接账号需要表的读写和建表权限。缺少 Towny 或 Vault 经济服务时，WDER 会停用。

## 3. 配置文件

配置位于 WDER 插件数据目录：

| 文件 | 主要用途 |
| --- | --- |
| `config.yml` | 全局模块开关、货币、经济、存储与居民税接管 |
| `nation.yml` | 国家政体、选举、集结及国家史书开关 |
| `town.yml` | 城镇政体、选举、征召兵、常规城镇战争与集结 |
| `organization.yml` | 集团类型、维护费、主权帝国自治、贡税与军事义务 |
| `war.yml` | 战争理由条件、战争分数、和平条款和停战期 |
| `ideology.yml` | 意识形态、模因、戒律、费用和金库税制 |
| `backgrounds.yml` | 儿童期、成年期背景及 AuraSkills 增量 |
| `foods.yml` | 食物分类和饮食戒律效果 |
| `drops.yml` | 玩家死亡额外掉落池 |
| `inn.yml` | Towny INN 床位费 |
| `event.yml` | 国家史书事件句子模板、日期格式、书名和命令提示 |
| `message.yml` | GUI 标题、说明与菜单文案 |
| `lang/` | 命令和系统消息多语言文本 |
| `data/worlddynamics-engine.db` | 默认 SQLite 数据库 |
| `history/<史书UUID>/` | 国家史书 JSON 事件文件及 TXT 导出 |

全局模块开关位于 `config.yml`。意识形态和背景另有各自配置开关；国家史书使用 `nation.yml -> history.enabled`。

### 存储和货币

`config.yml -> storage.type` 支持 `sqlite` 和 `mysql`，默认 SQLite。数据库后端或连接参数变更需要完整重启；WDER 不提供 SQLite 与 MySQL 的自动迁移。

`economy.exchangeRates` 第一项必须与 `economy.defaultCurrency` 完全一致，该项是运行时默认货币。货币 ID 区分大小写，例如 `USD` 与 `usd` 不同。Towny 国家、城镇金库和国家集团余额以默认货币结算；集团账户不支持按币种分账。

## 4. Towny 同步、保存与重载

- 启动时读取现有 Towny 城镇与国家，并为缺少 WDER 治理档案的对象建档，不重置已有治理数据。
- 运行期间的创建、删除、改名、入国、退国等生命周期由 Towny 事件维护，不靠周期性扫描补齐。
- `/wde reload` 重载配置、语言、菜单与相关任务，但不重新扫描 Towny 数据。
- 修改 `storage.*` 后必须重启。插件会自动补齐部分旧配置缺失字段，不覆盖已存在值，也不替服主重新平衡已有参数。

```text
/wde reload
/wde debug balance <玩家> [货币]
/wde debug craftengine
/wde debug realisticseasons
```

`/wde debug` 子命令需要 `wde.debug`，重载需要 `wde.reload`。完整权限节点和管理员命令见[权限与管理员指令](权限组与管理员指令.md)。

## 5. 常用入口

```text
/wde
/wde help [页码]
/wde nation [国家名] [menu]
/wde town [城镇名] [menu]
/wde org [menu]
/wde war [menu]
/wde ideology [menu]
/wde background
/wde rally <nation|town>
/wde history <list|read|txt|book>
```

GUI 用于浏览和发起操作；最终命令仍会重新检查玩家身份、权限、费用、战争状态和目标归属。普通玩家权限为 `wde.player`，实际操作仍受 Towny 职位和业务规则限制。

## 6. 治理与国家集团

国家政体为 `DICTATORSHIP`、`DEMOCRACY`、`NOBLE_COUNCIL`；城镇政体为 `DICTATORSHIP`、`REPUBLIC`。独裁制界面不会展示选举操作。选举周期、候选人和投票资格分别由 `nation.yml`、`town.yml` 和玩家在 Towny 中的身份决定。

国家集团只以国家作为成员单位，类型为：

- `TRADE_ALLIANCE`：贸易联盟及联盟制裁
- `MILITARY_ALLIANCE`：成员国入盟投票和集团宣战投票
- `SOVEREIGN_EMPIRE`：主席国管理从仆国的国家层级事务
- `IDEOLOGICAL_ALLIANCE`：绑定意识形态并提供相应联盟规则

主权帝国从仆等级为傀儡国、保护国、自治领，并可标记为卫戍国。自治、镇压、税率上限、贡税、强制参战及卫戍巡检参数位于 `organization.yml`。主席国不直接管理从仆国下属城镇。

城镇与国家使用 Towny 的实时归属。民主国家领袖变更会尝试同步 Towny 国王；首都转让时，按剩余城镇人口优先、名称排序选择继任首都。

### 外交致函

国王、政府领袖或军队统帅可代表本国向其他国家发送侮辱、通知或请求信：

```text
/wde diplomacy letter <目标国家> <insult|notice|request> <正文>
/wde diplomacy letters <页码>
/wde diplomacy readletter <信件UUID> [页码]
```

正文最多4000字符，发送后不支持修改；命令中的空格会保留。费用由发信人的个人钱包支付，配置位于 `config.yml -> diplomacy.letters.cost.amount/currency`，默认100默认货币，0免费，修改后 `/wde reload`。

信件按收发国家UUID保存，目标国家成员在线时收到通知；目标领导者离线也可稍后查收。读取与列表需要上述外交身份，仅收发两国可读取原始信件。侮辱信不会自动设为敌对或宣战。

史书采集开启时双方各记一条事件，正文亦保存在事件参数中，默认史书句子只展示类型，例如“于2026年10月19日，甲国向乙国发表了一封言辞激烈的信”。通知信为“正式的信”，请求信为“充满恳切的信”。措辞由 `event.yml` 调整，使用史书所选现实或季节日期。史书是公开历史，不应在信中填写隐私或秘密。

## 7. 战争、和约与停战

玩家手动选择战争理由，系统在菜单、命令和投票结算时校验资格。理由包括征服、收复失地、独立、圣战、贸易冲突、羞辱宿敌、输出革命和摧毁威胁。主要资格为：

- 输出革命：发起国是民主制。
- 收复失地：目标国拥有符合配置连续持有时长的本国旧城镇。
- 贸易冲突：目标贸易联盟正在制裁发起国。
- 羞辱宿敌：双方互相敌对。
- 圣战：双方均有意识形态且不同。
- 摧毁威胁：目标为军事同盟或主权帝国主席国。
- 独立：城镇向所属国家，或仆从国向帝国主席国。

常用命令：

```text
/wde war
/wde war declare nation <目标国家> <理由>
/wde war declare town <目标城镇或所属国家> <理由>
/wde war focus
/wde org declarewar <军事同盟> <目标国家> <理由>
/wde org votewar <军事同盟> <目标国家> <yes|no>
/wde org peacetreaty [集团名]
/wde org reviewtreaty [集团名]
```

国家战争直接开战；军事同盟成员须提交宣战提案并按权重投票。占领分每 `war.yml -> scoring.cycleSeconds` 累计，击杀分即时计算。分数用于战争详情和和约预算，不会单独触发自动胜负。中立保护、停战期、Towny spawn 限制、防守方复活冻结及城镇战争开关共同约束战争行为。

和约条款由后端校验可用性，包括赔款、强制改信、转城、解散或退出军事联盟、解放从属国、通行、羞辱、掠夺首都、长期贡金、强制附庸与允许独立。总分和条款分值由 `war.yml -> peaceTreaty` 控制。接收方接受后才执行；条款点数与停战时长均不代表所有外部经济动作已到账。

现有独立机制已并入普通战争理由，不再有独立战争专属计分周期或按分差强制接受。主权帝国自治领可依规则支付费用和平独立；从仆国执行 `leave` 会进入战争菜单，不会自动宣战。

完整限制、计分、和约状态及 Towny 联动见[插件机制说明](插件机制说明.md)。

## 8. 意识形态与背景

意识形态数据配置在 `ideology.yml`。玩家个人、城镇和国家各有归属；创建者自动成为新意识形态的追随者和领袖。模因用于展示与戒律态度筛选，戒律实际效果只在对应实现存在时生效。图标可使用原版材质名或完整 CraftEngine 物品 ID。

```text
/wde ideology list
/wde ideology info <意识形态>
/wde ideology create <名称>
/wde ideology setplayer <意识形态>
/wde ideology setnation <国家> <意识形态|none>
/wde ideology settown <城镇> <意识形态|none>
/wde ideology setmemes <意识形态> <模因1> [模因2] [模因3] [模因4]
```

国家和城镇政体、意识形态、领袖等变更会进入国家史书（需启用）。

背景分儿童期和成年期，必须依次选择；配置位于 `backgrounds.yml`。强制选择开关可让未完成选择的玩家暂时无法移动。AuraSkills 奖励需要相应插件可用。

## 9. 国家史书

`nation.yml` 中的 `history.enabled` 控制是否采集。当前资源配置已启用；若需停用可设为 `false` 后 `/wde reload`。时钟支持：

```yaml
history:
  enabled: true
  clock: REAL_TIME
  world: world
```

`REAL_TIME` 按服务器现实日期分组；`REALISTIC_SEASONS` 使用指定世界日历，无法读取时该事件回退现实日期。`event.yml` 定义事件句子和占位符。

国家史书使用永久 UUID 索引保存在 SQLite/MySQL；每个事件另生成一个 JSON 文件，存于 `history/<史书UUID>/`。国家解散后只归档，不删除索引与历史；显示名附现实存续日期。历史停用期间不会补造普通事件；重新启用时重新采集当前快照。

```text
/wde history list [页码]
/wde history read <国家名或史书UUID> [页码]
/wde history txt <国家名或史书UUID>
/wde history book <国家名或史书UUID> [卷号]
```

TXT 写入史书目录，成书为“XXXX的史书”，长内容可分卷领取。史书机制、事件字段和归档边界见[国家史书机制](国家史书机制.md)。

## 10. 其他模块与上线检查

- `inn.yml`：Towny INN 床位费。成功入睡后收费，本镇居民免费；床位定价单独保存。
- `drops.yml`：玩家死亡时额外抽取物品，不替换原版掉落；支持原版与 CraftEngine 物品。
- `foods.yml`：原版与 CE 物品分类以及饮食戒律效果。
- `message.yml` 与 `lang/`：GUI、命令提示及多语言文本。
- `rally`：成员主动传送至军队统帅或镇长位置，费用由国家或城镇金库承担。

首次上线前确认 Java 21、Paper、Towny 和经济服务正常；备份 SQLite/MySQL；核对默认货币；测试国家与城镇同步、权限、和约执行和可选插件联动。启用史书后，另测试初始化接管、新国家成立、城镇归属变更、战争和约、解散归档、TXT 与分卷成书。

WDER 不承诺未实测的插件组合、经济原子性、TPS 或第三方直接绕过标准事件的行为。存储备份应覆盖数据库和 `history/` 目录。
