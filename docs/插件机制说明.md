# WorldDynamicsEngine:Reborn（万邦演变引擎:重生）插件机制说明

> [Wiki 首页](README.md) · [玩家玩法](玩法说明.md) · [服主使用文档](使用文档.md) · [数据库设计](数据库设计检查.md)

## 1. 文档定位

这份文档用于说明 `WorldDynamicsEngine:Reborn` 当前版本已经实现的机制结构、状态流转、权限边界、配置承载方式以及各模块之间的联动关系。

它与 [使用文档](./使用文档.md) 的分工不同：

- `使用文档.md` 侧重安装、命令、配置示例和操作流程
- `插件机制说明.md` 侧重规则设计、当前实现边界、运行原理和审查重点

如果你需要核对数据库承载方式，可以再配合阅读 [数据库设计检查](./数据库设计检查.md)。

---

## 2. 运行前提与总体思路

当前工程以以下环境为目标：

- `Java 21`
- `Paper API 1.21`
- `Towny`
- `Vault / VaultUnlocked`
- `AuraSkills`（可选软依赖，仅用于角色背景技能等级增量）

插件当前的设计目标不是替代 Towny，而是在 Towny 的世界、城镇、国家、金库与居民归属之上，再叠加一层“治理规则引擎”。

职责划分可以概括为：

- `Towny` 负责底层事实：城镇、国家、居民归属、Towny 原生金库、部分原生外交事实
- `WDER` 负责扩展治理：政体、选举、政府班子、军队、国家集团、意识形态、角色背景、多货币换算与税收接替

因此，当前系统本质上是：

```text
Towny 基础事实层 + WDER 治理扩展层
```

## 3. 架构总览

### 3.1 三层主架构

当前主业务采用三层分级：

1. 城镇
2. 国家
3. 国家集团

核心关系如下：

- 国家记录其下属城镇
- 城镇记录其所属国家
- 国家集团只接受“国家”作为成员单位
- 居民不再作为国家集团成员直接参与集团治理

### 3.2 辅助数据层

在三层主架构之外，还存在四个辅助维度：

- 居民扩展数据
- 角色背景数据
- 意识形态数据
- 外交与经济桥接数据

这些辅助层不单独构成新的行政层级，但会直接影响权限、费用、数值变化与可执行动作。

## 4. 数据与存储机制

### 4.1 存储后端

主业务数据支持两种后端：

- `sqlite`
- `mysql`

默认后端为 `sqlite`。

规则：

1. 当 `storage.type=sqlite` 时，数据写入插件目录下的 `data/worlddynamics-engine.db`
2. 当 `storage.type=mysql` 时，数据写入指定 MySQL 数据库
3. 当前支持自动建表，不支持自动建库
4. 当前未实现 `sqlite -> mysql` 或 `mysql -> sqlite` 的自动跨库迁移

### 4.2 当前承载分类

当前核心数据分类包括：

- `towns`
- `nations`
- `organizations`
- `residents`
- `religions`

其中前台术语已经统一为“意识形态”，但底层分类仍保留 `religions` 这一历史键名，用于兼容旧结构。

### 4.3 当前落库方式

当前数据由 `DataStorageManager` 统一管理，整体采用“按分类存储实体快照”的方式。

这意味着：

- 实体对象在内存中以 Java 模型长期存在
- 保存时按分类批量序列化
- 加载时再恢复为内存对象

这个方案的优点是模型演化灵活、实现简单；缺点是数据库本身不承担复杂查询职责，更适合插件内存驱动而不是后台强查询场景。

### 4.4 居民扩展数据

居民扩展数据当前除了基础身份外，还承担以下状态：

- 意识形态归属
- 是否已完成意识形态首次选择
- `儿童时期` 背景选择结果
- `成年时期` 背景选择结果
- 已经发放过的背景 AuraSkills 加成记录
- 其他扩展标记 `flags`

也就是说，角色背景不是单纯的展示配置，而是已经进入居民长期存档的一部分。

### 4.5 启动加载、事件接管与自动保存

城镇与国家采用“每次启动加载 + 生命周期事件维护”，不通过定时任务查询 Towny 中是否缺失，并据此补建或删除记录。

1. 每次插件启动都会读取 Towny 的现有城镇、国家，并为缺少 WDER 记录的对象建立治理数据，不再使用一次性导入标记。
2. 新建治理记录默认 `DICTATORSHIP`（独裁）、意识形态 `None`，首次改信资格尚未使用；镇长与国家领袖分别取当前 Towny 镇长和国王。
3. 已有 WDER 政体、信仰与其他治理数据不重置；旧国家记录中未设置的政体 `None` 自动规范为独裁。
4. 启动加载会更新现有城镇所属国家，并重建国家下属城镇列表，随后保存城镇与国家数据；不会仅因 Towny 列表中缺少某对象而删除既有 WDER 记录。
5. `/wde reload` 不重新扫描城镇、国家列表；停服仅保存已有记录，不执行存在性对照。
6. 后续 Towny 创建事件立即初始化并保存治理记录，重复创建事件不会重置已有记录。删除事件移除对应记录；改名事件保留治理数据并维护城镇、国家的名称和层级关系。
7. 城镇入国、退国事件直接维护双向层级；镇长变更、成功的国王变更事件更新对应领袖。居民入镇、离镇后更新征召兵名单。

定时任务仍负责选举推进与存档。居民数据的既有导入逻辑不在本次城镇、国家生命周期接管范围内。

Towny 仍负责原生创建流程、领土、金库和居民归属；WDER 接管其成功创建后的治理记录，不新增独立建镇或建国命令，也不绕过 Towny 的创建条件或费用。

注意：WDER 停用期间新建的城镇、国家可在下次启动时补建治理记录，城镇归属也会重新加载。但停用期间的删除、改名及其他扩展关联变化，不会由启动加载自动清理或完整迁移。

## 5. Towny 与 WDER 的权力分工

这是整套系统最重要的理解前提。

### 5.1 Towny 负责什么

- 城镇与国家的存在性
- 居民所属城镇 / 国家
- Towny 城镇金库与国家国库
- Towny 原生税制与部分原生外交事实

### 5.2 WDER 负责什么

- 城镇政体与国家政体
- 镇长 / 国王之外的治理职位
- 选举与投票
- 军队与征召兵扩展
- 国家集团及其规则
- 意识形态、模因与戒律态度约束
- 角色背景与 AuraSkills 增量接入
- 多货币费用与税收接替
- 部分外交限制与访问收费

### 5.3 当前设计的直接结果

这会带来两个直接结果：

1. 城镇与国家的生命周期通过 Towny 事件维护，不依赖周期性存在性扫描
2. 国家接管的居民税制在配置动作和每日税收前写回 Towny，不依赖周期扫描

最典型的例子就是国家对城镇税制的接管。

## 6. 角色背景机制

### 6.1 定位

角色背景机制是当前新增的一套“居民个人成长档案”系统。

它当前承担三类职责：

- 为玩家建立可配置的阶段化背景选择
- 为玩家提供一次性的 AuraSkills 技能等级增量
- 在需要时强制玩家先完成背景选择，再允许正常移动

### 6.2 两阶段结构

当前背景选择分为两个固定阶段：

1. `儿童时期`
2. `成年时期`

规则：

1. 玩家必须先选择 `儿童时期`，再选择 `成年时期`
2. 两个阶段各只能选择一个背景
3. 一旦某阶段已选定，就不能再次修改
4. 当两个阶段都选完后，背景选择永久完成

### 6.3 背景配置结构

背景定义由独立配置文件 `backgrounds.yml` 承载，而不是塞回 `config.yml`。

每个背景当前包含：

- 唯一 `id`
- `title`
- `lore`
- `skillLevelBonuses`

其中 `skillLevelBonuses` 采用如下写法：

```yml
skillLevelBonuses:
  "auraskills/farming": 1
```

规则：

1. 只允许正数增量
2. 当前只做“增加”，不做覆盖或降低
3. 支持 `auraskills/farming`、`auraskills:farming` 两种写法
4. 如果未写命名空间，则默认按 `auraskills` 处理

### 6.4 玩家锁定与强制选择

配置项 `forceSelectionOnFirstJoin` 控制是否启用“未完成背景前限制移动”。

规则：

1. 该项为 `false` 时，玩家可自由延后选择背景
2. 该项为 `true` 时，只要玩家尚未完成两个阶段的全部背景选择，就会被限制移动
3. 玩家进入服务器后会收到提示，告知当前必须选择的阶段与对应命令
4. 当前移动限制通过 `PlayerMoveEvent` 实现，未完成前无法离开原位置

### 6.5 AuraSkills 兼容逻辑

角色背景的数值奖励当前通过反射兼容 `AuraSkills`。

这意味着：

1. 插件本身不强制要求 AuraSkills 存在
2. `plugin.yml` 中仅将 `AuraSkills` 作为 `softdepend`
3. 如果 AuraSkills 未安装、未启用或玩家 AuraSkills 用户对象尚未加载，则不会报致命错误
4. 未能发放的背景奖励会保留为“待补发”
5. 玩家后续上线或插件下次触发补发时，会再次尝试发放

为避免重复加点，居民数据中会记录哪些背景奖励已经发放过。

### 6.6 当前命令与展示能力

当前已接入以下命令：

- `/wde background status`
- `/wde background list <childhood|adulthood>`
- `/wde background info <childhood|adulthood> <id>`
- `/wde background choose <childhood|adulthood> <id>`

命令行为规则：

1. 只有玩家可执行 `status` 和 `choose`
2. `choose` 必须按阶段顺序执行
3. 已完成的阶段不能重复选择
4. 全部完成后不可重选

### 6.7 背景描述占位符

当前背景 `lore` 已支持玩家名占位符：

```text
%player_name%
```

当前效果为：

1. 配置中可以直接写 `%player_name%`
2. 玩家使用 `/wde background info ...` 查看背景详情时，会将其替换为玩家当前名字
3. 默认示例背景文案已经全部改为该占位符写法

### 6.8 配置补全策略

`backgrounds.yml` 已接入自动缺失补全。

规则：

1. 插件启动或重载时，会自动补齐缺失的总开关、强制选择开关和默认背景示例
2. 自动补全只补缺失项，不会强行覆盖服主已经改过的现有背景文案

## 7. 城镇机制

### 7.1 城镇政体

当前支持两种城镇政体：

- `DICTATORSHIP`
- `REPUBLIC`

规则：

1. 独裁制下，镇长可直接指定
2. 共和制下，城镇按现实日周期进入选举
3. 共和制是多候选人竞选，而不是单候选人表决
4. 候选人过半可提前胜出
5. 若到期后最高票出现平票，则本轮作废

### 7.2 镇长与 Towny 同步

当前城镇存在两套相关身份：

- Towny 的 `Mayor`
- WDER 的 `townLeader`

同步规则：

1. 首次导入或创建治理记录时，参考 Towny 镇长
2. 当 WDER 选举或命令成功改变镇长后，会反向写回 Towny
3. Towny 镇长成功变更后，通过事件更新 WDER 镇长数据

### 7.3 城镇意识形态

城镇默认意识形态为 `None`。

规则：

1. 首次选择免费
2. 再次变更收费
3. 费用从 Towny 城镇金库扣除
4. 若配置货币不是默认货币，会先换算为默认货币再扣费

### 7.4 居民税制与国家接管

城镇还支持独立的旅馆床位收费：仅对 Towny `INN` 地块内成功入睡的非本镇居民收费；默认价格由 `inn.yml` 控制，单床覆盖价持久化于 `inn_beds`。定价权限属于地块拥有者或本镇 Towny 镇长，要求床尾存在可放置告示牌的位置，并通过方块放置事件接受保护插件校验。告示牌生成失败时不保存定价。

床位费先以指定币种预扣，下一 tick 确认玩家在目标床内睡觉后向当前地块拥有者（无拥有者则为镇长）的私人钱包入账；被取消入睡或入账失败时尝试原币种退款，退款失败记录详细日志。费用不使用 Towny 金库，也不调用汇率转换。普通 Vault 仅允许默认币种，多币种要求 VaultUnlocked 提供者支持对应币种。

每个城镇都维护自己的居民税制扩展字段，支持：

- `FIXED`
- `WEALTH_PERCENTAGE`

规则：

1. 首次导入、新建记录和每日税收前，未由国家接管的税制从 Towny 读取
2. 当国家接管后，配置动作与每日税收前会把已保存税制写回 Towny
3. Towny 侧对已接管税制的手改可能在下一次税收前被覆盖，不再通过每五分钟扫描覆盖

### 7.5 征召兵机制

每个城镇都可以维护自己的征召兵名单。

规则：

1. 征召兵必须是本镇居民
2. 默认上限为城镇人口的 `50%`
3. 比例由 `town.yml -> townConscriptLimitRatio` 控制
4. 居民入镇、离镇事件发生后，清理失效名单并重新检查人口容量
5. 目前已实现的征召兵特权为 `taxfree`
6. 若某城镇所属国家被设为主权帝国的“卫戍国”，则该城镇征召兵容量直接提升为人口的 `100%`

### 7.6 城镇常规战争开关

当前 `town.yml` 已提供：

```text
allowRegularWarParticipation
```

规则：

1. 默认值为 `false`
2. 当该项为 `false` 时，城镇不能通过 Towny 的常规战争逻辑关闭中立保护
3. 该限制只用于屏蔽“城镇 vs 城镇 / 城镇 vs 国家”的常规战争参与
4. 该限制不会介入 WDER 的主权帝国独立战争
5. 该限制也不用于阻断用户定义的“城镇独立战争”类机制

## 8. 国家机制

### 8.1 国家政体

当前支持三种国家政体：

- `DICTATORSHIP`
- `DEMOCRACY`
- `NOBLE_COUNCIL`

规则：

1. 独裁制下，国王直接掌握主要任命权
2. 民主制下，国家领袖候选池固定为各下属城镇镇长
3. 贵族议会制下，镇长群体构成核心投票层
4. 民主制到期自动发起换届
5. 现任领袖可提前发起民主选举，但会自动从候选池中排除自己

### 8.2 国家层角色结构

当前国家层并不是“只有 Towny 国王一个权力中心”，而是并行存在多类职位：

- Towny 国王
- WDER 政府领袖
- WDER 军队统帅
- 政府成员
- 军队成员
- 外交官

这是一个“Towny 法定领袖 + WDER 扩展治理班子”的结构。

### 8.3 国家意识形态

国家默认意识形态为 `None`。

规则：

1. 首次选择免费
2. 再次改宗收费
3. 费用从国家国库扣除
4. 若配置货币不是默认货币，会先折算后扣除

### 8.4 国家对城镇税制的独立分配

国家可以按城镇维度，为下属城镇分别指定居民税制类型与额度。

规则：

1. 只能修改本国下属城镇
2. 可执行者为国王、政府领袖或军队统帅
3. 设置成功后会立即同步写回 Towny
4. 若该国是主权帝国从仆国，则还需额外受到自治等级税收上限限制

### 8.5 军队与跨国调度

当前军队系统主要是“身份与权限系统”，不是完整的职业战斗系统。

已实现重点包括：

- 任命军队统帅
- 维护军队成员名单
- 传送到本国征召兵
- 在主权帝国内进行有限跨国调度

具体表现为：

1. 主权帝国主席国军队统帅可以传送到从仆国在线征召兵
2. 从仆国军队统帅可以传送到主席国军队统帅

## 9. 意识形态机制

### 9.1 定位

前台术语已经统一为“意识形态”，不再向玩家暴露“宗教”作为主要前台名称。

它当前主要承担三类职责：

- 身份与归属展示
- 改信费用与治理限制
- 模因 / 戒律态度的配置约束

### 9.2 默认状态与改信规则

以下对象默认都为无意识形态：

- 玩家
- 城镇
- 国家

基础规则：

1. 玩家首次选定意识形态免费
2. 城镇首次选定意识形态免费
3. 国家首次选定意识形态免费
4. 再次变更时，分别从个人钱包、城镇金库、国家国库扣费

### 9.3 强迫改信

当前存在两条强制链路：

1. 镇长 / 城镇领袖强迫本镇居民改信
2. 国家强迫下属城镇改宗

规则：

1. 强迫改信不享受首次免费
2. 强迫居民时，费用从城镇金库扣除
3. 强迫城镇时，费用从国家国库扣除
4. 镇长强迫居民时，只能改为城镇当前意识形态或所属国家当前意识形态
5. 国家强迫城镇时，只能改为国家当前意识形态

### 9.4 意识形态领袖与制裁

每个意识形态拥有一个意识形态领袖。

规则：

1. 创建者默认成为首任领袖
2. 领袖可以向同意识形态玩家禅让
3. 领袖可以制裁玩家、城镇、国家
4. 当前制裁主要是象征性状态，不直接带来数值效果

### 9.5 模因系统

模因系统当前已经独立成展示层与限制层，而不是效果承载层。

规则：

1. 每个意识形态最少 1 个模因，最多 4 个模因
2. 模因必须互不重复
3. 模因可通过 `exclusive_with` 配置互斥
4. 模因本身不直接产生数值效果
5. 模因主要负责展示，以及限制某些戒律可切换到的态度

### 9.6 戒律系统

戒律与模因已经分离。

当前规则为：

1. 戒律负责“态度配置”
2. 模因负责“态度筛选与限制”
3. 每条戒律的第一项态度会作为默认态度
4. 戒律效果可通过外部注册事件扩展；已实现的内置效果由 WDER 自身逻辑执行

目前“穿着护甲”（`namespace:wder/armor_wearing`）戒律会根据玩家个人意识形态态度和护甲栏装备状态持续生效：

| 态度 | 符合态度的装备状态 | 符合时效果 | 不符合时效果 |
| --- | --- | --- | --- |
| 全裸 | 头盔、胸甲、护腿、靴子均未穿戴 | 急迫 I、速度 I | 缓慢 I、挖掘疲劳 I |
| 仅裤子 | 只穿护腿，其他护甲栏为空 | 急迫 I、速度 I | 缓慢 I、挖掘疲劳 I |
| 无规则 | 不检查装备状态 | 无 | 无 |
| 完全遮蔽 | 四个护甲栏均有装备 | 急迫 I、速度 I | 缓慢 I、挖掘疲劳 I |

效果只作用于玩家个人意识形态，不会由城镇或国家意识形态覆盖。Paper 的 `PlayerArmorChangeEvent` 在装备变化后触发重算；登录及装备损坏事件也会补做检查，不再周期扫描装备栏。整组持续贡献交给统一处理器；态度或装备状态变化时替换旧贡献，切到无规则时撤销贡献。其他戒律仍不一定具有内置效果。

饮食戒律通过 `FoodDoctrineListener` 和 `FoodDoctrineManager` 接入：

1. `foods.yml` 将原版材质或 CE 完整 ID 映射为素食、肉食、人肉、血食，识别 CE 后不会回退到原版底材。
2. `PlayerItemConsumeEvent` 未取消且实际完成后，下一主线程任务读取玩家当前个人意识形态并判定；蛋糕通过交互后饥饿值与咬数变化确认实际进食。
3. 素食/肉食检查 `meat_eating`，人肉同时检查 `meat_eating`、`cannibalism`，血食检查新增 `blood_feeding`。识别 `wde` 和 `wder` 两种戒律路径。
4. 任一适用规则违规时施加虚弱，否则施加力量；没有已知适用规则时不施加效果。负面食人/血食态度违规，认可、喜好、渴望、贪婪态度不违规。
5. 默认力量 I / 虚弱 I 持续 30 秒，配置等级为 0～10，0 不提供该效果。饮食作为一个限时来源提交统一处理器，重复进食替换旧贡献及刷新期限；力量和虚弱切换会撤销该饮食来源的旧效果。原版食品自身的其他效果保留，同类型药水效果按下述覆盖规则处理。
6. 食物映射和效果参数可热重载。模因或戒律定义从 `ideology.yml` 删除后，对应选项不再显示且不参与限制或效果；重载不会自动补回定义，已保存的选择会作为休眠数据保留。食品可食用能力仍由原版或 CraftEngine 定义；映射本身不制造进食行为。

### 9.7 统一原版戒律效果

`DoctrineBuffCalculator` 保存来源贡献，`DoctrineBuffManager` 是护甲、饮食和动物击杀戒律施加原版药水效果的统一入口。

1. 账本按玩家 UUID、来源 ID 和原版效果类型组织。提交非负逻辑等级；0 表示没有贡献，负数提交拒绝。同类型不同来源相加，不同效果类型分别计算，不自动抵消力量与虚弱等效果。
2. `replacePersistent` 替换持续来源，`replaceTimed` 替换限时来源。相同来源重复提交不自我累加；`adjustLevel` 可增减单个来源，结果限制为 0～256，不延长其期限；`removeSource` 撤销整组贡献。
3. 每次贡献变化重新求和，以最终等级覆盖旧效果。单来源及最终等级上限为 256，逻辑 I 级转换为 Bukkit amplifier 0；总等级为 0 时撤销该类型效果，不施加负 amplifier。
4. 每个限时来源独立保存服务器 tick 截止时间，每 tick 检查到期并重算；一次无关来源更新不会延长已有来源。持续来源使用无限时长，但状态不符合时主动撤销。
5. 玩家改信、戒律态度变化或意识形态关闭时清空旧贡献；死亡、离线、插件停用和 `/wde reload` 也清空。运行时贡献不持久化；重载后护甲监听器会检查在线玩家，饮食需重新触发。
6. 原版药水效果没有可靠的来源标签。本处理器按要求接管活跃戒律涉及的效果类型，移除旧效果后施加最终值，包括降级。相同类型的原版药水、军罚或其他插件效果可能被覆盖；贡献清空时不恢复被覆盖的效果。未涉及的效果类型不处理。
7. 每 10 tick 核对已登记效果是否丢失或等级被改写，在贡献有效期内重新施加；这只检查已登记药水结果，不扫描护甲。牛奶或外部插件清除效果后，仍有效的戒律贡献可能重新施加；外部插件持续强制写入相同效果时仍可能竞争，不承诺互不干扰。
8. 所有入口限服务器主线程。对外注册的戒律效果标识接口不会自动生成贡献；外部效果实现应调用统一入口，不能继续直接施加药水后期待自动纳入求和。

动物击杀戒律由 `AnimalKillingDoctrineListener` 监听玩家造成的动物死亡，并交由 `AnimalKillingDoctrineManager` 判定：

1. `slaughter_animals` 检查所有 Bukkit `Animals` 动物；态度 `taboo/fear/oppose` 视为破戒，`neutral/support/love` 视为允许。
2. `killing_innocent_animals` 只检查不能攻击或反击玩家的动物；`abhor/fear/disgust` 视为破戒，`neutral` 视为允许。蜜蜂、狼、熊、熊猫、羊驼、山羊及杀手兔等会攻击或反击玩家的动物不归入无辜动物。
3. 若任一适用戒律被违反，提交虚弱；适用戒律均未违反时提交抗性提升。缺少相关戒律定义或无法识别态度时不触发本次效果。
4. 默认效果为抗性提升 I 或虚弱 I，持续 30 秒；`ideology.yml -> doctrineEffects.animalKilling` 可关闭机制或调整持续时间和等级。重复击杀替换本来源效果并刷新时长；不同来源仍由统一处理器分别计入。

## 10. 外交机制

### 10.1 外交关系

当前外交关系采用三档：

- `friendly`
- `neutral`
- `unfriendly`

规则：

1. 敌对关系会阻止正常访问
2. 友好关系会降低访问成本
3. 开启贸易可改变外交访问费用表现

### 10.2 外交访问收费

外交访问已经接入多货币收费。

规则：

1. 访问费用由全局配置定义金额与货币
2. 扣费通过统一经济桥处理
3. 余额不足时访问失败

### 10.3 军事集团限制

如果一个国家已经加入军事集团，就不能再直接绕过集团流程开战。

也就是说，军事集团成员国的“宣战入口”会被上收到国家集团层。

### 10.4 Towny 和平维护费联动

当前已接入 Towny 的中立 / 和平维护费状态。

实现基于 Towny 的 `Nation.isNeutral()` 与 `Town.isNeutral()`，不按外交态度或意识形态中的“中立”判定：

1. 中立保护国家不能主动发起常规战争、被常规宣战或作为盟友进入常规参战集合。限制覆盖 WDER 宣战发起、战争投票结算、直接战争业务入口和 Towny 原生添加敌对国家事件。
2. 中立国家不能创建、申请或加入军事同盟；已提交的申请在准入结算时再次检查，不能通过旧申请绕过。
3. 和平时期开启国家中立后，在 Towny 中立状态和费用处理完成后检查实际状态，强制退出全部军事同盟，清理军事同盟申请及该国的投票，并移除涉及该国的常规宣战提案。
4. 参战期间禁止开启国家或城镇中立保护。检查原始战争参与记录，覆盖普通参战国、战争盟主、其下属城镇、当前独立战争及 Towny 标记的活跃战争，不以外交敌对态度代替参战判定。管理员通过标准 Towny 切换事件操作也不豁免。
5. 战争期间的中立开启事件被取消，不产生退战或退盟动作；需先通过和约退出或结束战争。和平时期军事同盟主席开启中立而退出时，沿用集团主席递补规则，空军事同盟自动解散。
6. 中立城镇居民的击杀不参与常规战争分数；常规交战双方之间，中立城镇居民或中立城镇领土内的玩家受到的近战、玩家投射物伤害被阻止。与 WDER 常规交战无关的玩家伤害不受此监听器影响。
7. 中立保护优先于常规战争的卫戍与强制调遣义务；中立国家不能被开启常规强制调遣，中立城镇居民不计入常规军队巡检到场人数，也不会获得该巡检的军罚。
8. 独立战争保持例外：战前已有的国家中立不会阻断城镇独立战争，也不取消当前已实现的主权帝国从仆国独立战争、独立战争评分与对应敌对关系。但战争开始后，同样禁止临时开启中立逃战。常规战争清理不会清除独立战争状态。
9. 国家中立不限制贸易联盟、意识形态联盟或主权帝国的非军事同盟成员资格。
10. 每次启动和 `/wde reload` 检查已存国家与集团成员的中立状态，清理遗留资格；不恢复定时扫描 Towny 城镇、国家存在性的旧逻辑。取消中立后不会自动恢复旧军事同盟或旧战争。

中立切换监听基于 Towny 标准事件。外部插件直接调用 `setNeutral()` 而不发事件时，无法通过此事件拦截；常规宣战、入盟和评分仍读取实时中立状态，下一次启动或重载会防御性清理冲突的军事成员与常规战争记录。此清理是异常状态兜底，不是允许玩家开启中立退战的流程。

## 11. 国家集团机制

### 11.1 基本定位

前台已经统一使用“国家集团”术语，不再把它描述为玩家组织。

当前国家集团只接受“国家”作为成员单位。

### 11.2 国家集团类型

当前支持四类国家集团：

- `TRADE_ALLIANCE`
- `MILITARY_ALLIANCE`
- `SOVEREIGN_EMPIRE`
- `IDEOLOGICAL_ALLIANCE`

### 11.3 一般入盟规则

除主权帝国外，当前采用权重投票制。

当前权重公式为：

```text
军事同盟 = 国库余额 + 国民数 × 1000
贸易联盟 = 国库余额 × 5 + 国民数 × 1000
意识形态联盟 = 国库余额 + 相同意识形态国民数 × 1000 + 非相同意识形态国民数 × 500
```

规则：

1. 申请国先提交申请
2. 成员国再进行投票
3. 赞成权重大于总权重 `50%` 时通过
4. 反对权重达到或超过总权重一半时拒绝

### 11.4 集团经济

国家集团拥有独立余额，但当前仍是“单一默认货币账户”。

规则：

1. 创建国家集团的费用从创建者所属国家国库扣除
2. 国家集团 `deposit / withdraw / balance` 固定使用默认货币
3. 维护费按小时周期结算
4. 若维护费配置为其他货币，程序会先折算为默认货币后扣除
5. 若余额不足，当前只会跳过该轮维护费并记日志，不会自动解散

### 11.5 贸易联盟与意识形态联盟

当前这两类国家集团的附加效果分别是：

- 贸易联盟：支持联盟级经济制裁；若被制裁国家与某联盟成员国家之间未交战，则不能使用该成员国的访问传送，也不能进入该成员国领土
- 意识形态联盟：可按联盟总人口降低成员国范围内的改信费用；创建时会绑定联盟意识形态，且仅允许相同意识形态国家加入

意识形态联盟专属和平条款规则：

- 该宗教修正不影响击杀得分，只影响和平条款点数消耗
- 若被宣战的战争盟主与联盟意识形态相同，则和平条款按 `sameReligionClauseCostMultiplier` 倍计算
- 若被宣战的战争盟主是异教徒，则和平条款按 `hereticClauseCostMultiplier` 倍计算

其中，意识形态联盟的折扣系数、同教条款倍率与异教徒条款倍率均由 `organization.yml` 控制。

### 11.6 军事同盟

军事同盟拥有集团级战争提案机制。

规则：

1. 成员国不能直接绕过军事同盟进行宣战
2. 需要先由集团发起 `declarewar`
3. 再由集团内部投票决定是否正式开战
4. 投票通过后，集团成员会统一同步敌对关系
5. 国家加入军事同盟前，必须与现有任一成员都不处于敌对状态
6. 若目标国家已经提交 Towny 和平维护费并处于中立保护，则不能对其发起常规战争投票

### 11.6.1 和平条约机制

当前已经在国家集团战争上下文中接入和平条约机制。

它的定位不是普通外交协商，而是“战争结果结算器”。

当前规则：

1. 交战双方都可以主动发起条约
2. 条约分为两类：
   - `demand`：提案方要求对方接受一组战败条款
   - `surrender`：提案方主动提交一组投降条款
3. 每份条约都有总分数预算，默认上限为 `100`
4. 当前战争会维护双方分数，发送条约时会同时显示“当前条约总分”和“当前参考分数差”
5. 除独立战争中的特殊强制生效情形外，条约是否成立仍由对方玩家决定
6. 总分数上限由 `war.yml -> peaceTreaty.maxProposalPoints` 控制
7. 当前条约状态会持久化记录在国家集团设置中，不是一次性内存命令
8. 条约被接受后，会执行全部条款，并按“全面停战”或“单独谋和退出战争”结算对应战争状态

当前命令入口：

- `/wde org peacetreaty <orgname> <nation> <demand|surrender> <clause1;clause2;...>`
- `/wde org reviewtreaty <orgname> <nation> <accept|reject>`

当前条款输入格式仍偏开发式，使用 `;` 分隔多个条款。

例如：

```text
reparations:20;forceConversion;tribute
transferTown:AlphaTown:WinnerNation;humiliate
liberateSubject:SubjectNation;unconditionalPassage
```

#### 分数与条款边界

当前支持以下条款：

- `reparations:<percent>`
- `forceConversion`
- `transferTown:<town>:<destinationNation>`
- `dissolveAlliance`
- `expelFromAlliance`
- `liberateSubject:<subjectNation>`
- `unconditionalPassage`
- `humiliate`
- `lootCapital`
- `tribute`
- `allowIndependence`

各条款分数都由 `war.yml -> peaceTreaty.clauses.*` 配置控制。

其中需要特别说明的点如下：

1. `reparations` 默认按“国库 `1% = 1 分`”计算，且默认最高只能索要 `20%`
2. `tribute` 不按一次性金额处理，而是建立长期贡金义务；默认按税收额度的 `5%`，在 Towny 每日税收周期结算
3. `forceConversion` 会让让步方国家直接改为受益方国家当前的意识形态
4. `transferTown` 只能转移让步方当前实际拥有的城镇，且目标国家必须属于条约受益一侧
5. `dissolveAlliance` 只对“让步方本身是军事同盟主席国”的情况有效
6. `expelFromAlliance` 只对“让步方当前是某集团普通成员”的情况有效
7. `liberateSubject` 只对“让步方是主权帝国主席国，且目标国家确实是其从仆国”的情况有效
8. `unconditionalPassage` 会让让步方向受益方授予无条件通行权，后续外交访问不再受敌对访问费用和限制阻断
9. `humiliate` 当前会记录国家羞辱状态，作为长期政治结果保存在国家扩展设置中
10. `lootCapital` 会从让步方首都金库掠夺 `50%` 给受益方
11. `allowIndependence` 只能用于独立战争，且受益方必须是独立方
12. 若独立方想在独立战争中附带其他要求，必须先包含 `allowIndependence`
13. 若独立方提出的条约仅包含 `allowIndependence` 且当前分数差距已经达到该条约总分，则该和约会直接强制生效

#### 单独谋和与停战期

当前军事同盟战争已从单纯外交态度中抽离为独立战争状态。

规则：

1. 外交态度仍然只是外交态度，不再直接等同于战争状态
2. 活跃战争期间，交战双方会被系统强制视为敌对
3. 只有相互的战争盟主之间，才能提出“结束整场战争”的全面和约
4. 战争盟主可以向敌方参战国中的非仆从国提出单独和约，接受后该成员国退出当前战争
5. 敌方参战成员国也可以主动向对方战争盟主提出单独求和，接受后自身退出当前战争
6. 单独谋和会触发双倍分数惩罚，同样一组条款在单独谋和时按两倍总分计算
7. 单独谋和后，退出战争的两个国家会进入停战期
8. 默认停战期时长由 `war.yml -> truce.baseHours + truce.maxAdditionalHours * 条约分数百分比` 计算；启用 RealisticSeasons 后，新停战期可按指定世界日期计算
9. 停战期内，这对国家不能再次发起常规战争讨伐
10. 常规战争、城镇战争和独立战争在真正开始或被结算结束时，都会向全服聊天栏广播一次状态消息；广播挂在战争状态创建与移除的源头，而不是只挂在某个命令入口上。

战争侧边计分板与专注切换：

1. 参战玩家会定时刷新一个基于个人视角的侧边计分板，默认展示当前专注战争。
2. 专注战争保存在居民扩展档案中；若没有手动选择或原目标已失效，会从当前仍可参与查看的活跃战争中自动选择第一场。
3. 计分板统一展示当前视角下的我方/敌方总分、占领分、击杀分、主要占领分账，以及独立战争的已结算周期。
4. `/wde war focus` 列出当前可切换的战争序号；`/wde war focus <序号>` 切换，`/wde war focus clear` 清除当前手动专注。`/wde war` 菜单中的战争详情页也可直接设为专注。
5. 常规战争与独立战争都通过统一的战争视图组装计分板；城镇战争同样可被专注，但仍不接入国家和约菜单。

#### RealisticSeasons 日期停战期

RealisticSeasons 为可选软依赖，通过其 `SeasonsAPI.getDate(World)` 与 `getCurrentMonthName(World)` 读取指定世界日期。缺少该插件时 WDER 仍可启动，不需要打包其付费插件 JAR。

规则：

1. `war.yml -> truce.realisticSeasons.enabled=true` 时，新停战期优先使用 `world` 指定世界的日期，不使用参战玩家所在世界。
2. 日历天数为 `baseDays + ceil(maxAdditionalDays * 条约分数百分比)`。单独谋和的双倍分数继续参与时长计算，比例最多为 100%。
3. 月份顺序与天数从 RealisticSeasons 的 `calendar.yml` 读取，支持自定义月份数量与天数。按日序计算，日期到达创建日序加停战天数时失效，不按现实世界经过几小时判断。
4. `warTruces` 记录保存 `clock`、`world`、`calendarSignature`、`endDay`，并保留按现实小时规则生成的 `endAt` 备用截止点。两国各保存一份，存档重启后仍可继续判断。
5. 旧记录只有 `endAt` 时继续按现实时间计时。关闭开关或改换指定世界只影响新停战期，旧日历记录仍使用其创建时的世界。
6. 缺少依赖、指定世界未加载、日期读取失败或日历结构变更时，使用现实时间备用截止点并限频告警。此回退可能比原日历停战期更早结束，应确保依赖与指定世界持续可用。
7. 指定世界日期不推进时，日历停战期不会按现实时间自然结束；手动快进日期可能使其提前结束，回退日期则延长剩余停战期。
8. 日历配置修改后，先重载 RealisticSeasons，再执行 `/wde reload` 刷新 WDER 的日历结构缓存。新设置不重新生成现有记录。
9. `/wde debug realisticseasons` 可查看开关、指定世界、当前日期和日序，权限与其他调试命令相同。
10. 此联动只改变和约后的停战期，不改变战争复活冻结、占领巡检或其他秒级计时。宣战发起及投票通过前均检查停战状态。

接口依据：[RealisticSeasons API](https://wiki.realisticseasons.com/developers/api)、[日历配置](https://wiki.realisticseasons.com/configuration/calendar)。

#### 受益方与让步方判定

当前条约不是简单按“命令发送者 = 受益方”处理，而是按提案类型判定：

1. 当类型为 `demand` 时，提案方是受益方，目标国是让步方
2. 当类型为 `surrender` 时，提案方是让步方，目标国是受益方

这意味着同一套条款，在 `demand` 和 `surrender` 两种模式下，实际执行方向是相反的。

#### 当前落库位置

当前和平条约相关的长期数据分别保存在：

- 国家集团 `settings`：战争状态、待审核条约提案
- 国家 `settings`：无条件通行权、羞辱记录、长期贡金义务

因此，和平条约当前已经是可持久化、可审核、可跨重启延续的机制，而不只是临时命令效果。

### 11.7 主权帝国

`SOVEREIGN_EMPIRE` 是当前规则最复杂的一类国家集团。

基础规则：

1. 创建国自动成为主席国
2. 主席国不轮换
3. 主席国不可主动退出
4. 其他成员国前台称为“从仆国”
5. 从仆国没有普通投票权，集团治理由主席国裁决

### 11.8 从仆国自治等级与镇压度

当前每个从仆国都维护一份独立的从属状态。

其中包含：

- 自治等级
- 镇压度
- 是否为卫戍国

自治等级分为三档：

- `自治领`
- `保护国`
- `傀儡国`

规则：

1. 新加入主权帝国的从仆国默认是 `保护国`
2. 新加入时默认镇压度为 `50`
3. 镇压度区间固定为 `0 - 100`
4. 当镇压度降到 `0` 后，从仆国可消耗国家国库资金提升一级自治等级；完整路径为 `傀儡国 → 保护国 → 自治领 → 和平独立`
5. 当镇压度达到 `100` 后，主席国可将其降一级自治等级
6. 仍保留从属身份的自治升级成功后，镇压度会重置到可配置值，当前默认 `90`
7. 自治降级成功后，镇压度会重置到可配置值，当前默认 `10`
8. 自治领继续提升时，须镇压度归零且本国未参加任何活跃战争；使用相同国库费用，不需主席国批准。执行后移除帝国成员资格与整个从属状态（包括卫戍和强制参战标记），保留 Towny 国家、城镇和外交关系，不生成战争或和约。普通 `leave` 的独立战争入口保持不变。

### 11.9 能力对比与卫戍国分组

当前主权帝国存在“能力对比”机制。

主席国能力采用：

```text
国库余额 + 玩家数 × 1000
```

从仆国侧会被拆成两组分别计算：

- 一般从仆国
- 卫戍国

规则：

1. 一般从仆国合计能力与主席国比较，决定一般从仆国组的镇压度升降
2. 卫戍国合计能力与主席国单独比较，决定卫戍国组的镇压度升降
3. 两组互不混算

### 11.10 卫戍国机制

主席国可以把从仆国设置为“卫戍国”。

卫戍国当前主要有四项效果：

1. 不参与一般从仆国能力组，而是进入卫戍国独立分组
2. 不再被主权帝国贡税机制征税
3. 其下属城镇征召兵容量提升为 `100%`
4. 只要主权帝国处于战斗状态，卫戍国就会被视为“强制参战”

它本质上是一种“军事化从属国”状态，而不是单纯的显示标签。

### 11.11 主权战争参战义务

当前主权帝国已经补入“从仆国参战义务”机制。

规则：

1. 卫戍国默认必须参与主权国家战斗，不能被手动关闭
2. 一般从仆国默认不强制参战
3. 主席国可通过 `mobilizewar` 将一般从仆国调遣为“必须参战”
4. 当前参战义务状态会显示在主权帝国的 `org info` 成员信息中

### 11.12 卫戍国消极参战巡检

当前会按 `organization.yml -> sovereignEmpire.warParticipation` 配置进行周期巡检。

规则：

1. 默认每 `180` 秒检查一次
2. 检查半径默认是宗主国军队统帅周围 `200` 格
3. 该巡检 Debuff **仅检查卫戍国**；被主席国调遣的一般从仆国仍纳入强制参战集合，但不因未靠近统帅受到此项惩罚
4. 只要卫戍国中存在至少 1 名在线玩家位于主席国军队统帅附近，就视为该国本轮已参与作战
5. 若卫戍国全体在线玩家都不在该范围内，则该卫戍国在线玩家会获得 `挖掘疲劳 I`
6. 效果会持续到下一次巡检；若下次巡检满足“附近至少 1 人”，则不会继续补发
7. 若主席国军队统帅不在线，则当前不会执行该轮附近检查

### 11.13 自治等级附加限制

自治等级除了影响升降级逻辑外，当前还已经影响税收上限。

规则：

1. `自治领 / 保护国 / 傀儡国` 拥有各自独立的固定税上限
2. 三个等级也拥有各自独立的财产税比例上限
3. 当从仆国自治等级被降级时，如果现有城镇税率超出新等级上限，程序会自动压回上限范围

### 11.14 主权强制动作

主权帝国当前除了被动压制外，还支持主动强制动作。

已实现的包括：

- 强制更换从仆国领袖
- 强制要求单笔贡金

规则：

1. 强制更换从仆国领袖会降低该从仆国镇压度，默认 `-50`
2. 强制贡金会按自治等级读取不同的金额配置
3. 强制贡金成功后会降低该从仆国镇压度，默认 `-30`
4. 强制贡金扣费来源于从仆国国家国库

### 11.15 主权贡税

当前主权帝国已经拥有独立的贡税结算机制。

规则：

1. 贡税按 `organization.yml` 配置的小时周期结算
2. 每轮会向每个“一般从仆国”收取固定贡税
3. 贡税从从仆国国家国库扣除
4. 集团账户只记录默认货币余额，因此贡税若配置为其他货币，会先折算为默认货币后再计入集团余额
5. 卫戍国不会被征收主权贡税

### 11.16 主权帝国独立战争

从仆国不能像普通集团成员那样直接退出主权帝国。

当前流程是：

1. 从仆国执行 `leave`
2. 不会立即退出，而是自动进入独立战争
3. 帝国内成员会自动进入敌对状态

独立战争当前包含三部分：

- 击杀得分
- 周期占领得分
- 最终周期结算
- 特殊和平条约结算

当前特点：

1. 所有 WDER 战争统一使用每国50分权重，首都25分，非首都按人口分配；单城国家/城镇为50分
2. 全面和约按阵营国家数归一化为50分基础占领池，单独谋和使用独立的单国原始分账
3. 独立国为防守方，宗主阵营为进攻方；只有防守方复活冻结，期间不计入占领人数
4. 主席国可以主动放弃压制，使从仆国立即独立成功
5. 独立战争中的和平条约支持特殊条款 `allowIndependence`
6. 若独立方只提出 `allowIndependence` 且无其他附加条件，系统会按分数差距判断是否直接强制生效

统一计分补充：每周期在防守方城镇按进攻/防守活人数比例分配权重，无人时全额归防守方；进攻方本土不奖励进攻方，但防守方反攻按敌方城镇权重获得额外占领分。周期累加、击杀分统一可配置，死亡和旁观玩家不计入。统一周期和防守方冻结秒数放在 `war.yml -> scoring`。
常规战争记录独立持久化到 `wars` 分类，旧军事联盟战争记录自动合并，避免同一战争多份副本重复结算。单独谋和的单国占领及击杀分账与全面战争阵营总分分别存储。
新入口 `/wde war` 提供战争列表和理由选择。无联盟国家可直接宣战，军事联盟成员仍执行内部投票；城镇战争受原有参战开关限制，由镇长发起和结束。无集团国家和平条约命令使用 `war` 作为范围参数。
战争理由为征服、收复失地、独立战争、圣战、贸易冲突、羞辱宿敌、输出革命、摧毁威胁。独立理由只能由独立流程生成，摧毁威胁仅面向军事联盟或主权帝国，其他暂不增加资格条件或分数倍率。

## 12. 经济与多货币机制

### 12.1 默认货币规则

插件支持多货币，但存在一个硬约束：

1. `economy.exchangeRates` 第一项必须是默认货币
2. `economy.defaultCurrency` 必须与第一项一致
3. 运行时会以第一项作为真正的默认货币

原因在于 Towny 与部分经济接入仍以单默认货币模型为核心。

### 12.2 当前已接入多货币的主要场景

当前多货币换算已用于：

- 外交访问
- 创建意识形态
- 玩家改信
- 城镇改宗
- 国家改宗
- 强迫改信 / 强迫改宗
- 创建国家集团
- 主权帝国贡税
- 主权帝国强制贡金
- 国家集团维护费

### 12.3 Towny 居民税收接替

插件支持接替 Towny 的“城镇向居民收税”流程。

规则：

1. 固定税优先扣默认货币
2. 默认货币不足时，再按汇率从其他货币补足
3. 财产税会先计算居民总财富折算值，再确定应缴金额
4. 最终统一折算为默认货币打入城镇金库
5. 若居民余额不足，可执行部分收税
6. 具有 `taxfree` 特权的征召兵会在该流程中被跳过

## 13. 热重载、迁移与配置演进

### 13.1 热重载范围

`/wde reload` 当前可以重载：

- `config.yml`
- `nation.yml`
- `town.yml`
- `organization.yml`
- `ideology.yml`
- `backgrounds.yml`
- `lang/` 目录下的语言文件

同时还会刷新部分运行时引用、命令和监听器。

### 13.2 不能仅靠热重载处理的内容

`storage.*` 配置不属于安全热切换范围。

如果你修改了以下内容，应直接重启服务器，而不是只执行 reload：

- `storage.type`
- MySQL 连接参数
- sqlite 文件目标

### 13.3 已实现的配置迁移思路

当前工程已经具备一定的旧配置补全与迁移能力，例如：

- 旧模块配置拆分迁移
- 旧国家集团维护周期字段迁移
- 旧意识形态配置键迁移
- `backgrounds.yml` 缺失键自动补全

这意味着项目已经在朝“升级时自动补齐缺失字段”的方向演进，而不是要求服主手工逐项比对。

## 14. 当前已知边界

以下内容是当前实现边界，不代表最终设计终点：

1. 意识形态制裁当前仍以象征性状态为主，尚未形成完整数值效果
2. 戒律效果依赖外部注册，不是每条戒律默认都有实际逻辑
3. 国家集团账户仍是单默认货币账户，不支持多币种分账
4. 当前未实现跨数据库自动迁移
5. MySQL 模式下不会自动创建数据库实例
6. 国家接管城镇税制后，Towny 原生命令的手动修改可能被 WDER 后续同步覆盖
7. 角色背景的 AuraSkills 奖励依赖 AuraSkills 运行状态，未加载时会延后补发
8. 当前 `%player_name%` 占位符已经接入背景 lore 展示，但并没有扩展为全插件统一占位符系统
9. 独立战争当前仍是“单次战争周期结算”模型，尚未扩展为更复杂的多战线长期战役系统

---

## 15. 建议审查重点

如果后续继续扩展机制，建议优先关注以下问题：

1. 角色背景是否还需要承载更多长期属性，而不仅是一次性技能增量
2. 主权帝国的自治等级是否还需要继续影响更多权限或税务比例
3. 卫戍国是否需要额外承担军事义务或提供更多战略增益
4. 意识形态制裁是否要从象征状态升级为真实效果
5. 国家集团账户是否需要演进为多币种分账
6. 当前快照式数据库结构是否需要逐步演进到更细粒度的关系化模型

## 16. 总结

`WorldDynamicsEngine:Reborn` 当前已经不再只是 Towny 的命令补丁，而是一个覆盖城镇、国家、国家集团、意识形态、角色背景、外交与多货币结算的治理扩展层。

它最核心的特征有四点：

1. 以 Towny 作为底层事实锚点
2. 以 WDER 作为治理、规则与扩展状态控制层
3. 以配置驱动、生命周期事件与定时业务任务为主要运行方式
4. 以“模块化独立配置 + 自动补全迁移”作为长期演进方向

理解这四点，基本就能读懂当前插件的大部分机制设计。

## 集结传送

集结入口为 `/wde rally nation|town`，只允许成员主动发起，不提供统帅或镇长强制拉人接口。
国家范围要求请求者是本国下属镇的 WDER 征召兵或 Towny 镇长，目标是当前 WDER 军队统帅；城镇范围要求请求者是本镇 WDER 征召兵，目标是当前 Towny 镇长。
目标必须在线、存活且仍在对应组织内，目标坐标在本次命令执行时获取。

费用分别取 `nation.yml` 或 `town.yml` 的 `rally.cost`，使用默认货币，通过国家或城镇的 Towny `BankAccount` 预扣。
标准 `PlayerTeleportEvent` 保留其他插件和贸易制裁拦截，返回失败或抛出异常时尝试原额退款，退款失败记录严重日志。
复活冻结、强制背景选择冻结、乘坐载具、死亡和目标为自身均禁止使用。命令的重入保护避免传送事件回调再次触发同一玩家请求。
菜单仅显示符合身份的按钮，二次确认后执行相同命令；付款金额只能由服主配置，玩家无改价入口。
