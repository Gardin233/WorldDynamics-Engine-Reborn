# WDER 插件机制说明

> [Wiki 首页](README.md) · [服主使用文档](使用文档.md) · [数据库设计](数据库设计检查.md) · [国家史书机制](国家史书机制.md)

本文说明当前实现中的职责边界、数据流和状态转换，供维护与审查使用。命令和配置入口见[使用文档](使用文档.md)。只描述由源码实现或资源配置承载的行为，不把玩法设想写成既有能力。

## 1. 总体架构

WDER 是 Towny 治理扩展层，不替代 Towny 的行政对象与领土事实。

| 数据或动作 | 主要责任方 |
| --- | --- |
| 城镇、国家、居民及其原生归属 | Towny |
| Towny 国库、城镇地块和原生访问控制 | Towny 与经济提供者 |
| 政体、选举、WDER 职位及征召兵扩展 | WDER |
| 国家集团、战争账本、和平提案、停战 | WDER |
| 意识形态、背景选择与附加效果 | WDER |
| 实际扣款、存款和退款 | Vault/VaultUnlocked 提供者及 Towny 账户 |

主要对象层级为“城镇 → 国家 → 国家集团”。集团以国家为成员，不直接收纳玩家；居民扩展数据独立保存。

### 启动顺序

1. 读取配置、语言、模块配置并初始化存储。
2. 加载 Towny 兼容集成及可选依赖。
3. 创建城镇、国家、居民、集团、意识形态等管理器。
4. 同步已有 Towny 城镇和国家治理记录。
5. 创建并初始化国家史书管理器。
6. 注册命令和事件监听，启动自动保存及业务周期任务。

国家史书必须在 Towny 首次导入之后建立管理器，因而首次接管现有国家只能记录史官接管，不把同步时间误记为国家成立时间。

## 2. 存储模型

SQLite/MySQL 共用 `DataStorageManager` 的实体分类快照表。国家、城镇、居民、集团、意识形态和战争账本以类别和实体键寻址；项目没有依靠数据库关系查询来完成主业务。

一般实体采用“内存模型 → 序列化快照 → 数据库”的保存方式。城镇、国家、居民等部分类别保存时会整体替换该类别记录。战争账本采用单实体保存以集中维护活跃战争、条约和城镇停战。

存储限制：

- SQLite/MySQL 表由 WDER 自动创建；MySQL 数据库本身需预建。
- 不提供运行中的存储后端热切换。
- 不提供 SQLite/MySQL 自动迁移。
- 业务修改可能先影响 Towny/经济服务，再写数据库；不同插件间没有共同事务，不能承诺断电级原子回滚。

## 3. Towny 生命周期与治理档案

### 3.1 启动同步

启动时，`TownManager.importExistingTownyTowns` 与 `NationManager.importExistingTownyNations` 将 Towny 对象接入 WDER：

- 不存在 WDER 记录时才建立默认治理档案。
- 已存在政体、职位、意识形态等扩展状态不会因启动同步而重置。
- 重建国家-城镇双向层级与现有归属。
- 不使用周期性扫描删除缺少 Towny 对象的历史治理档案。

`/wde reload` 不重跑这套导入。运行中创建、删除、改名及城镇入国/退国由 Towny 生命周期事件接管。

### 3.2 状态来源与一致性

Towny 是城镇和国家实际存在性、Towny UUID、国王、镇长、国库及成员归属的实时来源。WDER 档案保存扩展字段。某些数据通过快照差异检测变更，另一些动作在业务完成后显式记录。

外部插件若直接改变内存字段而不触发 Towny 事件、WDER 保存或相应 API，WDER 无法保证即时记录。启动同步可以刷新对象现状，但不可能推断错过的中间历史。

## 4. 权限与治理边界

命令入口首先检查插件权限节点，具体操作再检查 Towny 身份、WDER 职位和业务状态。OP 身份不自动替代业务授权。

- 国家治理按国王、政府领袖、军队统帅、国家居民等具体操作检查。
- 城镇治理以城镇归属、镇长和城镇领袖为准。
- 主权帝国主席国的集团权力止于从仆国层级，不因帝国关系获得从仆国下属城镇的直接治理权。
- 管理菜单只控制展示入口，命令及管理器仍进行后端校验。

## 5. 城镇与国家治理

### 5.1 城镇

城镇政体为独裁或共和。独裁制不展示选举操作；共和选举维护候选人和投票，并在变更成功后同步 Towny 镇长。征召兵名单以本镇居民为约束，居民加入/离开后清理无效成员并重新处理人数上限。

国家可为所属城镇配置居民税制。接管值会写回 Towny；WDER 在标准居民税周期介入收税。使用 Towny 原生税收接口的功能仍以 Towny 账户和对应时机为基础。

### 5.2 国家

国家政体为独裁、民主或贵族议会。WDER 政府领袖与军队统帅等职位和 Towny 国王是关联但不同的字段。民主国家的领袖结果会尝试同步 Towny 国王和首都；同步失败应以日志和 Towny 当前状态为准。

国家意识形态保存于 WDER 国家档案。国家更名、领导者/政体/意识形态更改和城镇归属等变更是国家史书当前快照采集的对象。

### 5.3 征召兵与集结

城镇征召兵必须属于本镇，常规人口容量取 `town.yml` 配置；卫戍国使用特殊容量规则。集结由成员主动发起，使用当前在线统帅或镇长位置及国家/城镇金库费用，不属于战争宣战、战争胜负或史书交易回执。

## 6. 国家集团

集团类型为贸易联盟、军事同盟、主权帝国和意识形态联盟。集团成员和投票数据存于集团档案。

- 一般集团申请采用权重投票；不同类型使用不同国家权重公式。
- 军事同盟要求成员国发起宣战提案，按有效成员国权重计算多数。
- 主权帝国由主席国直接审理国家加入及管理从仆等级。
- 贸易联盟制裁在传送和领土进入逻辑分别进行检查。
- 意识形态联盟将联盟意识形态作为成员资格和部分改信/和约成本计算条件。

不应把集团记录等同于 Towny 国家从属关系；例如主权帝国治理状态是 WDER 扩展数据，城镇归属依旧由 Towny 国家关系决定。

### 外交信件

外交信函由 `/wde diplomacy letter` 发送，复用外交身份校验（国王、政府领袖、军队统帅），最多4000字符，拒绝空正文及控制字符。它是措辞行为，不触发战争或关系变更。

费用来自发信人个人钱包；金额与币种通过 `config.yml -> diplomacy.letters.cost` 配置，币种必须被经济提供者精确支持。先扣款，再用 `diplomatic_letters` 分类按信件UUID保存收发国家UUID、当时名称、作者UUID、类型、正文和发送时间。存储失败则不通知目标并尝试原币种退款，退款失败留严重日志。

保存成功后写双方国家史书事件 `DIPLOMATIC_LETTER_INSULT/NOTICE/REQUEST`，记录事实参数而非叙述句子。`event.yml` 用 `%date%`、`%sender%`、`%target%` 生成三种外交措辞，正文可由 `%body%` 引用；默认不展示正文。日期沿用历史机制所选现实/季节时钟。

目标国在线成员收到查收通知；收发两国外交授权者可分页查收，按国家UUID过滤，防止同名新国家继承旧信件。史书关闭时信件仍持久化但不记新历史。信件存档与双边史书不是共同事务；史书写入失败不撤销已经保存的信件，会提示与记录错误。史书本身公开，正文事件参数不构成保密通道。

## 7. 战争状态机

### 7.1 战争身份与理由

玩家手动选择战争理由，资格由 `OrgManager.warReasonFailure` 统一校验，菜单和补全仅是预筛选，命令、投票和开战路径会复验。

| 理由 | 当前资格条件 |
| --- | --- |
| 征服 | 无专门政体/历史条件，仍须通过一般宣战限制 |
| 收复失地 | 目标当前拥有符合连续持有天数阈值的本国旧城镇 |
| 独立 | 镇长控制的城镇向所属国家，或仆从国向主权帝国主席国 |
| 圣战 | 双方国家意识形态均有效且彼此不同 |
| 贸易冲突 | 发起国受目标所属贸易联盟制裁 |
| 羞辱宿敌 | 双方对彼此均处于敌对关系 |
| 输出革命 | 发起国政体为民主 |
| 摧毁威胁 | 目标是军事同盟或主权帝国主席国 |

国家/联盟战争及城镇战争都写入统一 `MilitaryWarState`，参战身份可以是国家名或 `town:<城镇名>`。战争数据包含战争键、阵营、理由、开始时间、总分、占领分和击杀分。战争以数据库 `wars` 分类实体持久化，而非依赖 Towny 的原生战争对象。

### 7.2 宣战路径

1. 确认发起者具有对应国家职位或城镇镇长身份。
2. 解析目标和玩家所选战争理由。
3. 执行中立保护、停战、现存战争、阵营关系及理由资格校验。
4. 若发起国在军事同盟内，创建宣战提案并进行加权表决。
5. 投票通过后重新检查资格，构建参战阵营并写入战争账本。
6. 国家阵营战争同步 WDER 敌对关系；战争状态创建后全服广播并可被战争菜单/计分板读取。

军事实体阵营会纳入相关军事同盟成员；主席国参战时，符合参战义务的主权帝国从仆国也会按集团规则进入阵营。中立成员被排除且不能用中立规避已开始的战争。

**独立战争不是独立状态机。** 它使用统一战争记录及计分；独立理由会将发起国一侧限制为实际独立者。自治领在镇压度和参战条件满足时，另有支付费用和平独立路径，不能与战争借口混为一谈。

### 7.3 运行与计分

击杀分在有效敌对玩家死亡时即时写入。周期任务根据在线玩家的家乡城镇、当前所在城镇、阵营关系和防守复活冻结状态累计占领分。

- 一般多城国家占领权重总计 50：首都 25，其余 25 按非首都人口分配。
- 单城国家及独立参战城镇的占领权重为 50。
- 防守城镇内双方有效人数按比例分配该城镇权重；无人占领时该权重归防守方。
- 进攻方本土不为进攻方产生本土占领分；防守方反攻另行计算。
- 阵营全面计分会对各参战国贡献归一化；单独谋和使用对应两国的分账，不借用第三国领土分。
- 分数累加、持久化和展示，不自动触发胜利、投降或条款。

防守方死亡后短暂冻结，冻结玩家不参与占领人数统计；进攻方无此冻结。Towny spawn 与战争期间中立切换由标准事件监听拦截。WDE 规则不会自动模拟完整 Siege/区块占领或接管全部第三方战斗事件。

### 7.4 和约与战争结束

和平提案以战争键保存，双方提案方向决定受益方与让步方。GUI 和命令入口都调用同一预览、资格校验及接受流程。

接受时的处理顺序大致为：

1. 重新解析活跃战争和操作身份。
2. 校验条款、目标、战争阵营归属及总点数。
3. 执行强制改信、联盟变化、通行/羞辱/贡金、首都掠夺等国家级效果。
4. 执行转城；失败时不报告和约成功。
5. 结束全面战争或将单独谋和国家移出战争，并建立相应停战期。
6. 执行独立或强制附庸关系变化、清理解散国家关系。

全面和约结束战争两侧并创建阵营停战；单独谋和创建相关两国停战并将一国退出当前战争。单独谋和条款点数按双倍计算。条约接受是业务决策，不按分差自动批准。

城镇战争的和约条款能力受限，镇长可投降结束并设置城镇停战；它不等同于国家阵营和约。管理员结束战争会移除战争状态、广播结束，但不是自动分配胜者或自动套用和约条款。

## 8. 意识形态与背景

### 8.1 意识形态、模因与戒律

意识形态实体保存领袖、追随者、模因选择、戒律态度、冷却和金库/什一税配置。玩家、城镇与国家归属保存在各自治理档案。

- 创建者自动获得新意识形态的追随者和领袖身份。
- 玩家个人只能保留一个当前意识形态；首次个人选择免费，之后改信按费用规则处理。
- 模因是展示与态度约束数据，不自动等于玩法效果。
- 戒律定义态度选项；具体效果由 WDER 内置管理器或外部注册实现提供。
- 删除配置定义会让对应选项休眠/不显示，不自动删除持久化选值。
- 原版/CE 图标字段位于 `ideology.yml` 定义的 `icon`。

已接入的效果包括护甲状态、食物分类和动物击杀对应的原版药水效果。统一 Buff 处理器按玩家、来源和效果类型汇总等级；Minecraft 原版效果没有来源标签，活跃戒律可能覆盖其他插件施加的同类型效果，清除 WDER 贡献时不恢复之前被覆盖的效果。

### 8.2 金库、什一税与其他功能

意识形态金库为只存不取。什一税在 Towny 每日结算事件触发，按当前居民个人意识形态收取；固定/比例规则和币种换算见 `ideology.yml`。外部经济接口和数据库不能组成同一个事务。

背景选择分儿童期、成年期，先儿童后成年，每阶段不可重复更改。AuraSkills 是软依赖；用户数据或依赖未就绪时的奖励可延迟补发。

Towny INN 床位费在成功入睡后结算，并将配置价或单床价格付给房间拥有者/镇长。死亡掉落池只向原版死亡掉落追加，能生成已加载的原版或 CE 物品。

## 9. 国家史书事件机制

### 9.1 初始化、索引及存储

史书管理器在 Towny 启动同步后加载。每本史书使用 WDER UUID 作永久索引，并额外保存 Towny 国家 UUID、名称、成立/建档时间、归档状态、当前快照和事件副本。

- 索引实体保存在数据库分类 `nation_history`，键为史书 UUID。
- 数据库中的事件副本是恢复 JSON 文件的真本。
- 每个事件以独立 JSON 文件投影到 `history/<史书UUID>/<事件UUID>.json`。
- 文件使用 UTF-8，先写临时文件再原子替换；无法原子替换的文件系统使用普通替换。
- 启动时补建缺失 JSON 投影，不需要从 JSON 反向修复数据库。

使用数据库和文件投影双份记录会增加每次事件保存的 I/O；整个史书实体包含当前事件列表。大规模历史运行较久时应监控数据库实体大小和启动投影时间。

### 9.2 开启、成立与时间

`nation.yml -> history.enabled` 决定是否新增普通采集事件。当前仓库的 `nation.yml` 值为 `true`；旧配置缺失该字段时，启动补全使用关闭值 `false`，需由服主明确启用。

- 初次同步、首次启用或缺失史书的既有国家产生“从此时开始有了史官”，不伪造完整早期事件。
- 新国家由 Towny `NewNationEvent` 发现，成立时间使用 Towny 注册时间（如果有效），并记首任国王。
- Towny 国家 UUID 是生命周期稳定标识；国家改名沿用同一史书 UUID。
- 同名国家删除后重建会有不同 Towny UUID 和新史书。
- 时间时钟为 `REAL_TIME` 或 `REALISTIC_SEASONS`。季节日期写入日序、显示日期、世界和日历签名；接口不可用时当前事件回退现实时间。
- 每条事件保存自己的时钟，不因之后改配置而重新解释历史日期；分组按时钟、世界、日历签名与日序生成。

关闭采集会保留索引和既有事件，不新增常规历史。国家改名和归档是身份/状态维护，即使采集关闭仍维护索引；这时不会新增相应叙述事件。重新启用时以现有快照作为新基线，不把停用期间变化伪记为重启当天发生。

### 9.3 事件采集边界

治理类事件通过 `NationManager.saveNations()` 后的国家快照差异记录，覆盖：

- 政体、WDER 政府领袖、Towny 国王、国家意识形态变更。
- 国家城镇集合变化，记录加入和离开。

国家重命名及城镇重命名由 Towny 生命周期事件显式记录。城镇更名会更新该国快照中的城镇名，避免误判为“离开旧城镇并加入新城镇”。

战争记录由战争账本源头触发：

- 正式战争状态创建时，参战国家分别记录对手、理由和进攻/防守身份。
- 战争状态移除时记录结束事件和双方最终分数。
- 被接受的和约记录提案结果及每条条款，受益国记录“受益”视角，让步国记录“让步”视角；让步方标记为和约意义上的败方，不是分差自动判负。
- 和约执行失败会记录失败事件，不标成成功；若部分较早条款已执行，失败事件表示整份和约未完整完成，历史中保留实际执行过的具体变更。
- 解放仆从国事件也写入被解放国家史书。
- 单纯管理员结束战争会记战争结束，不自动判定胜负。

纯 `town:<城镇名>` 不是国家索引，因此没有国家史书的城镇战争参与者不会凭空新建国家史书。

纳贡条款记录谈判约定，不表示每次 Towny 税收扣款已经成功到账。当前史书不采集逐笔赔款/贡税交易回执。

### 9.4 模板渲染、归档与导出

JSON 保存类型与事实参数，不保存渲染句子。读取时从 `event.yml` 查找 `events.<事件类型>` 模板并替换 `%nation%`、`%before%`、`%after%`、`%town%`、`%opponent%`、条款参数等占位符。修改模板只影响之后的渲染，不修改事件事实；已导出的 TXT 或已发出的书是当时生成的副本。

国家被移除时：

1. 索引设为 archived，记录现实结束时间。
2. 追加解散事件（仅采集开启时）。
3. 保留 NationChronicle UUID、数据库索引、JSON 事件和导出目录。
4. 停止该归档史书接收新事件。
5. 展示名附国家现实存续区间，例如 `A国(2026.1.1-2026.2.1)`。

同名新国家使用新的国家 UUID 和史书，不续写已解散国家历史。和约中最后一城转让可能导致国家删除，归档会延迟到本次和约条款和结局记录结束后执行。

### 9.5 查阅接口

`/wde history list`、`read`、`txt`、`book` 使用 `wde.player` 权限，当前对普通玩家开放国家史书：

- `list` 与 `read` 按聊天页展示，列表每页 8 本，正文每页 8 行。
- `txt` 将渲染文本写入对应史书 UUID 目录的 `chronicle.txt`，不向玩家传文件。
- `book` 生成原版书并放入玩家背包。每卷最多 50 页，单页按约 20 个字宽、12 行拆分；大史书应使用卷号分页领取。
- 当前国家名可用于活动史书查询；归档史书使用带存续期名称或史书 UUID 查询。名称参数按一个命令参数处理，长名称建议用 UUID。
- 背包没有空位时拒绝发书，不清理或覆盖已有物品。

详细服主配置和玩家操作见[使用文档 §9 国家史书](使用文档.md#9-国家史书)及[国家史书机制](国家史书机制.md)。

## 10. 热重载和已知边界

`/wde reload` 保存运行时档案、重载模块/语言/事件模板、重建命令及监听器并重新启动任务；不重新扫描 Towny，不切换数据库连接。`storage.*` 修改须完整重启。

重要限制：

1. Towny、经济提供者、数据库和文件系统之间没有跨系统原子事务；服务崩溃可能留下已执行条款但未完成后续写入的状态，需结合日志核对。
2. 史书事件写数据库并同步投影 JSON，发生在对应业务保存路径上；数据库异常可能影响调用该保存逻辑的操作。
3. Towny 国家删除只通过事件/启动状态差异发现。服务端离线期间发生的变化，其时间无法精确还原；尤其离线删除会在下次启动发现时归档。
4. 史书文件夹不是数据库备份的替代品。长期保存应同时备份 SQLite/MySQL 与 `history/`。
5. 禁用史书后既往记录仍可查询、导出；这不表示停用期间新增了历史事实。
6. WDER 战争分数用于展示与条款预算，不是自动占领判定或自动战胜/投降系统。
7. 原版药水效果没有来源标识，WDER 对活跃戒律所涉及的同类型效果会进行统一覆盖；可能和其他插件效果冲突。
8. 可选插件及第三方战争/经济扩展需在目标服务端进行组合测试。

## 11. 维护检查

启用国家史书后建议在测试服逐项确认：

1. 接管既有国家只创建史官开始事件；新建国家记录成立事件。
2. 同步和周期保存不会重复新增不变的政体、领袖、意识形态和城镇事件。
3. 政体、国家领袖、国王、国家意识形态与城镇归属变化能按类型记录。
4. 国家更名保留同一史书 UUID；删除后同名重建得到新 UUID。
5. 宣战、投票通过、和约成功/失败、单独谋和、管理员结束战争均符合当前采集范围。
6. 最后一城转让导致国家解散时，和约事件先于归档事件持久化。
7. `REALISTIC_SEASONS` 不可用时事件有现实日期；跨日和更换日历能正确分组。
8. 修改 `event.yml` 后重载并再次读取，可看到新模板且事件 JSON 不变。
9. 长史书可分卷完整生成，背包满时不丢物品。

当前验证包括 Java 21 目标全量源码编译及序列化、模板和成书分页检查；未等同于真实 Paper/Towny 服务器联动测试。
