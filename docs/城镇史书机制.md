# 城镇史书机制

> [返回 Wiki 首页](README.md) · [服主使用文档](使用文档.md) · [国家史书机制](国家史书机制.md)

## 启用与时间

在 `town.yml` 中配置：

```yaml
history:
  enabled: true
  clock: REAL_TIME
  world: world
```

- 新安装默认开启；升级时若旧 `town.yml` 没有 `history` 字段，自动补为关闭，避免未明确启用就开始采集。
- `REAL_TIME` 按服务器时区的现实日期分组；`REALISTIC_SEASONS` 使用指定世界的季节日历，无法读取时该事件回退现实日期。
- 关闭期间不采集普通变化。重启或 `/wde reload` 重新启用时，用当前状态重建快照，不补造关闭期间的历史。
- 修改 `event.yml` 或 `town.yml` 后执行 `/wde reload`。

## 身份与存储

每座 Towny 城镇使用 Towny UUID 绑定独立史书 UUID。名称只作为展示与活动查询入口；城镇更名后继续写入原史书，同名新城镇则使用新的 Towny UUID 和新史书。

数据库中的 `town_history` 分类是索引及事件真本，包含城镇 UUID、名称、建档/成立/解散时间、归档状态、当前快照和结构化事件副本。每个事件另以 UTF-8 JSON 投影到：

```text
history/towns/<史书UUID>/<事件UUID>.json
```

启动时依据数据库补建缺失 JSON 文件。TXT 导出为同目录下的 `chronicle.txt`。备份需同时覆盖数据库、`history/` 和 `event.yml`。

## 采集范围

新建城镇记录成立事件和当时镇长、人口；初次接管已有城镇只记录史官接管，不补造早期历史。之后根据 Towny UUID 和 `WDEtown` 快照记录：

- 城镇建立、解散、改名。
- 城镇政体、WDER 城镇领袖、Towny 镇长和文化变更。
- 所属国家变化。
- 人口数量变化。

居民姓名不写入城镇史书。治理快照在 `TownManager.saveTowns()` 成功后比较；Towny 生命周期事件负责创建、删除及同步档案。无实际字段变化的重复保存不会产生事件。

删除城镇时软归档索引、保存结束时间并停止向该书新增事件；同名城镇重建不会接续旧史书。若删除发生在插件离线期间，系统只可在启动时发现，归档时间是发现时间，不推测精确解散时间。

## 文本模板

城镇史书使用 `event.yml` 中独立于国家史书的键空间：

```yaml
townDay: "[%date%]"
townBook:
  title: "%town%的城镇史书"
  author: "镇史官"
townEvents:
  TOWN_CREATED: "%town%于此日建立，首任镇长为%mayor%，最初人口为%population%人。"
  TOWN_GOVERNMENT_CHANGED: "%town%的政体由%before%改为%after%。"
  TOWN_NATION_CHANGED: "%town%的所属国家由%before%改为%after%。"
```

事件数据库只保存类型、时间和事实参数，叙述在查阅或导出时按模板生成。`townLabels` 可翻译城镇政体和“无归属”等标识，不会更改已保存事件。

## 查阅与导出

史书使用 `wde.player` 权限，对玩家开放：

```text
/wde history town list [页码]
/wde history town read <城镇名或史书UUID> [页码]
/wde history town txt <城镇名或史书UUID>
/wde history town book <城镇名或史书UUID> [卷号]
```

列表和聊天正文每页 8 行；成书每卷最多 50 页，长史书可分卷领取。城镇名称含空格时可将名称作为多个命令参数输入，归档城镇建议使用 UUID。

## 边界

城镇史书独立于国家史书；城镇加入或离开国家会写入本城镇史书，国家层面的城镇列表事件仍由国家史书负责。城镇史书不记录逐笔税收、金库交易或和约执行回执，也不执行事件中呈现的任何内容。

数据库写入及 JSON 投影目前在业务主线程执行；Towny、数据库和文件系统之间没有跨系统原子事务。大型服务器启用前应评估事件频率，并备份数据库和文件投影。
