# 契约系统机制说明

## 系统边界

契约是玩家自定义的文本档案，不是和平条约、法律或自动化工作流。系统仅保存正文、签署与决定信息，不解析条款，不执行正文，也不修改国家、城镇、战争、经济或外交状态。

## 生命周期

1. 玩家持有书与笔，提交双方类型和接收方名称。
2. 系统校验双方类型组合、发起方身份及接收实体，然后打开原版书与笔编辑界面。
3. `PlayerEditBookEvent` 检测到签署后，系统保存书页正文并生成契约编号、创建时间和发起者身份。书名由系统覆盖，玩家只提供正文。
4. 接收方授权代表在待办列表中打开成书。打开操作写入查看记录；书本关闭后，聊天栏显示可点击的承认/拒绝操作。
5. 决定操作重新校验接收方身份，并要求操作者已经打开契约。状态、决定人和时间保存至同一契约记录；后续打开书本可看到自动落款或拒绝记录。

状态仅有 `PENDING`、`ACCEPTED`、`REJECTED`，决定后不可重复处理。正文最多 97 页，为自动签署信息保留书页空间。签署展示名称最多 28 个 Unicode 码点，超出部分替换为 `...`；完整经办人名称仍在结构化记录中保留。

## 参与方与权限

支持玩家-玩家、玩家-城镇、玩家-国家、城镇-城镇、城镇-国家、国家-国家。玩家发起方自动绑定当前玩家；城镇和国家发起方自动绑定玩家当前所属实体。

- 玩家方：由对应玩家账号查看；接收方决定由该账号本人执行。
- 城镇方：镇长或 WDER 城镇领袖可以代表城镇发起、查看或处理。
- 国家方：国家最高领袖或已登记外交官可以查看、处理；作为国家对国家契约发起方时，`DEMOCRACY` 政体仅允许外交官，其他政体允许最高领袖或外交官。
- 国家和城镇使用 Towny UUID 作为记录身份，实体更名不改变历史契约的参与方身份。

玩家必须先打开书本才能作出决定；查看 UUID 会记录在契约实体中。命令权限仍受 `/wde` 的 `wde.player` 根权限和业务身份检查共同约束。

## 持久化

契约记录保存在共享 SQLite/MySQL 数据库的 `contracts` 分类中，序列化字段包括双方类型、Towny/玩家标识、显示名称、正文页、发起人、创建时间、已查看账号、状态、决定人和决定时间。签署页由已保存字段生成，拒绝也作为档案状态保存，不删除契约正文。
