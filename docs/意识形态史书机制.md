# 文化与教会史书机制

> [返回 Wiki 首页](README.md) · [服主使用文档](使用文档.md) · [文化治理机制](文化治理机制说明.md) · [国家史书机制](国家史书机制.md)

## 开启与时钟

在 `ideology.yml` 中配置：

```yaml
history:
  enabled: true
  clock: REAL_TIME
  world: world
```

- 新安装默认开启；旧版 `ideology.yml` 缺少 `history` 字段时，启动补全为关闭，升级不会静默开始采集。
- `REAL_TIME` 按服务器时区的现实日期分组；`REALISTIC_SEASONS` 按指定世界的季节日历分组，日历不可用时该事件回退现实日期。
- 关闭期间不新增普通事件；重新启用后以当前状态作为快照基线，不补造停用期间的变化。删除/解散仍会维护已有史书索引和归档状态。
- 修改设置或 `event.yml` 后执行 `/wde reload`。

## 独立索引

文化和教会使用独立于国家、城镇的 UUID 史书：

| 对象 | 数据库分类 | JSON 目录 |
| --- | --- | --- |
| 文化 | `ideology_history` | `history/ideologies/<史书UUID>/` |
| 教会 | `church_history` | `history/churches/<史书UUID>/` |

数据库事件副本是事实来源；每条事件另投影为 `<事件UUID>.json`。JSON 使用 UTF-8，临时文件写完后原子替换；启动时根据数据库索引补回缺失文件。TXT 导出写到对应史书目录的 `chronicle.txt`。备份应同时包含数据库、`history/` 和 `event.yml`。

文化以其永久 UUID 识别，来源文化和分裂来源教会 UUID 保存在史书索引中。教会按 Church UUID 识别，并关联所属文化 UUID；教会合并、分裂、解散后只归档，不删除原索引和事件。重名新对象不会续写旧时间线。

## 事件范围

文化史书记录：

- 新建、初次接管、解散与更名。
- 治理模式、领袖、枢机人数、模因、戒律和什一税设置变化。
- 玩家信徒、归属城镇、归属国家的数量变化，不记录这些玩家或实体的逐条名单。
- 玩家、城镇和国家绝罚数量变化，不记录被绝罚者名单。
- 教廷金库余额变化、枢机选举开闭状态、文化与父组织关系。
- 神圣大会议案的创建与状态迁移。

教会史书记录：

- 新建、初次接管、首脑移交、成员加入/离开人数变化。
- 金库实际入账/出账金额及交易编号。
- 制裁、申诉、解除制裁，以及并入、分裂、解散。
- 教会发起或作为目标参与的议案创建及状态迁移。

公开叙述和 JSON 事件不包含枢机/教会逐人选票、投票人 UUID、教会成员名单或议案理由；成员变化仅保留人数，金库事件不展示操作者 UUID。议案状态只记创建、批准/否决、完成或失败，不采集每次投票过程。

治理变化在文化实体成功保存后比较快照；教会事件从已保存的结构化教会事实转换为独立公开事件。数据库写入成功后再生成 JSON 投影。史书写入失败只记服务端错误，不撤销已经提交的治理、教会或经济事务。

## 模板

所有叙述由 `event.yml` 的独立键空间生成：

```yaml
ideologyBook:
  title: "%ideology%的文化史书"
  author: "文化史官"
ideologyEvents:
  IDEOLOGY_GOVERNANCE_CHANGED: "%ideology%的治理模式由%before%改为%after%。"
  COUNCIL_PROPOSAL_STATE_CHANGED: "%ideology%的%proposalType%议案状态由%before%变更为%after%。"
churchBook:
  title: "%church%所属%ideology%的教会史书"
  author: "教会史官"
churchEvents:
  CHURCH_HEAD_CHANGED: "%church%的首脑由%before%移交给%after%。"
  CHURCH_TREASURY_CREDIT: "%church%金库收入%amount%，交易编号%transaction%。"
```

日期行分别使用 `ideologyDay` 和 `churchDay`；命令提示分别位于 `ideologyMessages`、`churchMessages`，标识翻译使用 `ideologyLabels`、`churchLabels`。事件 JSON 只存类型、时间、对象和结构化参数，不存生成后的叙述。

## 查阅与导出

命令使用 `wde.player` 权限；两个时间线公开查阅：

```text
/wde history ideology list [页码]
/wde history ideology read <文化名或史书UUID> [页码]
/wde history ideology txt <文化名或史书UUID>
/wde history ideology book <文化名或史书UUID> [卷号]

/wde history church list [页码]
/wde history church read <教会名或史书UUID> [页码]
/wde history church txt <教会名或史书UUID>
/wde history church book <教会名或史书UUID> [卷号]
```

列表和聊天正文每页 8 行；实体书每卷最多 50 页，背包无空位时拒绝发书。不同文化可能有同名教会，查询不唯一时请用史书 UUID。已归档对象的展示名附现实存续区间。

## 边界

文化和教会史书只记录组织沿革与已保存的结构化结果，不重放治理、不结算金库、不保存密封投票，也不把提案内容当作执行结果。数据库和文件系统无法组成同一原子事务；数据库失败或文件投影失败需要依据日志核对。当前事件写入和投影在主线程同步完成，大型服务器启用前应评估 I/O 并备份数据。
