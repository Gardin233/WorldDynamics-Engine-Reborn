# 随机事件系统说明

随机事件由 `EventManager` 调度，配置文件为插件数据目录中的 `events.yml`。该文件与史书模板 `history.yml` 无关。

当前内置事件：

- `raiding`：在城镇外围生成灾厄村民进行劫掠。
- `refugees`：在城镇外围生成一群有职业的难民村民。
- `nether_invasion`：在城镇外围荒野生成一扇不可进入的地狱门，并持续发动下界生物入侵。
- `wandering_livestock`：在城镇外围荒野生成一群普通流浪家畜。
- `maddened_animals`：按强度生成原版外观的狂躁动物，主动追击并攻击附近玩家。
- `phantom_migration`：按强度在城镇已认领地块的无遮挡天空下生成幻翼群。
- `no event`：按配置概率跳过本次事件抽选，不生成实体。

## 调度流程

事件调度器按 `generation.check-interval-ticks` 周期检查城镇。默认值 `6000`，即 5 分钟；最小为 20 tick。调度器首次检查也会等待一个完整周期。

一次城镇检查按以下顺序处理：

1. 只考虑有在线 Towny 居民、且存在 WDE 城镇数据记录的城镇。
2. 根据事件权重和各事件的财富门槛筛出可用事件。权重为 0、负数或非有限值时视为禁用。
3. 以 `chance-per-town-check` 判定是否进入本次事件抽选。
4. 通过基础概率后，再以 `no-event-chance` 判定是否无事发生。
5. 从剩余事件中按权重抽取一个事件，并随机选取该城镇的一名在线居民作为初始目标。

每 5 分钟进行一次新抽取；一次抽取最多启动一个事件，但不同轮次之间完全独立，不设置城镇冷却，也不因同城已有事件而跳过。上一轮劫掠仍在进行时，后续抽取仍可选择难民或再启动一场劫掠；同城可同时存在多场劫掠，每场劫掠单独追踪和结算。

事件权重是相对权重，不是百分比。例如六种事件都符合条件且权重均为 `1.0` 时，单次抽取中各自概率约为 16.7%。某事件因财富门槛不符或权重为 0 被排除后，剩余事件按权重重新计算。

## 配置说明

以下配置均位于 `events.yml`。

### 全局调度

| 配置项 | 默认值 | 说明 |
| --- | ---: | --- |
| `generation.enabled` | `true` | 是否开始新的随机事件；关闭后仍会维护并结束已有持续事件。 |
| `generation.check-interval-ticks` | `6000` | 城镇检查周期，20 tick 为 1 秒，最小值为 20。 |
| `generation.chance-per-town-check` | `0.05` | 每次符合条件的城镇检查进入事件抽选的概率。 |
| `generation.no-event-chance` | `0.25` | 基础概率通过后，无事发生的条件概率，范围按 0–1 限制。 |
| `generation.event-weights.raiding` | `1.0` | 劫掠事件相对权重，设为 0 可禁用。 |
| `generation.event-weights.refugees` | `1.0` | 难民事件相对权重，设为 0 可禁用。 |
| `generation.event-weights.nether_invasion` | `1.0` | 下界入侵相对权重，设为 0 可禁用。 |
| `generation.event-weights.wandering_livestock` | `1.0` | 流浪家畜事件相对权重，设为 0 可禁用。 |
| `generation.event-weights.maddened_animals` | `1.0` | 狂躁动物事件相对权重，设为 0 可禁用。 |
| `generation.event-weights.phantom_migration` | `1.0` | 幻翼迁徙事件相对权重，设为 0 可禁用。 |

`no-event-chance` 是在基础触发概率通过后的条件概率。以默认配置为例，满足资格的单次检查先有 5% 进入抽选；进入后再有 25% 什么也不发生。

### 劫掠强度与生成

| 配置项 | 默认值 | 说明 |
| --- | ---: | --- |
| `raiding.minimum-town-wealth` | `10000.0` | 城镇财富必须严格大于此值，劫掠才进入候选事件。 |
| `generation.strength-formula` | `floor(wealth / 10000)` | 根据城镇财富计算强度点数。 |
| `generation.maximum-strength-points` | `100` | 强度点数上限；设为 0 会使劫掠无法组成兵力。 |
| `raiding.strength.mob-costs` | 见配置文件 | 各灾厄村民类型消耗的点数；只接受有效且大于 0 的劫掠类型。 |
| `raiding.maximum-mobs-per-raid` | `40` | 一次劫掠最多生成的灾厄村民数量。 |
| `raiding.spawn.attempts-per-mob` | `12` | 每名灾厄村民在城镇边界相邻未认领地块中寻找安全生成点的尝试次数。 |

强度公式支持 `wealth`、四则运算、括号，以及 `min`、`max`、`floor`、`ceil`、`abs` 函数。点数会向下取整、限制在配置上限内，并按在线居民数占总人口的比例缩放。公式无效时会跳过劫掠，但不会阻止难民事件。

兵种会从当前剩余点数可负担的配置类型中随机选择，直到点数不足或达到数量上限。劫掠者生成位置从城镇已认领地块边界相邻的 Towny 未认领地块中搜索，不依赖城镇出生点；每个位置还会校验安全地面和未认领状态。

### 劫掠结算

劫掠开始时，事件会记录当时在线的城镇居民；事件期间新加入的在线居民也会纳入参与名单。灾厄村民会在死亡、复活或玩家进出时切换目标。

- 玩家死亡只记录一次死亡状态，不会立即结束劫掠或扣款。
- 即使参与者都已死亡，城镇仍有在线居民时，劫掠继续进行。
- 城镇没有在线居民后，事件才结束。
- 结束时所有参与者都至少死亡过一次，才算劫掠成功；成功时向最初选中的目标扣除其默认货币余额的 5%。
- 城镇先空下来但尚未满足全员死亡条件时，劫掠失败结束，不扣款。
- 扣款需要经济提供方支持该默认货币并成功完成交易；若原目标已离线，也会尝试扣除其账户余额。

服务器或插件重载会清理进行中的劫掠实体，不会因此触发成功惩罚。旧配置中的 `generation.town-cooldown-minutes` 和 `raiding.cooldown-minutes` 已废弃，加载时会移除，不再限制后续抽取。同城存在多场成功劫掠时，每场都会按自身的原目标独立结算 5% 扣款。

### 难民事件

难民事件会在城镇出生点外侧寻找荒野生成位置，生成 3–5 名成年村民并让他们集中在小范围内。找不到至少 3 个有效位置时，本次事件不会启动。

| 配置项 | 默认值 | 说明 |
| --- | ---: | --- |
| `refugees.profession-weights` | 各职业 `1.0` | 职业相对权重；权重为 0 可禁用职业。`NONE` 和 `NITWIT` 不参与抽选。 |
| `refugees.maximum-level` | `5` | 允许的最高村民等级，实际范围限制在 1–5。 |
| `refugees.level-weights` | 等级 1–5 均为 `1.0` | 各等级的相对权重；最高等级的权重可单独调节，设为 0 可禁用该等级。高于最高等级的配置不参与抽选。 |
| `refugees.spawn.minimum-radius` | `32` | 难民群相对城镇出生点的最小外围半径，代码下限为 8。 |
| `refugees.spawn.maximum-radius` | `64` | 最大外围半径，不能小于最小半径。 |
| `refugees.spawn.location-attempts` | `40` | 寻找难民群中心位置的尝试次数。 |
| `refugees.spawn.attempts-per-villager` | `20` | 为每名村民寻找聚集位置的尝试次数。 |
| `refugees.spawn.group-radius` | `4` | 群体活动范围，代码限制在 1–8 格。 |

成功生成后会向被抽中的城镇玩家发送到达提示。难民村民会保持持久化，不会随劫掠事件结束而清理。

### 下界入侵事件

城镇财富严格大于 `nether-invasion.minimum-town-wealth` 时，下界入侵才可进入抽选。事件会在城镇出生点外的 Towny 未认领荒野寻找平坦空地，搭建标准 4×5 黑曜石门框并放置传送门方块。传送事件会被取消，因此玩家和生物都无法进入下界。

初始敌人数按 `ceil(strengthPoints × initial-mobs-per-strength-point)` 计算，默认每点 `0.25` 只，最多 12 只。生物类型从 `mob-weights` 配置中按权重抽取，只允许配置下界敌对生物。事件期间按强度持续增援：强度从 0 增至 `strength-reference-points` 时，间隔由默认 5 分钟线性缩短至 2 分钟，每次增援一只。达到同时存活数量上限时会暂缓生成，`maximum-active-mobs: 0` 表示不限制。

地狱门水平周围默认 5 格范围内禁止放置方块。所有参与入侵的镇民（事件开始时在线及事件期间上线的镇民）都至少死亡一次后，事件会判定劫掠成功、向最初目标扣除 5% 余额并自动结束。破坏门框任意一块黑曜石也会立即结束事件，但不算劫掠成功。默认持续 60 分钟，超时后无成功惩罚并清理入侵生物和门框。城镇无人在线不会提前结束事件。

| 配置项 | 默认值 | 说明 |
| --- | ---: | --- |
| `nether-invasion.minimum-town-wealth` | `10000.0` | 城镇财富必须严格大于此值。 |
| `nether-invasion.duration-minutes` | `60` | 入侵最长持续时间，超时后自动结束。 |
| `nether-invasion.protection-radius` | `5` | 地狱门周围禁止放置方块的水平半径。 |
| `nether-invasion.initial-mobs-per-strength-point` | `0.25` | 初始敌人数相对于强度点数的倍率。 |
| `nether-invasion.maximum-initial-mobs` | `12` | 初始生成数量上限。 |
| `nether-invasion.mob-weights` | 见配置文件 | 下界敌对生物权重；设为 0 可禁用类型。 |
| `nether-invasion.spawn.minimum-radius` | `32` | 门框相对城镇出生点的最小距离，代码下限为 8。 |
| `nether-invasion.spawn.maximum-radius` | `64` | 门框最大生成距离。 |
| `nether-invasion.reinforcement.minimum-interval-minutes` | `2` | 强度达到参考值时的增援间隔。 |
| `nether-invasion.reinforcement.maximum-interval-minutes` | `5` | 低强度时的增援间隔。 |
| `nether-invasion.reinforcement.strength-reference-points` | `100` | 达到此强度后使用最短增援间隔。 |
| `nether-invasion.reinforcement.maximum-active-mobs` | `30` | 同时存活的本场入侵生物上限；0 表示不限制。 |

### 流浪家畜事件

事件会沿城镇已认领地块的边界搜寻相邻 Towny 未认领地块，并在其中的安全地面聚集生成同一类型的牛、羊、猪、鸡、马、驴、骆驼等家畜；选点不依赖城镇出生点。动物使用原版实体和行为，作为普通生物保留在世界中，不会因事件结束而被清理。每次事件按物种权重选一种动物；只有至少生成配置的最小数量时，事件才算成功。成功后会向初始目标发送到达提示。

| 配置项 | 默认值 | 说明 |
| --- | ---: | --- |
| `wandering-livestock.minimum-count` / `maximum-count` | `3` / `5` | 每次到达的普通家畜数量范围，代码最多允许 20 只。 |
| `wandering-livestock.animal-weights` | 见配置文件 | 普通家畜物种相对权重；权重为 0 可禁用物种，所有有效权重为 0 时事件不触发。 |
| `wandering-livestock.animal-names.<ENTITY>` | 实体英文名 | 到达消息中显示的物种名称。 |
| `wandering-livestock.spawn.center-attempts` | `40` | 在城镇边界相邻的未认领地块中寻找安全群体中心的尝试次数。 |
| `wandering-livestock.spawn.group-radius` | `5` | 群体中各动物相对中心的分布半径，代码限制在 1–16 格。 |
| `wandering-livestock.spawn.attempts-per-animal` | `20` | 为每只动物寻找安全位置的尝试次数。 |

### 狂躁动物事件

城镇财富严格大于 `maddened-animals.minimum-town-wealth` 时，事件才可进入抽选。狂躁动物复用熊猫、猪、牛、羊、鸡、山羊、马等原版生物外观；每次事件按物种权重选一种动物。生成数量按 `ceil(strengthPoints × animals-per-strength-point)` 计算，至少 2 只并受配置上限约束。生成中心从城镇边界相邻的 Towny 未认领地块中搜寻，不以城镇出生点为圆心。事件通过 Paper 寻路让动物追击其所在世界中搜索范围内最近的玩家，并在近距离造成配置伤害。默认 15 分钟后，仍存活的狂躁动物会死亡；如果所有动物提前死亡，事件会提前结束。城镇无人在线不会提前结束事件。到达和到期提示中的持续时间会使用实际配置值。

| 配置项 | 默认值 | 说明 |
| --- | ---: | --- |
| `maddened-animals.minimum-town-wealth` | `10000.0` | 城镇财富必须严格大于此值。 |
| `maddened-animals.animals-per-strength-point` | `0.25` | 每个强度点对应的狂躁动物数量倍率。 |
| `maddened-animals.maximum-initial-animals` | `20` | 一次狂躁动物事件的数量上限，代码最多允许 64 只。 |
| `maddened-animals.duration-minutes` | `15` | 狂躁动物存活时限，到期后仍存活的动物会死亡。 |
| `maddened-animals.animal-weights` | 见配置文件 | 狂躁动物物种相对权重；权重为 0 可禁用物种。 |
| `maddened-animals.animal-names.<ENTITY>` | 实体英文名 | 到达消息中显示的物种名称。 |
| `maddened-animals.spawn.center-attempts` | `40` | 在城镇边界相邻的未认领地块中寻找安全群体中心的尝试次数。 |
| `maddened-animals.spawn.group-radius` | `5` | 群体中各动物相对中心的分布半径，代码限制在 1–16 格。 |
| `maddened-animals.spawn.attempts-per-animal` | `20` | 为每只狂躁动物寻找安全位置的尝试次数。 |
| `maddened-animals.attack.target-range` | `96.0` | 搜索玩家的最大距离，单位为方块。 |
| `maddened-animals.attack.range` | `1.8` | 动物进入该距离后可攻击玩家，单位为方块。 |
| `maddened-animals.attack.path-speed` | `1.1` | Paper 寻路速度倍率。 |
| `maddened-animals.attack.damage` | `2.0` | 每次攻击造成的伤害。 |
| `maddened-animals.attack.update-interval-ticks` | `10` | 更新寻路目标的间隔，20 tick 为 1 秒。 |
| `maddened-animals.attack.cooldown-ticks` | `20` | 每只动物两次攻击的最短间隔。 |

### 幻翼迁徙事件

幻翼迁徙会从城镇主世界的已认领 Towny 地块中抽取生成列。幻翼生成位置至少高于该列最高实心地面 10 格，并且从生成位置直至世界高度上限的垂直列必须没有方块遮挡；屋顶、树叶等遮挡会使该列被跳过。数量按 `ceil(strengthPoints × phantoms-per-strength-point)` 计算，默认至少 3 只、最多 40 只。若找到的无遮挡位置不足最小数量，本次事件不启动。幻翼保留原版实体行为。

| 配置项 | 默认值 | 说明 |
| --- | ---: | --- |
| `phantom-migration.phantoms-per-strength-point` | `0.5` | 每个强度点对应的幻翼数量倍率。 |
| `phantom-migration.minimum-phantoms` | `3` | 事件成功启动所需的最少幻翼数。 |
| `phantom-migration.maximum-phantoms` | `40` | 单次事件幻翼数量上限，代码硬上限为 64。 |
| `phantom-migration.minimum-height-above-ground` | `10` | 幻翼生成位置高于最高实心地面的最小距离；低于 10 的配置会按 10 处理。 |
| `phantom-migration.spawn.attempts-per-phantom` | `20` | 为每只幻翼搜索已认领地块无遮挡空域的尝试次数。 |

## 修改与重载

修改 `events.yml` 后可使用 `/wde reload` 热重载，命令需要 `wde.reload` 权限。重载时会补齐缺少的默认配置项；已经配置的值会保留。重载会终止进行中的劫掠并清理劫掠者。

## 第三方事件 API

其他插件可通过 Bukkit 服务发现 `RandomEventRegistry`，注册自定义事件、设置默认权重和资格条件，并选择一次性或持续事件。事件所属插件卸载或主动注销时，WDE 会清理其注册和进行中的实例。接入依赖、接口及代码示例见 [随机事件 API 使用说明](随机事件API使用说明.md)。
