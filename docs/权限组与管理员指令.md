# 权限组与管理员指令

> [Wiki 首页](README.md) · [服主使用文档](使用文档.md) · [国家集团管理菜单](国家集团管理菜单.md)

本文面向服主和管理员。所有管理操作统一从 `/wde admin` 执行，可由有权限的玩家或控制台操作，不需要管理员担任游戏内国王、镇长、统帅或意识形态领袖。

## 1. 权限分组

插件声明权限节点，不会自动创建 LuckPerms 用户组，也不需要安装 LuckPerms 才能使用默认权限。

| 建议组 | 权限节点 | 默认授权 | 能力 |
| --- | --- | --- | --- |
| 默认玩家 | `wde.player` | 所有玩家 | 所有正常玩法命令与菜单 |
| 完整管理员 | `wde.admin` | OP | 所有管理模块、普通玩法、调试与重载 |
| 运维管理员 | `wde.admin.system` | OP | 保存、手动同步、模块开关、重载 |
| 国家管理员 | `wde.admin.nation` | OP | 国家政体、领袖、统帅、成员、选举和外交 |
| 城镇管理员 | `wde.admin.town` | OP | 城镇政体、镇长、征召兵、税制、选举、归属 |
| 集团管理员 | `wde.admin.org` | OP | 集团创建、解散、成员、主席国、制裁、从属状态 |
| 战争管理员 | `wde.admin.war` | OP | 开战、结束战争、分数、停战期、独立战争、和约 |
| 意识形态管理员 | `wde.admin.ideology` | OP | 创建、删除、领袖、归属、首次免费资格、模因和戒律 |
| 背景管理员 | `wde.admin.background` | OP | 查看、修正和重置玩家背景 |
| 集团经济管理员 | `wde.admin.economy` | OP | 修改国家集团账户余额 |
| 调试人员 | `wde.debug` | OP | 原有 `/wde debug` 集成和余额检查 |
| 重载人员 | `wde.reload` | OP | 原有 `/wde reload` |

`wde.admin` 通过子权限继承全部管理模块。非 OP 仅被授予某个管理模块时，可以访问该模块的管理指令、帮助和补全，不会自动获得其他管理模块。

权限判断使用 Bukkit `hasPermission()`，不额外使用 `isOp()` 绕过明确的权限否定。OP 的默认管理资格来自权限声明。实际权限结果由所安装的权限插件、继承关系和上下文共同决定。

### 默认玩家的“所有正常命令”

默认玩家无需逐条申请权限，即可使用 `/wde`、`help`、`docs`、`background`、`ideology`、`town`、`nation`、`org`、`diplomacy`、`inn` 和正常菜单。

**指令访问权限不等于业务决策权限。** 国王任命、镇长征召、居民投票、教主管理、成员国代表操作等，仍须满足 Towny 身份、WDER 职位、当前政体、模块开关、费用、选举期和战争状态。普通玩家不能借由 `wde.player` 替其他国家管理事务。

正常入口仍使用原来的业务规则；管理权限不会自动把普通 `/wde nation` 等命令变为免校验命令。管理员干预应明确使用 `/wde admin`。

默认玩家无法执行 `admin`、`debug`、`reload`。帮助和 Tab 补全隐藏未授权的管理入口；手动填写完整指令时，后台也会拦截。若玩家在打开菜单后被撤销 `wde.player`，点击和聊天输入提交时也会重新检查权限。

## 2. LuckPerms 授权示例

默认玩家已经自动获得 `wde.player`，无需再执行授权命令。需要在 LuckPerms 中显式展示时可使用：

```text
/lp group default permission set wde.player true
```

给完整管理员组授权：

```text
/lp creategroup wdeadmin
/lp group wdeadmin permission set wde.admin true
/lp user 管理员名字 parent add wdeadmin
```

只授予战争干预权限，不需要 OP：

```text
/lp creategroup waradmin
/lp group waradmin permission set wde.admin.war true
/lp user 战争管理员名字 parent add waradmin
```

只授予调试与重载：

```text
/lp group 运维组 permission set wde.debug true
/lp group 运维组 permission set wde.reload true
```

不要给默认组授权 `wde.admin`、任意管理子节点或通配的 `wde.*`。若管理人员是 OP，默认会拥有所有管理子节点；需要严格限制职责时，建议使用非 OP 账号按模块授权。

## 3. 管理入口

```text
/wde admin
/wde admin help [页码]
```

帮助每页最多 8 条指令，仅展示当前操作者有权限的模块。Tab 补全包含模块、动作、国家、城镇、集团、玩家、模因、戒律、背景 ID 和部分参数值。

下方 `<参数>` 必填，`[参数]` 可选；不要输入尖括号。玩家目标可使用已有居民姓名或 UUID，支持离线的已登记居民，不通过输入未知名字创建虚假玩家档案。

带 `confirm` 的指令须显式填写该单词；这是操作者主动确认，不是主席国或其他玩家批准，也不会弹出额外菜单。

## 4. 运维管理

权限：`wde.admin.system`。

```text
/wde admin system save
/wde admin system reload
/wde admin system sync
/wde admin system module <gov|org|army|ideology|background|drops|inn> <enabled|disabled>
```

- `save` 保存城镇、国家、居民、集团和意识形态的当前运行数据。
- `reload` 使用插件现有热重载流程，不切换运行中的数据库连接。
- `sync` 主动补建 Towny 城镇与国家治理记录、更新层级并同步居民。这是显式管理操作；不恢复定时扫描，也不会清理停用期间遗留的删除或改名记录。
- `module` 将对应开关写入配置文件并执行热重载，修改可持续到下次启动。禁用模块不删除其存档。

## 5. 国家管理

权限：`wde.admin.nation`。

```text
/wde admin nation info <国家>
/wde admin nation setgov <国家> <DICTATORSHIP|DEMOCRACY|NOBLE_COUNCIL>
/wde admin nation setleader <国家> <玩家>
/wde admin nation setcommander <国家> <玩家|none>
/wde admin nation govmember <国家> <玩家> <add|remove>
/wde admin nation armymember <国家> <玩家> <add|remove>
/wde admin nation diplomat <国家> <玩家> <enabled|disabled>
/wde admin nation election <国家> <start|cancel|cancelarmy>
/wde admin nation relation <国家> <目标国家> <friendly|neutral|unfriendly>
/wde admin nation trading <国家> <目标国家> <enabled|disabled>
```

设置政体或治理领袖会清理相应旧选举状态。强制设置领袖会按已有治理接口同步 Towny 国王、镇长和首都，候选人仍必须是目标国居民。设置统帅不经过投票；`none` 清空统帅并取消旧统帅投票。

政府与军队成员新增时检查本国居民资格，移除时可清理已有记录。外交官标记仍属于居民扩展状态。`election start` 提前启动民主领袖选举，`cancel` 和 `cancelarmy` 分别取消领袖与统帅选举。

外交态度修改是单向的，不等于开战；`neutral` 表示外交态度，不是 Towny 和平维护费中立状态。原生中立状态、金库、圈地和 Towny 创建删除操作仍使用 Towny 自己的管理工具。

## 6. 城镇管理

权限：`wde.admin.town`。

```text
/wde admin town info <城镇>
/wde admin town setgov <城镇> <DICTATORSHIP|REPUBLIC>
/wde admin town setleader <城镇> <玩家>
/wde admin town conscript <城镇> <玩家> <enabled|disabled>
/wde admin town taxfree <城镇> <玩家> <enabled|disabled>
/wde admin town tax <城镇> <fixed|wealth_percentage> <数值>
/wde admin town election <城镇> start <候选人>
/wde admin town election <城镇> cancel
/wde admin town electiondays <城镇> <天数>
/wde admin town transfer <城镇> <目标国家> confirm
```

强制设置镇长会同步 Towny，并取消旧选举。镇长和新增征召兵必须是本镇居民；管理征召可超过正常人数上限，用于修复档案，后续容量计算仍按服务器设置。免税只能给已登记征召兵设置。

税费不得为负数，财产比例税范围为 `0～100`。管理员设置税制不受正常职位或自治税率上限阻止，后续帝国税率约束结算仍可能重新限制税率。`election start` 仅用于共和制，候选人须属于本镇。

城镇转国使用 Towny 归属操作并更新 WDER 层级；涉及的原国家或目标国家正在参战时，先处理战争再转移。

## 7. 集团管理

权限：`wde.admin.org`。

```text
/wde admin org info <集团>
/wde admin org create <名称> <类型> <主席国>
/wde admin org dissolve <集团> confirm
/wde admin org addnation <集团> <国家>
/wde admin org removenation <集团> <国家> confirm
/wde admin org chairman <集团> <国家> confirm
/wde admin org sanction <贸易联盟> <国家> <enabled|disabled>
/wde admin org subject <帝国> <从仆国> tier <DOMINION|PROTECTORATE|PUPPET>
/wde admin org subject <帝国> <从仆国> suppression <0到100>
/wde admin org subject <帝国> <从仆国> garrison <enabled|disabled>
/wde admin org subject <帝国> <从仆国> duty <enabled|disabled>
/wde admin org independence <帝国> <从仆国> confirm
```

类型为 `TRADE_ALLIANCE`、`MILITARY_ALLIANCE`、`SOVEREIGN_EMPIRE` 或 `IDEOLOGICAL_ALLIANCE`。

创建和添加成员跳过普通成立费、申请投票和集团数量上限；仍保留意识形态匹配、中立军事保护、军事成员冲突和单一帝国归属检查。创建的集团领袖记录取主席国当前国王。

修改主席国属于管理员干预，可以覆盖主权帝国正常玩法中的固定主席国规则；目标须为集团现有成员，且成员未参战。修改时同步集团领袖 UUID，并重建从属状态。

删除成员、解散、改变从属状态及强制和平独立不能留下活跃战争记录；必要时先用战争模块结束战争。`independence` 无需达到自治领或镇压度归零，也不收费、不触发独立战争，直接解除从属身份。

卫戍国始终承担参战义务，不能在保持卫戍身份时单独解除义务；中立国家不能被开启常规强制参战。调整自治等级后重新执行税率上限。普通 `/wde org leave` 的独立战争机制保持不变。

## 8. 战争管理

权限：`wde.admin.war`。

```text
/wde admin war start <进攻国家> <防守国家> confirm
/wde admin war end <国家> <敌方国家> confirm
/wde admin war score <国家> <敌方国家> <进攻方分数> <防守方分数>
/wde admin war independencestart <帝国> <从仆国> confirm
/wde admin war independenceend <帝国> <从仆国> <SUCCESS|FAILURE|STALEMATE> confirm
/wde admin war independencescore <帝国> <从仆国> <独立方分数> <帝国方分数>
/wde admin war truce <国家> <敌方国家> <现实小时数>
/wde admin war reviewtreaty <集团> <收件国家> <对方国家> <accept|reject> confirm
```

- `start` 不经过集团内部宣战投票，但仍要求至少一方具备军事同盟、非中立、无双边停战期且未在同一对抗中交战。
- `end` 结束包含指定双方的整场 WDER 军事同盟战争，清理各关联集团的战争和待决和约；不支付赔款，也不自动创建停战期。不是某个成员国单独退战。
- `score` 的两个数值永远表示进攻方和防守方，不随输入国家顺序交换。修改分数会取消该战争的旧和约提案，需要重新谈判。
- 独立战争结果 `SUCCESS` 解除从属，`FAILURE` 或 `STALEMATE` 保留从属关系；使用现有结果结算与公告流程，并清除旧和约。
- `truce` 设置双边现实时间停战期限，数值 `0` 使其立即到期。管理员手工期限不使用 RealisticSeasons 日历。
- `reviewtreaty` 代替指定收件国家受理现有和约，但仍检查战争和条款是否合法。接受时会真实执行条款，而不只是修改显示状态。

分数与金额拒绝负数、`NaN` 和无限值。战争指令只管理 WDER 战争记录，不强行终止 Towny 或其他战争插件独立维护的战争。

## 9. 意识形态管理

权限：`wde.admin.ideology`。

```text
/wde admin ideology create <名称> <创立者玩家>
/wde admin ideology delete <意识形态> confirm
/wde admin ideology leader <意识形态> <玩家>
/wde admin ideology assign <player|town|nation> <目标> <意识形态|none>
/wde admin ideology firstfree <player|town|nation> <目标> <enabled|disabled>
/wde admin ideology memes <意识形态> <模因1> [模因2] [模因3] [模因4]
/wde admin ideology doctrine <意识形态> <戒律ID> <态度ID>
```

管理员创建不扣费，创建者成为领袖，但不会自动修改其个人信仰；需要时再使用 `assign`。管理员指定领袖不要求其本人先信奉该意识形态。

`assign` 免费覆盖归属；设置为非空意识形态会标记已使用首次选择资格。清空为 `none` 不自动恢复免费资格；`firstfree enabled` 只恢复资格标记，不能在仍有现存信仰时让每次改信都免费。

改变国家信仰不能使其与现有意识形态联盟冲突，需先处理联盟成员关系。删除意识形态前，必须先解除居民、城镇、国家及联盟引用，不留下悬空归属。

模因要求 `1～4` 个合法且不互斥的定义；戒律态度必须存在并满足模因约束。管理员操作不意味着未接入的戒律自动具有数值效果。

## 10. 背景修正

权限：`wde.admin.background`。

```text
/wde admin background info <玩家>
/wde admin background set <玩家> <childhood|adulthood> <背景ID> confirm
/wde admin background reset <玩家> <childhood|adulthood|all> confirm
```

这是管理员档案修复例外，普通玩家的“一阶段选择一次、不可更改”规则保持不变。设置成年背景前仍须有儿童背景。清空儿童背景会一并清空成年背景，避免破坏阶段顺序。

管理员直接设置背景**不发放技能奖励**，会将目标背景记为已处理；重置不扣回 AuraSkills 等级，也不会清除过去已发放奖励记录，以防重复领取同一背景奖励。重置后选择新的、从未发放过的背景，仍按正常玩法奖励流程处理。

## 11. 集团余额

权限：`wde.admin.economy`。

```text
/wde admin economy orgbalance <集团> <非负金额>
```

直接设置 WDER 集团默认货币账户余额，不扣除管理员个人钱包，也不生成转账。该指令不是 Vault 玩家账户修改工具，也不修改 Towny 国库或城镇金库。

## 12. 留痕与使用边界

管理请求、拒绝、成功和失败记录在服务端日志的 `[ADMIN]` 行中，包含操作者名称、玩家 UUID（玩家执行时）、指令和处理结果。日志类独立于指令实现。敏感管理参数不广播给普通玩家；控制台无需游戏内身份。

管理员可以跳过自然玩法中的角色、费用、投票和部分数值门槛，但不会绕过对象存在性、关系一致性和必需的状态清理。管理指令也可以维护已关闭模块的已有 WDER 数据；开启模块后按存档继续运行。

高风险操作前备份数据库。运行期管理命令会保存数据，但并不提供跨模块事务或自动回滚整个操作流程；外部 Towny、经济插件或磁盘写入失败时，应结合日志核查结果，不要盲目重复执行。

升级后需加载新版 JAR 并重启一次，使 Bukkit 注册新权限节点。配置与文案仍可使用插件热重载。
