# 国家史书机制

> [返回 Wiki 首页](README.md) · [使用文档](使用文档.md) · [战争与治理机制](插件机制说明.md)

## 启用与时间节点

修改服务器的 `nation.yml`：

```yaml
history:
  enabled: true
  clock: REAL_TIME
  world: world
```

- 默认关闭，由服主选择是否启用。执行 `/wde reload` 生效。
- `REAL_TIME` 按服务器时区的现实日期分组。
- `REALISTIC_SEASONS` 按指定世界的季节日历日期分组。依赖、世界或日历不可用时，本次事件回退现实日期。
- 每个事件独立保存所使用的时钟、日期、现实时间戳以及可用的日历签名。以后切换配置不会重新解释以前的时间节点。
- 关闭后不新增普通事件，已有史书仍可查阅和导出。解散、重命名等索引维护仍继续，确保不会把新国家写入旧史书。
- 再次开启时，以当时状态作为基线；不推测停用期间发生过哪些事件，也不把这些变化虚构成重新启用当天的历史。

## 史书身份

每本史书有一个永久 UUID，另保存 Towny 国家 UUID。名称只是展示与活动国家查询入口，不用作存储目录。

数据库沿用插件当前的 SQLite 或 MySQL，在 `wde_entities` 中使用：

| 字段 | 内容 |
| --- | --- |
| category | `nation_history` |
| entity_key | 史书 UUID |
| payload | 国家 UUID、名称、建档/成立/解散时间、归档状态、目录索引、快照与结构化事件副本 |

事件目录为插件数据目录下的 `history/<史书UUID>/`。每个事件一个 `<事件UUID>.json`，数据库索引中的 `folder` 字段用于定位目录。

数据库是事件真本，JSON 是可恢复的文件投影。数据库写入成功后通过临时文件与原子替换生成 JSON；文件生成失败会记录服务端错误，后续启动可以根据数据库补回缺失文件。备份应同时包括数据库、`history` 目录和 `event.yml`。

## 成立与接管

- 插件初始化、首次开启历史机制或同步接管已存在国家时，只新增“XXXX从此时开始有了史官”，不会冒充亲历其成立。
- 通过 Towny `NewNationEvent` 发现新国家时，记录“国家于此日成立”，并保存首任国王。
- 现实存续期限优先使用 Towny 原始注册时间；没有可靠注册时间时，使用史书建档时间。这里的时间只用于索引后缀，不补造早期事件。
- 多次同步或重启不会重复建立同一活动国家的史书。

## 采集事件

| 范围 | 记录 |
| --- | --- |
| 国家生命周期 | 成立、史官接管、解散、重命名 |
| 治理 | 政体修改、政府领袖变更、Towny 国王变更 |
| 城镇 | 加入、离开、所属城镇重命名 |
| 意识形态 | 国家意识形态变更，包括和约强制改信产生的国家变更 |
| 战争 | 实际开战、进攻/防守身份、理由、对手、战争结束及双方最终分数 |
| 和约 | 谈判受益方、让步方、谈判败方、条款内容、执行失败 |
| 第三方国家 | 因解放条款获释的从属国也会记载解放事件 |

普通治理事件在国家数据库存档成功后比较快照；命令、菜单、管理员入口与选举共享这条路径。Towny 的成功生命周期事件同步国家档案。重复保存且状态没变化时不会重复记载。

战争事件在战争正式写入账本时记录，不把尚未通过的宣战投票当作战争成立。城镇独立时，其所属国家记载被宣战；独立城镇本身没有国家史书。

和约分别在双方史书中保存“受益/被迫让步”视角，覆盖赔款、强制改信、割地、解散军事同盟、退出集团、解放从属国、无条件通行、羞辱、掠夺首都、长期纳贡、允许独立、强制附庸。

“败方”表示在已生效和约中作出让步的一方，不表示程序依据分数自动判负。管理员单纯结束战争只记录结束，不虚构胜败。主席国主动承认已开战仆从国独立时，也记录解放与主席国的战争让步。

条款记载的是约定和生效结果，不是经济对账单：现有战争经济接口未给所有条款提供完整到账确认，因此赔款、掠夺和长期贡金不宣称每笔资金一定已经到账，也不会逐日重复记载收款。

## JSON 与模板

JSON 不保存生成后的历史句子，只保存事件类型与事实参数。例如：

```json
{
  "id": "事件UUID",
  "type": "GOVERNMENT_CHANGED",
  "recordedAt": 1792368000000,
  "nation": "示例国",
  "clock": "REAL_TIME",
  "day": 20745,
  "values": {
    "before": "DICTATORSHIP",
    "after": "DEMOCRACY"
  }
}
```

人名、国家名、城镇名等是事件事实，允许作为字符串保存；政体、战争理由、结果与条款均保存标识，而非中文叙述。

`event.yml` 管理全部史书句子、日期标题、成书标题、作者、命令反馈和标识翻译：

```yaml
book:
  title: "%nation%的史书"
  author: "史官"
events:
  CHRONICLER_STARTED: "%nation%从此时开始有了史官。"
  GOVERNMENT_CHANGED: "%nation%的政体由%before%改为%after%。"
  TREATY_CLAUSE_TRANSFER_TOWN_CONCEDING: "%nation%被迫将城镇%town%割让给%destinationNation%。"
```

常见占位符包括 `%nation%`、`%before%`、`%after%`、`%town%`、`%opponent%`、`%reason%`、`%beneficiary%`、`%conceding%`、`%percent%`、`%destinationNation%`、`%subjectNation%`。具体可用参数取决于事件类型；条款 `parameters` 的字段也可作为占位符。

修改模板后 `/wde reload`，下一次读取或导出时使用新模板。历史 JSON 不受影响；已经领取的书与已经导出的 TXT 是生成时的快照，需要重新生成才能应用新模板。

## 解散归档

国家被移除时，史书索引软删除：设置 `archived=true` 和现实解散时间，不删除原事件、史书 UUID 或目录，并停止向该书新增事件。

归档显示名为 `国家名(2026.1.1-2026.2.1)`。活跃国家仍使用原名称；同名新国家按新的 Towny UUID 建立新史书。查询归档请使用史书 UUID，或完整的归档显示名。

和约割让最后一城可能先触发国家解散，所以结算期间暂缓封存，待本次和约结果与条款全部记录后再写解散事件。执行失败也会记载失败，不将未完成和约记为成功。

插件停服期间发生的解散只能在下次启动时发现，归档截止点采用发现时间，不伪造精确解散时间。停服期间的国家改名通过 Towny UUID 识别；关闭采集时的变更不会补造普通事件。

国家运行档案仍按原治理规则移除，仅史书索引与事件永久归档；归档国家不会继续参加治理、战争或日常结算。

## 查阅与导出

权限沿用 `wde.player`，史书作为公开国家历史对玩家开放：

```text
/wde history list [页码]
/wde history read <国家名或史书UUID> [页码]
/wde history txt <国家名或史书UUID>
/wde history book <国家名或史书UUID> [卷号]
```

- 列表和聊天读取每页 8 行。名称及 UUID 支持 Tab 补全。
- TXT 写入 `history/<史书UUID>/chronicle.txt`，使用 UTF-8，不展示服务端绝对路径，也不自动向客户端传文件。
- 成书标题为“XXXX的史书”，显示名保留完整国家名；Minecraft 原生成书标题字段受长度限制，过长时截短，仅影响原生标题。
- 中文按行宽保守分页，每卷最多 50 页。长史书可逐卷领取，提示总卷数，不截断后续历史。
- 背包无空位时拒绝领取，不消耗物品、不覆盖已有物品。
- 归档史书同样支持读取、TXT 与成书。

## 验证与边界

已通过全量源码 `javac --release 21` 编译检查以及 33 项序列化、条款模板完整性和成书分页检查。未在真实 Paper/Towny/RealisticSeasons 服务端执行联动测试。

上线应核对：初始化仅一条史官接管事件、新国家成立、改名 UUID 不变、领袖与政体修改、城镇进出、实际宣战、双边条款、割让最后一城后归档、同名新国家、日历不可用回退、长史书分卷和背包满时拒绝领取。

历史写入与 JSON 生成目前在业务主线程同步完成；数据库保存失败会抛出错误并留下日志，不能视为跨 Towny、数据库和经济插件的原子事务。超大史书会增加数据库实体与启动文件投影的成本，建议定期备份，并在大型服务器上评估后再开启。
