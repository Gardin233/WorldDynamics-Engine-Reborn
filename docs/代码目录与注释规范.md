# 代码目录与注释规范

> [Wiki 首页](README.md) · [插件机制说明](插件机制说明.md) · [Paper 兼容性](compatibility-analysis-1.21.11.md)

## 整理范围

源码按“命令、管理器、监听器、模型、集成、事件”分层，并在业务层内按功能拆分子包。持久化实体与对外注册事件保留稳定包名；业务类按功能归档。各类型以职责注释说明用途和关键边界。

## 常用定位

| 要修改的内容 | 首先查看 |
| --- | --- |
| 管理员权限、确认与审计 | `command/admin/`、`command/CommandPermissions.java` |
| 国家政体、选举与城镇税制 | `command/governance/`、`manager/governance/` |
| 帝国自治、贡税与独立 | `command/organization/SovereignSubjectCommand.java`、`manager/organization/OrgManager.java` |
| 和约提出、受理与条款执行 | `command/organization/PeaceTreatyCommand.java`、`manager/organization/OrgManager.java` |
| 占领权重与停战日期 | `manager/war/` |
| 献金、什一税与饮食规则 | `manager/ideology/`、`listener/ideology/` |
| GUI、分页与聊天输入 | `manager/menu/PlayerMenuManager.java` |
| 原版与 CE 额外掉落 | `manager/drop/`、`integration/craftengine/` |
| Towny 创建、改名与归属同步 | `listener/towny/TownyLifecycleListener.java` |

`OrgManager` 管理集团、成员和附属关系。战争实现和战争类型由同包的 `WarManager` 负责。自 `0.3.0` 起，原 `OrgManager` 战争转发方法已删除；Java 调用方须通过 `getWarManager()` 使用新接口，并更新类型引用。`PlayerMenuManager` 仍集中管理其余菜单页面，背景选择页面已通过窄上下文分离。

## 共享逻辑

- `manager/organization/WarManager.java`：持有中央战争账本，负责宣战、计分、占领、停战、和约、重生锁和旧战争存档迁移。组织与战争交叉时仍协作，旧 `OrgManager.saveOrganizations()` 保持先保存战争账本、再保存组织的顺序。计分板直接使用同一战争管理器实例。
- `manager/organization/PeaceTreatyRules.java`：计算条款点数、匹配战争目标条款和识别符合掠袭戒律的经济条款。规则类不查询国家、不保存数据、不执行条款；`OrgManager` 仍负责审批流程、文化倍率查询和结算。
- `manager/ideology/IdeologyRegistryParser.java`：解析模因、戒律、态度、moodWeight、模因限制和效果 ID，只修改调用方传入的注册表并通过告警回调报告无效定义；不访问插件、存档或 Bukkit 事件。`ReligionManager` 仍负责注册表生命周期、外部注册事件、效果校验和文化态度协调。
- `manager/menu/MenuView.java` 和 `MenuPageContext.java`：页面共享库存动作视图与最小渲染能力；它们不持有 `PlayerMenuManager`，由中央菜单监听器统一分发点击事件。
- `manager/organization/WarStateStore.java`：按原格式读写中央战争快照及中央、集团和约提案，不执行磁盘 I/O。`PeaceTreatyTributes.java`：负责固定贡金记录、旧比例贡金迁移及扣款后入账的顺序，国家查询与金库操作由调用方提供。`OrgManager` 保留公开接口、实际保存和战争、和约业务协调。
- `PluginConfiguration.java`：负责配置加载和写回顺序，保留其余模块的默认值补全、经济设置解析和心情期望的局部热读。文件访问由 `ConfigurationFiles` 负责；`LegacyConfigMigration` 仅迁移内存中的跨文件旧键，`CultureConfigRepair` 仅修改内存中的 `ideology.yml` 内容，不直接写盘。主类仍通过 Bukkit 加载根配置，语言文本查询仍由 `LocaleMessages` 负责。
- `manager/ideology/CultureModule.java`：集中持有文化、教会、仪式、心情、戒律效果和文化史书的管理器/监听器，共 31 个字段。入口仅持有该模块，原文化 getter 保留并委托给模块，以兼容现有调用。模块构造不获取插件依赖；入口按原顺序分阶段初始化，文化监听注册、任务启动、重载、保存和关闭清理统一由模块负责。全局任务取消及监听解绑仍由入口统一执行。该类只做装配和生命周期协调，不合并管理器业务逻辑，也不代表已消除管理器之间通过入口 getter 取得依赖的关系。
- `manager/ideology/DoctrineAttitudePolicy.java`：独立判断戒律态度合法性、非人化模因门槛、默认候选优先级及态度 ID 规范化。只接收定义和已登记的模因 ID，不读取插件、YAML、居民或数据库，也不修改文化。`ReligionManager` 保留原接口，负责解析模因别名、查询注册表、写入态度和刷新装备心情；默认候选选择与跨模因合法性校验仍是两个独立步骤。
- `manager/ideology/MoodManager.java`：持久化戒律行为的心情变动，每分钟按模因效果与心情概率发布 `PlayerMoodEvent`。`DoctrineBuffManager.java` 仅管理仍保留的圣物药水效果；护甲、饮食和动物击杀戒律不再直接施加药水效果。
- `manager/economy/GovernmentTreasury.java`：统一公共金库费用的默认货币换算、展示、余额检查、扣款和国家/城镇保存。集团创建、从仆国操作、文化改信和帝国征费复用此实现。
- `command/organization/NationAuthority.java`：统一国王、政府领袖、军队统帅的集团代表资格判断。调用方仍按原规则通过玩家姓名或 UUID 取得居民，不改变身份查找方式。
- 金库工具不决定操作权限，不新增退款或跨插件事务。调用方仍负责其原有业务校验及补偿；币种比较保持大小写敏感。
- 和约的国王专属权限、投票与开关解析的不同输入别名不强行合并，避免因降低重复而扩大授权或改变指令行为。

## 兼容边界

- 插件主类路径及 `/wde` 指令不变，资源配置位置不变。
- 持久化实体的原包名、序列化别名和数据库分类不变，不需要因为本次整理迁移数据库。
- 文化注册事件及其定义接口保留原包名，避免仅因目录整理破坏常见外部监听接口。
- 被移动类的完整包名已经变化。外部插件若直接引用这些管理器、命令、集成或辅助模型，需要更新导入并重新编译；本次不提供旧包转发类。
- CraftEngine 的反射适配器路径已同步更新，仍采用可选依赖加载。
- 验证编译产物位于临时目录，本次未替换 `target/` 中既有发布包。正式发布应使用完整的干净构建，避免把旧包下的 `.class` 残留混入 JAR。

## 注释约定

1. 类型注释放在声明及类型注解之前，说明职责和重要边界。
2. 状态类、枚举和结果记录应说明其保存的数据或代表的流程阶段。
3. 对扣款退款、持久化、冷却、权限和跨插件调用，优先解释约束与原因。
4. 不为每个 getter 或普通赋值添加重复注释；复杂算法和状态转换再补方法或局部说明。
5. 注释不应把注册定义描述为已执行的效果，也不承诺未经实服测试的兼容性。
