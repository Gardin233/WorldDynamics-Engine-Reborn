# 代码目录与注释规范

> [Wiki 首页](README.md) · [插件机制说明](插件机制说明.md) · [Paper 兼容性](compatibility-analysis-1.21.11.md)

## 整理范围

源码按“命令、管理器、监听器、模型、集成、事件”分层，并在业务层内按功能拆分子包。持久化实体与对外注册事件保留稳定包名；业务类按功能归档。各类型以职责注释说明用途和关键边界。

## 常用定位

| 要修改的内容 | 首先查看 |
| --- | --- |
| 管理员权限、确认与审计 | `command/admin/`、`command/CommandPermissions.java` |
| 国家政体、选举与城镇税制 | `command/governance/`、`manager/governance/` |
| 帝国自治、贡税与独立 | `command/organization/SovereignSubjectCommand.java`、`manager/organization/OrgManager.java` |
| 和约提出、受理与条款执行 | `command/organization/PeaceTreatyCommand.java`、`manager/organization/OrgManager.java` |
| 占领权重与停战日期 | `manager/war/` |
| 献金、什一税与饮食规则 | `manager/ideology/`、`listener/ideology/` |
| GUI、分页与聊天输入 | `manager/menu/PlayerMenuManager.java` |
| 原版与 CE 额外掉落 | `manager/drop/`、`integration/craftengine/` |
| Towny 创建、改名与归属同步 | `listener/towny/TownyLifecycleListener.java` |

`OrgManager` 仍协调集团与战争状态，`PlayerMenuManager` 仍集中维护菜单。目录整理不代表这两个大型类已经按业务拆分。

## 共享逻辑

- `manager/ideology/DoctrineBuffCalculator.java` 与 `DoctrineBuffManager.java`：按来源计算非负药水等级，统一替换、加减、到期及清理；护甲与饮食效果均通过此入口施加。`listener/ideology/DoctrineBuffListener.java` 负责死亡和离线清理。
- `manager/economy/GovernmentTreasury.java`：统一公共金库费用的默认货币换算、展示、余额检查、扣款和国家/城镇保存。集团创建、从仆国操作、意识形态改信和帝国征费复用此实现。
- `command/organization/NationAuthority.java`：统一国王、政府领袖、军队统帅的集团代表资格判断。调用方仍按原规则通过玩家姓名或 UUID 取得居民，不改变身份查找方式。
- 金库工具不决定操作权限，不新增退款或跨插件事务。调用方仍负责其原有业务校验及补偿；币种比较保持大小写敏感。
- 和约的国王专属权限、投票与开关解析的不同输入别名不强行合并，避免因降低重复而扩大授权或改变指令行为。

## 兼容边界

- 插件主类路径及 `/wde` 指令不变，资源配置位置不变。
- 持久化实体的原包名、序列化别名和数据库分类不变，不需要因为本次整理迁移数据库。
- 意识形态注册事件及其定义接口保留原包名，避免仅因目录整理破坏常见外部监听接口。
- 被移动类的完整包名已经变化。外部插件若直接引用这些管理器、命令、集成或辅助模型，需要更新导入并重新编译；本次不提供旧包转发类。
- CraftEngine 的反射适配器路径已同步更新，仍采用可选依赖加载。
- 验证编译产物位于临时目录，本次未替换 `target/` 中既有发布包。正式发布应使用完整的干净构建，避免把旧包下的 `.class` 残留混入 JAR。

## 注释约定

1. 类型注释放在声明及类型注解之前，说明职责和重要边界。
2. 状态类、枚举和结果记录应说明其保存的数据或代表的流程阶段。
3. 对扣款退款、持久化、冷却、权限和跨插件调用，优先解释约束与原因。
4. 不为每个 getter 或普通赋值添加重复注释；复杂算法和状态转换再补方法或局部说明。
5. 注释不应把注册定义描述为已执行的效果，也不承诺未经实服测试的兼容性。
