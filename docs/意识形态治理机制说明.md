# 意识形态治理机制说明

> [Wiki 首页](README.md) · [意识形态治理模式使用说明](意识形态治理模式使用说明.md) · [项目完结目标](项目完结目标.md)

## 数据状态

一元制治理状态保存在 `WDEreligion` 实体内；共议制扩展到三个持久化实体类型：

- `governanceMode`：`LIFETIME`、`CARDINAL`、`SYNODAL`。
- `cardinals`：玩家 UUID 到最近名称的映射。
- `nextElection`、`electionDeadline`、`electionBallots`：下一轮时间、进行中选举截止点和密封选票。
- `leadershipHistory`：领袖交接、治理模式变化、枢机任免和选举汇总记录。
- `WDEChurch` (`ideology_churches`)：源意识形态 UUID、教会 UUID、首脑、成员、金库、制裁、状态和结构化组织事件。
- `IdeologyCouncilProposal` (`ideology_council_proposals`)：提案来源、提案教会/首脑、结构化参数、理由、截止时间、教会票箱、权重结果和执行状态。
- `WDEresident.churchUuid`：一名居民在当前源意识形态中的教会归属；个人意识形态变更会清除此字段。

缺少 `governanceMode` 的历史数据迁移为 `LIFETIME`；缺少 `ideologyUuid` 的旧数据按名称生成确定性 UUID，并立即保存。独立分裂后的新意识形态保存 `parentIdeologyUuid` 与 `parentChurchUuid`，后续改名不影响来源关联。

## 终身制与领袖连续性

禅让校验目标仍是未受制裁的当前追随者，且未担任另一意识形态领袖。继任以服务器当前时间即时生效，历史记录的 `effectiveAt` 与 `previousLeaderAuthorityEndedAt` 相同。

主动改信和城镇强迫改信不能使现任领袖绕过禅让规则。管理员 `/wde admin ideology leader` 是明确的恢复入口，并校验目标资格。创建意识形态时也保留“一名玩家不得同时领导多个意识形态”的既有规则。

## 枢机任免和金库

任免操作顺序为：检查现任领袖权限、检查枢机模式、检查目标成员/制裁状态、计算席位限制、复制实体、扣减治理费用、记录任免、保存并发布。治理费用只从意识形态实体记录的默认货币余额扣除，不调用玩家经济账户。数据库保存失败时旧实体仍保留原余额和任免名单，因此不需要对玩家钱包执行补偿退款。

普通献金和什一税仍只能增加金库余额。任免是唯一允许扣减金库的治理操作，且没有玩家可调用的提款命令。

席位容量由当前未受制裁追随者数动态计算：

```text
min(maximumSeats, baseSeats + floor(max(0, followers - 1) / followersPerAdditionalSeat))
```

席位缩减时从 `LinkedHashMap` 末尾开始撤销，即优先撤销最新任命；撤销原因记为 `SEAT_CAPACITY_REDUCED`。受制裁或改信导致资格失效时，成员资格在保存事件或下一次治理巡检中重算。巡检每分钟运行一次。

## 枢机选举

周期和投票截止点以 `endAt` 保存现实时间备用值。使用季节时钟时，同时保存日历签名、世界和日序；重启后沿用该截止点，不重新开周期。日历不可用或结构不匹配时遵循现有停战时钟回退规则。

选举规则固定如下：

- 选民为开票/计票时仍是该意识形态未受制裁追随者的现任枢机。
- 候选人为所有未受制裁追随者，或按配置限制为枢机；候选人不得同时领导另一意识形态。
- 投票权为 `ONE_CARDINAL_ONE_VOTE`，每个枢机 UUID 在票箱中最多有一条选择；票箱只保存在意识形态实体，命令不提供个人选票查询。
- 法定人数按有效枢机人数乘 `quorumRatio` 向上取整。缺席默认不计入，弃权默认计入法定人数但不计入候选人票数；两个行为可分别配置。
- 候选人需达到有效非弃权选票的 `winnerMinimumRatio`。最高票平局时按 `tiePolicy` 保留现任领袖或判定无人当选。
- 无人当选时不清空领袖，保留现任领袖。`noWinnerPolicy: RETRY_AFTER_DAYS` 按 `noWinnerRetryDays` 重试；`KEEP_INCUMBENT` 按正常周期重试。
- 开票和最终计票都会重新校验枢机、候选人及成员资格，避免资格改变后仍沿用旧身份。

结算结果只记录合格人数、参与人数、UUID 对应的汇总票数、胜出 UUID 和结算时间，不输出个人 UUID 对应的选票。完整的个人选票存储仅为重启恢复所需，后续意识形态史书不得将其公开。

## 枢机赐福与什一税

日税流程先读取居民当前个人意识形态，再检查该意识形态是否处于枢机制。系统通过 Towny 当前 Resident UUID 查询缴税者城镇和有效枢机城镇；只有两者城镇相同，才跳过该意识形态本次什一税。它不修改居民身份、税率、Towny 税务政策或任何其他意识形态账户。

此关系不做缓存，因此玩家离开城镇、枢机迁居和 Towny 城镇归属变化都会在下一次什一税结算实时反映。失去该意识形态追随者资格或受制裁的枢机不提供赐福。

## 共议制

### 教会归属与金库

进入共议制会在一个 SQLite/MySQL 事务中写入源意识形态、首教会和原领袖的居民档案。原教廷金库全额转入首教会，同时清零源意识形态金库；原枢机名单和选举状态关闭。每名玩家同时最多属于一座教会，首脑也属于自己的教会。

教会创建费用先从发起人钱包按配置币种扣除，数据库提交失败时尝试原币种退款。成员转会、禅让、解散及个人改信都更新相关教会与居民实体。只有空金库的教会能解散，且不能解散源意识形态最后一座活跃教会。教会首脑的禅让和成员操作均检查冷却。

共议制期间，什一税只向当前属于活跃教会的同信仰成员征收，写入其所属教会金库；未加入教会的源意识形态追随者不缴纳共议制什一税。什一税率仍保存在源意识形态上，只能由通过的大会议案修改。源教廷金库没有玩家提款入口；每座教会的金库互相隔离，成员可献金，只有本教会首脑可取款。教会提款先持久化金库扣款，再执行 Vault 入账；钱包明确拒绝时会写入同一交易 UUID 的补偿流水。若补偿写入也失败，服务器会输出 `CRITICAL` 日志及交易 UUID，供管理员按教会流水人工核对。数据库与 Vault 属于不同事务域，不能承诺跨服务 exactly-once。

### 大会议案与制裁

提案需要活跃教会首脑身份、书面理由和冷却校验；教义参数在创建和通过时分别校验，防止已移除定义或失效成员身份绕过筛选。已实现的议案类型包括模因、戒律态度、什一税、施加制裁、解除/复议制裁和回归一元制。

每座未受制裁的活跃教会由现任首脑投一张密封 `YES` 或 `NO` 票。默认权重是当前有效成员人数，可配置为 `EQUAL_CHURCHES` 等权模式，并由 `maximumChurchWeight` 封顶。投票资格与权重在计票时按实时成员关系重算。缺席不计入已投权重但仍留在总权重分母内；默认法定人数和通过比例均为 50%，赞成权重必须严格高于通过门槛，平票不通过。

制裁记录原因、提出议案 UUID 和现实时间截止点。制裁期间只排除该教会投票资格，不改写成员、教会身份和金库余额；目标教会首脑可以提交申诉，其他教会可以另提解除制裁案。制裁到期按现实时间自动失效。

### 回归一元制与独立分裂

通过回归议案后，单次数据库事务同时更新源意识形态、全部活跃教会、受影响居民及议案结果。每座归并教会保存 `treasurySettlementOperation` 和 `settledTreasuryAmount`，金库余额清零并归档；总额只向源意识形态入账一次。事务提交失败时数据库中仍保持原教会、原余额和 `APPROVED` 议案，分钟巡检会重试；不会先删教会再转钱。通过者成为新领袖。目标为枢机制时，所有现教会首脑必须仍是追随者，且人数不能超过动态枢机席位上限，否则议案转为失败而不动资产。

教会独立是首脑主动操作：操作事务同时创建带来源 UUID 的终身制异端、归档分裂教会、将教会金库转入新异端，并把教会当前成员转为异端追随者。新意识形态保存源模因、戒律态度与什一税政策快照，之后双方实体和玩家归属独立变化。

每项议案、教会改制及分裂先在副本中构造，再通过 `DataStorageManager.saveEntities` 在同一数据库事务写入多个分类；仅在提交成功后更新运行内存。选举与议案票箱只保存 UUID/教会 UUID 及选择，不提供查询个人选票的命令。
