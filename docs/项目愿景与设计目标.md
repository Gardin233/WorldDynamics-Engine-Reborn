# WDER 项目愿景与设计目标

> [Wiki 首页](README.md) · [玩家玩法](玩法说明.md) · [服主使用文档](使用文档.md) · [插件机制说明](插件机制说明.md) · [项目完结目标](项目完结目标.md)

## 一句话愿景

WDER 希望成为 Towny 文明服务器的长期治理与战后秩序引擎：让城镇、国家与国家集团不仅能存在，还能在治理、外交、战争、谈判和制度变化中留下持续影响。

## 为什么做 WDER

Towny 已经提供了城镇、国家、居民、领土与基础金库等重要底层能力。WDER 不打算重复实现这些基础系统，而是尝试补上更长周期的政治问题：

- 国家由谁治理，权力通过任命、选举还是议会产生？
- 国家如何合作、结盟、施加制裁，以及在战争中承担什么责任？
- 主权帝国如何处理自治、贡税、镇压、卫戍与独立？
- 战争结束后，领土、国家关系和从属结构怎样改变？
- 玩家和普通国家成员如何参与政治，而不只是在战场上交战？
- 这些选择如何持久保存，并形成服务器自己的政治历史？

WDER 的目标不是替服务器预写一段结局，而是提供一组可配置、可执行、可追溯的制度，让玩家共同创造历史。

## 核心定位

WDER 是 Towny 之上的治理扩展层：

| 层次 | 主要职责 |
| --- | --- |
| Towny | 居民、城镇、国家、领土、地块权限和原生金库等基层事实 |
| WDER | 政体、选举、国家职位、集团治理、战争状态、和约与政治后果 |
| 可选集成 | 经济、季节日历、技能、自定义物品等扩展能力 |

基层对象仍以 Towny 当前状态为准。WDER 不应因为增加上层权力结构，就让国家集团主席自动越级管理成员国的城镇；也不应把外交态度、战争状态和意识形态立场混为同一种关系。

## 核心玩法循环

```text
建立城镇
  → 形成国家
  → 选择政体并组织治理
  → 建立外交与国家集团关系
  → 长期积累利益、冲突与制度变化
  → 以战争、制裁或谈判处理重大争端
  → 通过条约改变领土与主权结构
  → 重建秩序并开启下一轮政治演变
```

这是一条长期循环，而不是一次性任务线。一次战争的价值不只在于谁击杀更多玩家，更在于它带来的让步、独立、附庸、领土转移、联盟瓦解与新的政治关系。

## 设计原则

### 权力有边界

每个治理层级只拥有其制度授予的权限。国家集团管理国家层关系；国家治理自己的城镇；城镇治理本地事务。授权、委托与职务权限必须由服务端校验，不能只靠隐藏菜单按钮。

### 结果必须落地

战争、和约、改宗、从属关系和治理变更应实际改变持久化状态，而不止是显示一段成功文案。涉及 Towny、经济提供者和数据库的跨系统操作必须说明失败补偿边界，并保留可调查记录。

### 规则透明且可预期

玩家在行动前应能知道资格、费用、目标、可选条款与失败原因。战争理由由玩家手动选择，系统筛选和复验资格；不能在玩家不知情时替其指定政治目标。

### 长期历史比即时数值更重要

人口、金库、领土、领袖和联盟都能影响制度；它们的变化应可持续、可复查。史书记录事件事实，叙述由模板生成，避免历史因语言调整而丢失。

### 有效玩法不等于配置定义

配置中出现一个模因、戒律、战争理由、仪式类型或条款，并不代表它已经有可运行效果。只有具备状态、校验、执行、保存、失败处理和测试的机制，才算真正接入。

### 允许服务器选择复杂度

不同服务器的政治风格和运营能力不同。高复杂度系统应能配置启停、调整成本和规则；未配置或缺少可选依赖时，基础 Towny 治理不应无故失效。

### 玩家选择是政治动力

制度可以约束玩家，但不应把所有重要决策都压给单一管理者。投票、职务、外交行动、仪式、战争目标和公开历史应逐步提供普通成员可理解、可参与的入口。

## 核心竞争力

WDER 的独特价值不在于“又一个领地战争插件”，而在于把长期国家治理和战后结构变化连接起来：

1. **主权帝国治理**：自治等级、镇压度、贡税、卫戍国和参战义务构成可演变的从属关系。
2. **有后果的和平条约**：谈判可以改变领土、国家关系、附庸结构与战后秩序，而不是只宣布胜负。
3. **制度与战争互相影响**：国家政体、联盟关系、战争理由和治理能力会改变可采取的政治行动。
4. **持久的服务器历史**：国家事件进入史书；未来意识形态、教会和外交历史也应沿用相同的可追溯原则。

这些是项目方向，不代表相关规划项都已实现。已经上线和正在规划的边界应以[使用文档](使用文档.md)、[插件机制说明](插件机制说明.md)和[项目完结目标](项目完结目标.md)为准。

## 面向的服务器

WDER 优先面向：

- 长期运行、以文明建设和国家关系为核心的 Towny 服务器。
- 有意组织政体、国家集团、外交、战争谈判与历史记录的历史/政治 RP 社区。
- 愿意由服主配置规则，并向玩家提供制度说明和新手引导的服务器。

WDER 不以纯 PvP、短期速战或完全无需管理的即插即用体验为首要目标。系统规模较大，运营者需要根据社区规模裁剪启用模块。

## 明确不做什么

- 不替代 Towny 的建镇、建国、圈地、领土保护与原生对象管理。
- 不把服务器中所有外交、政治、经济或人物关系强行收编为唯一系统。
- 不把战争自动等同于 PvP 胜负；战场战斗是政治结算的输入，不是唯一结果。
- 不把尚未实现的配置定义包装成已经生效的游戏机制。
- 不允许上级集团越过成员国家，默认取得其城镇层的无限管理权。
- 不承诺未经测试的经济提供者、Towny 扩展和战争插件组合能够无冲突运行。

## 当前与愿景的界线

当前 WDER 已有国家和城镇治理、国家集团与主权帝国、战争理由与战争账本、可执行和平条约、终身制/枢机制/共议制意识形态治理、教会与大会议案、部分意识形态戒律效果、背景系统、外交访问、外交信件命令以及国家史书等机制。

仍在规划或需要完成的方向包括：意识形态金库消费、异端与异教的政治关系、全部内置戒律效果、仪式、战争目标差异化、革命与反革命、书与笔外交信件界面、旗帜展示、臣子机制与稳定对外 API，以及意识形态和教会史书。

这些方向按[项目完结目标](项目完结目标.md)逐步推进。项目“完结”不是功能数量达到某个值，而是核心制度闭环可解释、数据可靠、权限清晰、玩家能参与，且文档与实服行为一致。
