# WDER 项目完结目标

> [Wiki 首页](README.md) · [使用文档](使用文档.md) · [插件机制说明](插件机制说明.md) · [国家史书机制](国家史书机制.md)

本文定义 WDER 从“功能已接入”走到“可长期运营”的剩余目标。它是路线图，不代表下列机制已经实现。开发时应先完成核心闭环和数据正确性，再扩展内容规模；每项完成后同步命令帮助、配置注释、语言文件、使用文档和机制文档。

## 1. 完成定义

项目达到可发布状态至少应满足：

1. 核心治理、外交、战争、和约、意识形态和史书链路有权限校验、持久化、失败反馈和可验证的结束状态。
2. 不存在只显示按钮但没有后端规则，或命令可执行而菜单状态不一致的主要功能。
3. 配置升级不覆盖服主数据；数据结构变更提供迁移、兼容或明确的重建边界。
4. 外部 API 有稳定契约、权限检查、生命周期说明和可运行示例。
5. 核心纯逻辑有自动化测试，Paper/Towny 依赖路径有可重复的集成测试清单，并在目标服务端实测。
6. 玩家能从游戏内帮助或 Wiki 明白操作后果、费用、失败条件和记录范围。

## 2. 当前基线

已经具备、后续目标不应重复从零开发的基础：

- 国家集团类型、主权帝国从仆等级、自治/镇压/贡税、卫戍国和参战义务。
- 手动选择且按条件过滤的战争理由、统一战争账本、周期计分、和约条款、停战期及独立战争整合。
- 意识形态治理模式（终身制、枢机制、共议制）、教会成员与独立金库、大会议案、制裁/申诉、教会分裂及回归一元制。
- 意识形态创建、模因和戒律定义、冷却、源意识形态单向金库、献金和每日什一税。
- 部分戒律实际效果：护甲、饮食和动物击杀；统一来源式药水效果计算器。
- 国家史书数据库索引、JSON 事件文件、模板渲染、归档、TXT 与分卷成书。
- 现有史书记录国家事件，没有独立意识形态/教会历史时间线。
- 外交信件的命令发送、费用、持久化、国家身份收件通知和史书事件。

本路线图聚焦这些基础上的缺口：意识形态金库消费行动、异端/异教关系、内置戒律效果补完、仪式与意识形态史书、战争目标与革命/反革命、外交信件 GUI、旗帜展示，以及面向臣子的稳定扩展 API。

## 3. P0：机制正确性与发布底座

这是扩展新玩法前的发布门槛。

### 3.1 状态与权限审计

- 为每个经济与政治动作画出“资格 → 预览 → 扣费/变更 → 持久化 → 结果反馈 → 史书记录”的完整链。
- 菜单展示、Tab 补全、命令入口和业务管理器采用相同资格规则；界面不能作为绕过服务端校验的方式。
- 确认国家、城镇、集团、意识形态、战争和史书数据在删除、改名、退出、并入、迁移时均有明确的主数据来源及失败处理。
- 为所有会扣款或变更 Towny 状态的流程定义补偿边界；退款失败、部分完成、重复回调均应留日志和可恢复信息。

**验收：**建立关键动作权限矩阵和状态转换表；每条拒绝路径有具体反馈；重复提交不产生重复扣款或重复事件；高风险流程在数据库失败及服务重启后可判定最终状态。

### 3.2 基础测试与实服回归

- 纯逻辑测试覆盖战争权重、和约点数、历史模板、Buff 叠加、权限判断和状态迁移。
- 存储测试覆盖 SQLite/MySQL 序列化、旧数据加载、软删除和失败注入。
- Paper/Towny 联调覆盖创建/改名/解散国家、城镇转移、国家中立、战争、死亡、复活、传送、每日税收及服务器重启。
- 每次发布使用 Java 21 编译，并在目标 Paper/Towny 版本完成回归清单。

**验收：**发布包可由固定脚本构建；核心测试可重复运行；实服回归记录实际依赖版本和结果，不以“源码编译成功”替代游戏行为验证。

## 4. P1：意识形态的政治与经济闭环

### 4.1 意识形态金库消费行动

源意识形态教廷金库支持献金和什一税收入，且没有玩家提款入口；共议制下各教会另有独立金库，由该教会首脑按权限提款。本目标是为源意识形态金库增加受业务规则约束的用途，不开放任意转账或直接提现，例如：

- 传教/公共仪式：面向信徒或指定城镇的可见活动。
- 教义传播：支付费用后产生有期限、范围和参与条件的影响。
- 救济或公共工程：消耗金库并产生可核验的受益对象和史书事件。
- 维护组织、圣地或意识形态设施等可配置行动。

每种支出需有独立费用、权限、冷却、目标范围、资金流水和幂等键；由受权领袖或配置规则触发，不能新增任意转账或提款漏洞。明确金额上限、失败退款、并发扣款和金库余额不足行为。

**验收：**金库余额只通过已注册消费行动减少；所有支出可追溯到发起者、行动、受益者、金额和时间；重复请求不会重复扣款；每种行动都有消息、配置和权限测试。

### 4.2 异端、异教与改宗关系

把“异端”和“异教”定义为两种不同关系，避免把名称相似的信仰一律当敌人：

- 异端：共享或承认部分信仰传统，但在指定教义、模因或合法领袖问题上存在分歧。
- 异教：被当前意识形态判断为不同信仰；无信仰是否算异教由显式规则决定。
- 宗教领袖、国家/城镇信仰和个人信徒需要分别判定，不得由国家信仰推断每个居民身份。

可配置对异端/异教的接纳、排斥、传教、贸易、通行和外交影响。初期只实现展示、资格与可记录政治关系；任何经济或战斗效果必须后端重校验，不能依赖 GUI 文案。

**验收：**同教、异端、异教、无意识形态四种关系结果明确；关系变化有来源和时间；宣战、改宗、集团加入等入口共享同一判定服务。

### 4.3 内置戒律效果补完

当前大量戒律已经有定义，但并非每条定义都有可执行效果。逐条审计 `ideology.yml` 的内置戒律，建立覆盖表：

| 维度 | 需要定义的行为边界 |
| --- | --- |
| 穿着与居住 | 护甲、服饰、室内/野外、舒适度与天气 |
| 食物与生物 | 素食/肉食/人肉/血食、动物共存、畜牧与击杀 |
| 资源与环境 | 采矿、伐木、树木崇拜、资源浪费和采集方式 |
| 社会与忠诚 | 多元文化、非人化、变节、仁善、奴役/救助等可观测行为 |
| 仪式与传播 | 仪式参与、传教行为、信仰场所等有明确事件来源的行为 |
| 战争与风险 | 和平主义、战斗参与、俘虏与战争行为，必须与统一战争状态联动 |

每条戒律应说明“检测事件、适用身份、允许/违背条件、效果来源、等级/持续时间、冷却、关闭与清理”。没有可信 Bukkit/Towny 事件支持的戒律先标为展示/筛选，不得伪造已经生效。

**验收：**内置戒律清单逐项标记为“已实现效果 / 仅定义 / 暂不支持”；已实现项具备正反行为测试、缺定义停用测试及卸载/重载清理。

### 4.4 仪式与仪式地点

仪式由两个层次组成：

- **仪式定义**：受治理模式约束的命名、固定类型、允许模因、消耗物、效果、目标规则和冷却配置。一元制由领袖管理；共议制下的定义修改须经神圣大会议案通过。
- **仪式场次**：发起人、仪式地点、参与者、提交物品、开始/结束时间和结果。允许不同玩家群体同时举行不同场次。

仪式类型及底层效果由服主/固定注册表决定，不允许玩家自定义任意 PotionEffect 或任意命令执行。仪式定义可以指定消耗物品来换取限时 Buff，或对符合范围的给定目标施加效果。

- 仪式场次不因参与者的阶级/职位而禁止举行；教会或个人主持资格应与“能否参与”分开定义。
- 效率只由明确的计算项组成：实际参与人数、参与者与发起方的意识形态/城镇/国家/教会关系、成功消耗物品数量。公式支持递减收益和上限，结算前显示预估效果。
- 一个玩家可在短时间内参加多场已经结束或不重叠的仪式，但同一时间只能属于一个进行中的场次。加入/退出/崩溃恢复需以仪式场次 ID 幂等。
- 仪式地点是定义或场次的一部分，校验世界、范围、可用性及破坏/改名；组织者取消、服务器重启、参与者离线和物品不足都要有明确处理。
- 仪式消耗物必须在开始/结算时可核验，统一记录物品 ID、数量、参与者和退款结果；不得只凭 GUI 预览消耗。
- 枢机赐福和共议教会无权私自修改仪式效果或名称。共议制下这类修改必须通过神圣大会议；未批准议案不得直接改变运行中场次。

**验收：**同一玩家无法并行参加两场仪式；多场之间的物品与 Buff 来源互不污染；玩家数量、身份和材料变化对效率的影响可复算；所有效果到期/撤销遵守 Buff 来源策略。

### 4.5 意识形态与教会历史

现有史书以国家 UUID 为索引，不能代替意识形态组织内部历史。新增独立的意识形态史书索引，并为共议制的教会保留可关联的组织时间线：

- 意识形态创建、创始人、治理模式变更、领袖选举/禅让、模因与戒律变更。
- 枢机任命/撤销、候选资格、投票权、投票结果、赐福城镇范围和什一税豁免启停。
- 教会创建、首脑禅让、成员/信仰归属变化、神圣大会议案、表决、制裁与解除、独立分裂、新异端意识形态创建。
- 教廷/教会金库收入、消费、什一税、退款及治理转换资产合并，记录交易 UUID、发起者、币种、金额和结果。
- 仪式定义变更、仪式地点、场次开始/结束/取消、参与者、消耗物、效率、目标和 Buff 结果。
- 共议制转入/转出、源信仰关系、模因继承、教会金库迁移及失败恢复。

沿用“数据库事件为事实、单条 JSON 为可恢复投影、`event.yml` 动态生成叙述”的原则。JSON 存稳定事件类型、对象 UUID、日期与结构化参数，不存渲染后的句子。意识形态/教会记录使用独立索引空间，与国家史书通过国家 UUID、玩家 UUID、教会 UUID 关联。

历史可见性应分级：公开的组织沿革可向玩家展示；个人选票、密封投票、私人信件正文及非公开仪式目标不得因复用模板而意外公开。金库历史要记录可核对的实际账本结果，不把提案或预览写成已完成交易。

**验收：**意识形态改名不改变史书 UUID；意识形态删除/合并按软归档保留记录；教会分裂可追溯源组织；金库迁移与治理模式转换均有单一操作 ID、幂等恢复和可查询结果；关闭采集时不伪造停用期间事件。

## 5. P1：Buff 与短时 Debuff 计算器

当前 `DoctrineBuffCalculator` 按来源求等级和到期时间，适用于“同来源替换、不同来源叠加”。它并没有完整定义 Minecraft 药水效果的所有堆叠策略。下一版应避免把“等级相加”和“时间相加”混为一谈。

建议将效果贡献扩展为显式策略：

- `REPLACE_SOURCE`：同来源刷新或覆盖，适用于护甲状态。
- `REFRESH_DURATION`：等级不叠加，只刷新剩余时长。
- `ADD_LEVEL`：短时触发叠加等级，但有单次上限与总上限。
- `EXTEND_DURATION`：等级不变，累计或延长时长，并设时长上限。
- `MAX_INTENSITY`：多来源只取最高等级，适合不应无上限叠加的惩罚。

还需处理同效果类型多来源到期、持续效果与短时效果混合、牛奶清除、死亡/离线/改信、其他插件强制覆盖等边界。外部药水没有可靠来源标签，恢复/覆盖规则应明确且可配置，不能承诺还原已被移除的第三方效果。

**验收：**使用可控 tick 的单元测试验证到期顺序、刷新、等级上限、时长上限、来源撤销与重复触发；实服确认短时虚弱不会被旧长时效果错误延长或过早清除。

## 6. P1：战争目标权重与革命战争

### 6.1 目标驱动的战争分数

当前占领计分主要按国家/城镇领土权重与人数计算。后续应将“战争目标”作为战争状态的一部分，避免仅有抽象总分：

- 宣战时明确目标类型、目标对象、目标领土/城镇及完成条件。
- 按战争目标的重要性配置基础权重或完成分，例如首都、防御要塞、边境城镇、保护对象、解放对象。
- 目标权重由 `war.yml` 配置，目标变更与历史状态写入统一战争账本。
- 对收复失地、解放、征服、摧毁威胁等理由定义相符目标，不允许选择与借口无关的目标刷分。
- 总分应说明是累计政治分还是封顶控制分；不要只在界面显示却不影响任何可解释流程。

**验收：**相同战场行为在不同合法目标下产生可解释分数；同一目标不会重复领取完成分；目标取消、城镇易主、阵营变化后可恢复或重新校验。

### 6.2 革命与反革命

将革命和反革命作为明确战争/政治状态链，而不是只增加战争理由枚举：

1. 明确革命发起主体（国家、城镇、政治派系或受支持的居民）。
2. 定义政体/意识形态诉求、支持度来源、发起门槛和失败后果。
3. 革命战争的目标与占领、投票、条约结局挂钩。
4. 反革命方必须由受攻击政权或符合规则的支持者主动形成，明确其胜利条件。
5. 结局决定政权更替、领袖更换、独立/重新并入、战争赔偿和停战，并通过单一事务协调 Towny 与 WDER 状态。
6. 反革命不能仅因防守方身份自动成立，也不能绕过中立、联盟投票、权限和停战规则。

**验收：**革命发起、阵营组建、战争目标、胜利/失败/僵持三类结局有持久化状态机；每个结局可重复执行而不重复改政权或重复发放效果。

## 7. P2：外交信件 GUI 与历史呈现

当前外交信件已有命令发送、收费、持久化、收件通知和史书事件；剩余目标是把文本命令升级为游戏内“书与笔”交互：

- 书与笔 GUI 选择侮辱、正式通知、请求信模板。
- 分页编辑正文、预览收件国家/信件类别/费用，确认页显示不可撤回提示。
- 发送前后端重新验证国家身份、外交权限、目标、正文长度、费用和经济提供者币种。
- 收件箱显示未读状态、发件国家、日期和类型；打开书阅读正文，已读状态持久化。
- 失败不扣款或尝试精确退款；成功后生成不可变信件 UUID。
- 文案模板允许服主调整，但玩家正文按原文保存；提供举报/过滤/长度限制选项，防止格式码、控制字符和刷屏。
- 明确史书正文可被有权/公开查史用户读取；如未来需要机密外交，必须设计独立权限和公开史书脱敏策略。

**验收：**命令与 GUI 共用同一服务；在线与离线收件均可读取；满背包、取消确认、存储失败、退款失败及跨国家越权均有测试。

## 8. P2：旗帜展示

允许玩家设计 Minecraft 原版旗帜并将其绑定给城镇、国家、意识形态或教会。

- 以 Banner 底色和图案序列形成可序列化旗帜定义，保存稳定目标 ID，不依赖玩家背包里那件物品长期存在。
- 绑定/替换/清除资格按对象治理权限控制；旗帜自定义使用原版可支持的图案数量和颜色限制。
- 国家、城镇、意识形态/教会介绍、外交对象选择、史书或集团相关面板都通过统一展示适配器取图标。
- 对象有旗帜时显示旗帜；没有绑定或旗帜数据损坏时继续显示现有领导人头颅，不破坏旧 UI 行为。
- 旗帜修改记录修改者和时间；支持预览、二次确认、清除及历史记录。不要只依赖某个在线玩家当前手持物。
- 共议制的源意识形态、各教会和分裂出的新意识形态有独立旗帜绑定；继承旗帜的默认/选择规则须在分裂确认界面展示。

**验收：**旗帜在重启、改名和绑定玩家离线后仍可显示；编辑、预览和最终应用一致；无旗帜、无头颅资料或损坏数据时可安全回退。

## 9. P2：臣子机制与对外 API

当前外交官主要是身份标记，政府/政治家职位主要提供权限入口；尚未形成覆盖臣子职责的标准任务机制，也没有面向外部插件的稳定服务门面。

### 9.1 臣子角色

围绕外交官、政治家及其他国家职员定义角色能力：

- 外交官：可代表国家执行哪些致函、接洽、访问、谈判、提出条约操作；哪些操作仍须国王/政府领袖批准。
- 政治家/政府成员：可提案、提交议题、组织投票或执行被授权的国内政策。
- 委托有范围、目标、有效期和撤销机制；不继承国王的全部权限。
- 对主权帝国明确国家层与城镇层权限分界，从仆国臣子只代表本国，不自动代表帝国主席国。
- 重大动作记录操作者、代表国家、目标、授权依据和结果，并写入史书或审计事件。

### 9.2 API 契约

建立稳定、版本化的 `WDER API` facade，至少公开：

- 国家、城镇、集团、意识形态和战争只读快照。
- 委托与角色能力查询。
- 经过统一校验的外交、提案、史书事件和战争目标服务。
- 注册戒律效果、模因/戒律定义的生命周期通知。
- 可取消/不可取消事件的明确语义、线程要求和重载行为。

避免要求扩展直接依赖 `OrgManager`/`ReligionManager` 内部实现类。API 使用稳定 ID 和不可变 DTO；变更采用版本化兼容策略，异步调用切回服务端主线程前必须验证对象仍有效。

**验收：**提供独立 API 文档、示例扩展和兼容性测试；未经授权的外部插件调用也不能绕过战争、经济及主权边界规则。

## 10. P2：战争现场与普通玩家参与

现有系统以战争账本、分数与战后政治结算为核心，战场目标和普通玩家参与感仍可提升：

- 将战争目标、前线城镇、占领进度和目标状态展示在 GUI/计分板。
- 提供征召报名、补给/建设、侦察、外交游说等非击杀贡献；贡献规则公开且可审计。
- 加入战争阶段（准备、交战、谈判、结算）和阶段变化事件，明确能执行哪些动作。
- 为离线、成员退出联盟、主席国变化、目标国家解散等情况定义战争阵营重算规则。
- 任何贡献分不得无限刷取；定义同一玩家/地点/周期的上限和反作弊处理。

**验收：**战场展示不取代服务端实时校验；普通参与行为在重启后可恢复，且战争结算能解释每项分数来源。

## 11. 推荐实现顺序

1. **稳定底座**：回归经济、史书、战争、外交信件和 Buff 生命周期，补齐幂等、退款及存储失败测试。
2. **意识形态剩余闭环**：完成受控金库消费、异端/异教判定和内置戒律效果覆盖，明确每项实际行为边界。
3. **仪式与 Buff 策略**：先明确仪式类型/效率/消耗语义，再升级短时效果计算和到期/重叠策略。
4. **意识形态史书**：建立独立 UUID 索引、教会关联事件、隐私分级和可恢复投影。
5. **战争目标与革命**：先目标模型和分数来源，再建立革命/反革命的组织、目标与结局状态机。
6. **展示与 API**：旗帜绑定及头颅回退、信件书与笔 GUI、臣子授权 API 和外部示例。
7. **运营完善**：史书筛选、战争参与感、性能、迁移预演和兼容性矩阵。

每一阶段均应遵循：机制规格 → 配置迁移 → 后端规则 → 命令/GUI → 史书与审计 → 测试 → 使用文档/机制文档。

## 12. 可选拓展

以下项目不应阻塞核心闭环，但可以在玩法验证后评估：

- 史书查询筛选、全文搜索、HTML/Markdown 导出、事件隐私级别。
- 可配置外交立场与国内支持率，用于和平提案或革命门槛。
- 国家议会/政治议案和有限时长的政策任期，避免所有国家决策只由少数职位直接操作。
- 基于组织能力、人口、地理和后勤的长期战争准备度；先建立平衡与反刷分测试，再用于实际分数。
- 服务器管理 API、指标和诊断命令，暴露事件采集失败、经济回滚失败、数据库延迟等健康状态。
- 插件升级迁移预演与导出备份命令，允许服主在生产迁移前查看会新增、变更和归档的记录。
